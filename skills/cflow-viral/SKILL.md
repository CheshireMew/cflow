# CFlow Viral

## 边界

负责内容的传播机制：为什么读者愿意把它发给别人、拿它表达自己、截图保存、评论站队、模仿二创或跨平台搬运。

不要替代 `$cflow-package` 做普通标题和 hook；不要替代 `$cflow-benchmark` 做完整对标拆解；不要替代 `$cflow-marketing` 做转化路径；不要替代 `$cflow-review` 做完整发布后复盘。

病毒式传播默认允许更刺激、更极端、更有站队感。强情绪、强挑衅和强传播钩子本身不是问题。只有用户要求品牌安全、事实核查、合规或平台风控时，才检查假事实、误导、攻击边界和作者声音。

## 工作流

1. **判断传播任务**：用户要设计传播潜力、诊断为什么没传播、拆解 viral 案例，还是复盘已发布内容。
2. **明确传播对象**：谁会分享？分享给谁？分享时想表达什么身份、情绪、立场、利益或关系？
3. **识别分享动机**：社交货币、身份表达、实用价值、情绪唤起、站队、共鸣、吐槽、提醒他人、展示品味或参与热点。
4. **设计传播单元**：金句、截图段、清单、meme、模板、观点阵营、故事反转、可复述框架、评论区问题或二创入口。
5. **检查传播路径**：平台内转发、评论区扩散、私域转发、群聊截图、跨平台搬运、二创挑战、模板复用。
6. **评估传播强度**：截图点、复述句、站队空间、评论冲突和二创入口。用户要求风控时再评估事实风险、语境坍塌、误读风险、品牌风险和作者声音失真。
7. **交接生产**：需要标题/hook 交给 `$cflow-package`；需要对标样本交给 `$cflow-benchmark`；需要成稿交给 `$cflow-draft`；发布后数据交给 `$cflow-review`。

## 输出

设计传播潜力时输出：

- 内容目标
- 目标分享者
- 分享对象
- 分享动机
- 传播单元
- 传播路径
- 可模仿或二创点
- 传播加压点
- 交接给哪个 CFlow skill

诊断传播弱点时输出：

- 当前内容为什么不容易被分享
- 缺失的分享动机
- 缺失的传播单元
- 可增强但不失真的修法
- 不建议追求传播的部分

复盘 viral 表现时输出：

- 已有传播信号
- 传播发生在哪个路径
- 读者复述了什么
- 哪些元素被截图、转发、评论或二创
- 可沉淀的传播模式
