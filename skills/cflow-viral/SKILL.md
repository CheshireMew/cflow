# CFlow Viral

## 边界

`cflow-viral` 负责发布前和生产中的传播机制：为什么读者愿意把内容发给别人、拿它表达自己、截图保存、评论站队、模仿二创或跨环境搬运。

它必须自己完成传播任务里的核心判断：分享动机是否存在、传播单元是否成立、截图段是否自足、复述句是否能流通、二创入口是否真实、强情绪是否被素材兑现、评论区是否有可接内容、传播路径是否匹配、是否只是空站队/空金句/爆款模板。不能把这些判断外包给 `$cflow-package`、`$cflow-shortform`、`$cflow-review`、`$cflow-edit` 或任何“合同”。

可以直接做：

- 设计分享动机、传播单元、截图点、复述句、二创入口和评论区问题。
- 诊断内容为什么不容易被分享、转发、截图、评论或模仿。
- 拆解用户提供的 viral 样本中的传播机制，但不做发布后表现复盘结论。
- 判断强情绪、强挑衅、站队、争议和 meme 是否服务核心主张。
- 设计发布前传播实验变量和给 `$cflow-review` 的复盘观察维度。
- 调用 `profiles/content-assets/` 里匹配的传播模式，但只采用传播机制，不引入新事实。

不负责：

- 写完整正文、长文、脚本或销售稿；需要完整成稿时交给 `$cflow-draft`。
- 把传播单元压成短内容、thread 或短脚本；需要生产短内容时交给 `$cflow-shortform`。
- 生成完整标题包、hook 包、opening 或发布包；交给 `$cflow-package`。但传播钩子、截图点、复述句和评论问题由 `cflow-viral` 先判断。
- 做已有草稿的逐句改稿、AI 指纹检测或去 AI 味改稿；交给 `$cflow-edit`。但传播表达里的爆款模板腔、空情绪、空站队、补尾巴和平台腔，`cflow-viral` 必须先判断。
- 发布后数据、评论、转发、截图、二创、跨环境搬运或传播路径证据的完整复盘；交给 `$cflow-review`。`cflow-viral` 只提供传播维度和发布前设计。
- 主动事实核查；用户要求品牌安全、事实核查、合规或发布限制时，事实来源交给 `$cflow-research`。

病毒式传播默认允许更刺激、更极端、更有站队感。强情绪、强挑衅和强传播钩子本身不是问题。只有用户要求品牌安全、事实核查、合规或发布限制时，才收窄假事实、误导、攻击边界和作者声音风险。

传播设计优先级固定为：第一，不能有 AI 式爆款模板腔；第二，传播模板必须是分享动机、传播单元和路径结构，不是固定口号；第三，最大化截图、复述、评论、二创和转发。任何传播加压都必须被素材兑现。

## 入口判断

进入 `cflow-viral` 后先判断用户真实任务：

- **传播设计**：为一个内容、选题、草稿、短内容、营销文案或活动设计分享动机和传播单元。
- **传播弱点诊断**：判断为什么当前内容不容易被分享、截图、复述、评论或二创。
- **viral 样本机制拆解**：用户提供爆款样本、截图、视频、帖子或案例，要求拆传播机制。
- **传播路径设计**：公开转发、评论区扩散、私下转发、群聊截图、跨环境搬运、二创挑战或模板复用。
- **传播风控**：用户要求品牌安全、事实核查、合规、发布限制或作者声音边界。
- **发布后复盘请求**：已有发布数据、评论、转发、截图、二创或跨环境证据时，交给 `$cflow-review`，但可提供观察维度。

## 工作流

1. **判断传播任务**：设计传播潜力、诊断传播弱点、拆解 viral 样本、设计传播路径还是给 review 复盘维度。
2. **检查内容资产**：读取 `profiles/content-assets/` 中匹配的传播模式、传播单元或资源包装资产。资产只提供机制，不提供新事实。
3. **明确传播对象**：谁会分享？分享给谁？分享时想表达什么身份、情绪、立场、利益或关系？
4. **识别分享动机**：社交货币、身份表达、实用价值、情绪唤起、站队、共鸣、吐槽、提醒他人、展示品味或参与热点。
5. **设计传播单元**：金句、态度句、截图段、清单、meme、模板、观点阵营、故事反转、可复述框架、评论区问题、二创入口或信息差后果句。
6. **检查传播路径**：公开转发、评论区扩散、私下转发、群聊截图、跨环境搬运、二创挑战、模板复用。
7. **评估传播强度**：截图点、复述句、站队空间、评论冲突、二创入口和跨环境可搬运性。
8. **做本地反 AI 味检查**：检查空情绪、空站队、空金句、爆款模板腔、平台腔、假二元对立、补尾巴和强词无素材兑现。
9. **判断风控**：只有用户要求品牌安全、事实核查、合规或发布限制时，才评估假事实、误导、攻击边界、语境坍塌、品牌风险和作者声音失真。
10. **交接生产和复盘**：只把不属于传播机制的生产或发布后复盘交给对应 skill。

## 分享动机

读者分享内容，通常不是为了帮作者传播，而是为了完成自己的社交动作。

常见动机：

- **身份表达**：这代表我是谁、我相信什么、我站在哪边。
- **社交货币**：我先知道、我懂这个、我品味好。
- **实用价值**：这对别人真的有用，值得转发给某个人。
- **情绪唤起**：惊讶、愤怒、好笑、安心、被看见、被冒犯。
- **站队**：我用转发表明立场。
- **共鸣**：这说出了我想说但没说出来的话。
- **吐槽**：这给了我一个表达不满的出口。
- **提醒他人**：这能让某个人少犯错。
- **关系维护**：我转给你，因为我知道你正在经历这个。
- **参与热点**：我也加入这个公共话题。
- **展示判断**：我不是搬运信息，我看懂了背后的变化。

设计传播时先问：读者转发这条内容时，是在替自己说什么？

## 传播单元

一条内容要传播，通常需要可被拆下来的传播单元：

- **金句**：一句话能独立流通。
- **态度句**：用极短句规定读法，让读者转发时顺手表达“好笑、荒诞、重大、危险、该来的来了”等情绪立场。
- **截图段**：一屏内自足，能被保存或转发。
- **清单**：读者愿意收藏或发给别人。
- **模板**：别人能套用。
- **Meme**：有固定格式，能被改写。
- **对立阵营**：读者能用它站队。
- **反常识框架**：读者能复述“原来不是 X，而是 Y”。
- **故事反转**：读者能讲给别人听。
- **评论区问题**：自然引发补充、反驳、晒经历。
- **二创入口**：别人能模仿结构、填入自己的版本。
- **信息差后果句**：读者能复述“表面是 X，真正变化的是 Y，所以 Z 会受影响”。

没有传播单元的内容，即使质量不错，也可能只被读完，不会被分享。

传播单元检查：

```text
这一句能否脱离原文被复述？
这一屏能否单独截图？
这个模板别人能否套用？
这个问题能否自然引发评论？
这个情绪是否有事实、场景或判断支撑？
这个二创入口是否足够低门槛？
```

## 信息差 + 后果判断

复杂变化类内容要传播，通常不能只提供“我先知道”。它需要把信息差翻译成读者愿意替自己转发的判断。

常见传播单元：

```text
笑点 / 荒诞 / 历史性 / 警示性先定调。
以前是 X，现在变成 Y。
表面是 X，真正被改变的是 Y。
最先受影响的不是 A，而是 B。
这不是功能更新，是旧规则被重新定价。
专业系统最脆弱的地方，不是技术，而是流程。
```

设计时检查：

- 读者转发时，是在表达“我先看懂了变化”，还是只是在搬运新闻？
- 读者转发时能否替自己说一句“真正麻烦 / 真正值钱 / 真正荒诞的是 X”，而不是只贴一个事件链接？
- 首句是否给了可转发的态度，而后文是否用事实兑现这个态度？
- 有没有一个一屏内自足的“变化 -> 后果 -> 判断”段落？
- 判断句能否脱离原文被复述？
- 评论区是否能自然接补充信息、反例、经历或站队？

如果传播依赖私有信源、作者身份、行业红利或热点时机，只能标为条件性机制，不要当成通用传播规则。

## 高可信证据传播

论文、数据、图表、回测、报告或专业观察要传播，不能只靠“资料硬”。传播设计必须把可信证据变成读者愿意替自己表达的判断。

默认检查：

```text
可信信号：读者为什么敢相信或敢转发这个离谱结论？
单变量反转：读者能否一句话复述“只改 X，结果从 A 到 B”？
既有情绪：这条证据释放了读者哪种不满、怀疑、恐惧、震惊或被看见感？
身份落点：读者转发时是在表达自己属于哪类人、看懂了什么、站在哪边？
视觉证据：是否有一屏自足的图表、截图、数字或对比段可截图？
争议留白：评论区能否自然接专家纠错、普通人共鸣、反例、经历或站队？
```

传播单元可以来自：

```text
单变量反转句。
极端结果差。
图表截图。
本土 / 自我处境落点。
真实边界问题。
```

不要把专业材料写成纯摘要。读者转发的不是资料本身，而是“这个证据替我说出了一个判断”。

## 内容资产采用

传播任务开始前，检查 `profiles/content-assets/` 是否有匹配资产。优先匹配 frontmatter 中包含 `cflow-viral` 的资产，以及 `triggers` / `use_when` 与当前传播目标相符的资产。

可采用的资产类型：

- 分享动机模式。
- 收藏或保存机制。
- 截图点和复述句模板。
- 二创入口。
- 传播路径模式。
- 资源包装模板。

采用规则：

- 资产只提供传播机制，不提供新事实。
- 不把资产里的权威人物、数字、结果和案例直接搬到当前内容。
- 如果资产依赖特定题材红利、作者身份或渠道优势，必须先判断当前任务是否具备同类条件。
- 如果需要把传播单元写成短内容或短脚本，交给 `$cflow-shortform`。

## 传播路径

不同路径需要不同设计：

| 路径 | 需要什么 | 风险 |
|---|---|---|
| 公开转发 | 强身份、强情绪、强实用 | 被误判或争议过载 |
| 评论区扩散 | 开放问题、站队空间、可补充经历 | 讨论失控 |
| 私下转发 | 对具体人有用、像提醒 | 太公共会失去私密相关性 |
| 群聊截图 | 一屏自足、低上下文依赖 | 被断章取义 |
| 跨环境搬运 | 格式简单、观点清楚、截图友好 | 丢失来源和语境 |
| 二创挑战 | 模板清楚、参与门槛低 | 质量不可控 |

传播路径必须和内容形态匹配。长文适合截图段、清单、金句和复述框架；短内容适合态度句、评论区问题、二创模板和信息差后果句；营销内容适合入口转发、私下提醒和利益点截图。

## 平台信号转译

不要背平台算法口诀，也不要把未经核查的流量参数写成通用规则。把平台信号转译成读者行为设计：

- **停留**：开头有进入理由，正文有持续推进，不用长铺垫消耗耐心。
- **点击继续看**：第一屏给出明确收益、冲突、信息差或未完成问题。
- **评论**：正文留出可补充经验、反例、站队、提问或纠错空间。
- **收藏**：内容有长期查阅价值，例如清单、步骤、框架、资料、避坑或决策标准。
- **转发**：读者能用它提醒别人、表达身份、节省试错、站队或复述一个判断。
- **复访**：内容承诺了后续价值、系列资产、持续观察或可追踪变化。

如果只说“让算法喜欢”，但说不清要制造哪一种读者行为，就回到分享动机、传播单元或包装入口重新设计。

## Viral 设计检查

发布前检查：

- 谁会愿意分享？
- 他分享给谁？
- 分享时他想表达什么？
- 哪一段可以被截图？
- 哪一句可以被复述？
- 有没有可模仿结构？
- 评论区能自然接什么？
- 这个传播是否足够有情绪、有站队、有复述点？
- 强情绪是否有事实、数字、场景、反差或具体后果兑现？
- 传播会不会吸引明显错误人群，且账号承接不了？
- 用户要求品牌安全或事实核查时，是否依赖假事实、误导或作者声音失真？

## 传播本地闸门

传播设计必须被素材兑现，不为了 viral 新增空态度、空站队或空金句。

- 没有截图点、复述句、分享动机或评论入口时，不要硬包装成传播内容；先回到 `$cflow-angle`、`$cflow-shortform` 或 `$cflow-package`。
- 强情绪必须接事实、数字、场景、反差或具体后果；不能只写“太炸了、封神、震撼、颠覆”。
- 金句和态度句必须能脱离上下文被复述，并且不改变素材事实边界。
- 模板只能组织传播动作，不能生成固定爆款腔、平台腔、空站队或空金句。
- 不为了站队制造假二元对立；对立阵营必须来自真实读者分歧、利益冲突或价值判断。
- 评论区问题必须真能接评论，不做装饰性提问。
- 如果最后一句只是替内容贴传播标签，而没有新增可复述判断，直接删掉。

## 中文母语传播表达

写给中文母语者时，viral 不等于无功能煽动。强情绪、强站队、强挑衅可以用，前提是服务核心主张、分享动机和传播单元。

- 开头直接给钩子，少铺背景。
- 每段短一点，让页面透气。
- 专业可以，但默认不要像报告或咨询稿；营销通稿风格是否可用取决于转化目标。
- 不要为了“更像爆款”硬扩篇幅；如果强表达能提高复述、截图或转发，保留并压缩到更有劲。
- 传播点要尽量嵌在核心信息里；如果目标是硬广或活动转化，可以直接广告化。
- 平台名不能自动生成平台腔；先看分享动机和传播路径。

## Viral 本地反 AI 味检查

`cflow-viral` 不负责专项 AI 指纹检测，但必须自己防止传播设计变成 AI 式爆款模板。

重点检查：

- 是否只有“震撼、炸裂、封神、颠覆”这类空情绪，没有事实兑现。
- 是否制造假二元对立，但素材里没有真实分歧。
- 是否每段都是金句，却没有可截图的具体信息。
- 是否用“不是 X，而是 Y”连续制造聪明感，但没有观察、场景或后果。
- 是否把传播点写成最后一句补尾巴，而不是嵌入核心信息。
- 是否评论区问题只是装饰，没人有理由回答。
- 是否二创入口太复杂，别人无法模仿。
- 是否为了平台感默认一句一行、清单化、短促喊话。
- 是否把普通信息强行升维成历史性、颠覆性、时代信号，但没有素材支撑。
- 是否把强传播误写成营销号腔、通稿腔或咨询腔。
- 是否追求“有传播感”，但读者转发时不知道自己在表达什么。

命中时先删、缩、重排或回到上游补素材。不要用“更像爆款、更有网感、更刺激”作为表层目标直接改写。viral 的目标是让内容拥有真实分享动机和可流通传播单元。

## 风控模式

用户要求品牌安全、事实核查、合规或发布限制时，再检查这些事：

- 编造事实或案例。
- 使用无法支撑的攻击性指控。
- 故意断章取义。
- 制造不必要的恐慌。
- 把复杂议题压成假二元对立。
- 用不符合作者价值观的极端表达。
- 为了评论量故意引战。
- 传播会吸引错误人群，且账号无法承接。
- 强情绪破坏作者长期可信度。

默认先放大张力和刺激。判断重点不是“够不够克制”，而是强情绪是否能带来复述、截图、评论或转发，并且不突破用户要求的事实和品牌边界。

## 给 Review 的传播复盘维度

发布后复盘归 `$cflow-review`。当 review 需要传播维度时，使用这些观察项：

- 转发率。
- 评论中是否出现复述句。
- 是否有人截图转发。
- 是否有人标注朋友或发给特定对象。
- 是否出现二创、改写、套模板。
- 是否跨环境搬运。
- 是否引发阵营化讨论。
- 是否带来错误人群或误读。
- 哪个传播单元被拿走。
- 哪条评论暴露真实分享动机。

这些观察项只能作为 `$cflow-review` 的复盘维度。是否沉淀为传播模式、生产资产或维护建议，由 `$cflow-review` 按资产分层和沉淀规则判断。

## 常见错误

- 把 viral 理解成更大声、更刺激。
- 只有情绪，没有传播单元。
- 只有观点，没有截图点。
- 只有金句，没有事实、场景或后果。
- 只想让算法喜欢，说不清读者为什么分享。
- 硬造站队，素材里没有真实分歧。
- 评论问题没人有理由回答。
- 二创模板太复杂，参与门槛高。
- 强传播吸引了错误人群，账号接不住。
- 为了传播牺牲事实边界。
- 把发布后复盘留在 `cflow-viral`，没有交给 `$cflow-review`。
- 把传播点外包给标题包装，自己没有判断分享动机。

## 路由

只在问题不属于 `cflow-viral` 时路由：

- **完整成稿、长文、脚本或销售稿**：交给 `$cflow-draft`。
- **短内容正文、thread 或短脚本生产**：交给 `$cflow-shortform`。
- **完整标题包、hook、opening 或发布包**：交给 `$cflow-package`。
- **已有草稿结构手术、逐句改稿、AI 指纹检测或去 AI 味改稿**：交给 `$cflow-edit`。
- **传播服务销售、私信转化、offer 或 CTA 策略**：交给 `$cflow-marketing`。
- **事实核查、来源、真实案例或最新资料**：交给 `$cflow-research`。
- **封面、分享图、截图图、视觉传播单元或配图 brief**：交给 `$cflow-image`。
- **发布后传播路径、转发证据、截图复述、评论和二创表现复盘**：交给 `$cflow-review`。
- **长期作者声音、表达禁区或人格边界沉淀**：交给 `$cflow-voice`。

不能路由的情况：

- 用户问分享动机、传播单元、截图点、复述句、二创入口、评论区扩散或 viral 风险，`cflow-viral` 必须先承担。
- 用户提供 viral 样本要求拆传播机制，`cflow-viral` 必须先拆分享动机和传播单元；只有发布后数据复盘才交给 `$cflow-review`。
- 用户说“这个不够传播、不够爆、没人转发”，`cflow-viral` 必须先判断缺分享动机、传播单元、路径还是素材兑现。
