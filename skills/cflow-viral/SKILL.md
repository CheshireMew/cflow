# CFlow Viral

## 边界

负责发布前和生产中的传播机制：为什么读者愿意把它发给别人、拿它表达自己、截图保存、评论站队、模仿二创或跨环境搬运。

已有发布数据、评论、转发、截图、二创、跨环境搬运或传播路径证据时，交给 `$cflow-review` 做复盘；`cflow-viral` 提供分享动机、传播单元、截图点、复述句、二创入口和传播风险这些分析维度。

病毒式传播默认允许更刺激、更极端、更有站队感。强情绪、强挑衅和强传播钩子本身不是问题。只有用户要求品牌安全、事实核查、合规或发布限制时，才检查假事实、误导、攻击边界和作者声音。

设计传播前按 `$cflow` 的 profile 发现规则检查 `profiles/content-assets/` 是否有匹配资产。匹配资产只提供传播机制和检查清单，不替代当前内容的核心主张、事实边界或品牌约束。

## 工作流

1. **判断传播任务**：用户要设计传播潜力、诊断发布前为什么不容易传播，还是拆解 viral 案例中的传播机制。发布后传播表现复盘交给 `$cflow-review`。
2. **检查内容资产**：读取匹配的传播模式、传播单元或资源包装资产。
3. **明确传播对象**：谁会分享？分享给谁？分享时想表达什么身份、情绪、立场、利益或关系？
4. **识别分享动机**：社交货币、身份表达、实用价值、情绪唤起、站队、共鸣、吐槽、提醒他人、展示品味或参与热点。
5. **设计传播单元**：金句、截图段、清单、meme、模板、观点阵营、故事反转、可复述框架、评论区问题或二创入口。
6. **检查传播路径**：公开转发、评论区扩散、私下转发、群聊截图、跨环境搬运、二创挑战、模板复用。
7. **评估传播强度**：截图点、复述句、站队空间、评论冲突和二创入口。用户要求风控时再评估事实风险、语境坍塌、误读风险、品牌风险和作者声音失真。
8. **交接生产和复盘**：需要标题/hook 交给 `$cflow-package`；需要对标样本交给 `$cflow-benchmark`；需要成稿交给 `$cflow-draft`；需要短内容或短脚本交给 `$cflow-shortform`；发布后传播数据和路径复盘交给 `$cflow-review`。

## 输出

设计传播潜力时输出：

- 内容目标
- 目标分享者
- 分享对象
- 分享动机
- 传播单元
- 传播路径
- 可模仿或二创点
- 传播加压点
- 交接给哪个 CFlow skill

诊断传播弱点时输出：

- 当前内容为什么不容易被分享
- 缺失的分享动机
- 缺失的传播单元
- 可增强但不失真的修法
- 不建议追求传播的部分

发布后传播复盘请求：

- 不在 `$cflow-viral` 内完整复盘
- 交给 `$cflow-review`
- 可提供传播维度：分享动机、传播单元、截图点、复述句、二创入口、传播路径和误读风险
