# CFlow 成稿

## 职责边界

`cflow-draft` 负责把稳定 brief、角度、大纲、笔记、转录、研究包、案例包、营销 brief 或用户直接素材写成一版完整可发布草稿。成稿能力包括：确认成稿合同、判断素材密度、选择主结构、组织素材、写正文、保留作者声音、处理销售语气、出稿前自检，并修掉第一稿里的默认 AI 文体。

只有目标、读者、交付形态、核心主张或素材边界缺失到会写成完全不同作品时，才暂停成稿并说明缺口。

成稿任务内部的素材密度判断、反 AI 文体、结构选择、段落密度、销售语气、尾巴删除和用户原话保留，都由 `cflow-draft` 自己完成，不外包给其他 skill。

## 成稿合同

成稿前先把输入整理成合同。能推断的缺项直接补成假设；只有缺项会改变根交付物时才提问。

```text
目标：
读者：
篇幅：
交付形态：
发布约束：
核心主张：
读者张力：
可放大素材：
表达目标：
主动作 / CTA：
题材类型：
素材边界：
事实边界：
声音约束：
```

合同判断优先级：

1. 用户当前明确指令。
2. 稳定 brief 或上游交接。
3. 用户提供的大纲、素材顺序、事实和限制。
4. `profiles/voice-profile.md` 的作者声音约束。
5. `profiles/content-assets/` 中匹配的结构资产。

voice profile 用来保护作者声音、禁用表达、句子节奏、思维动作和场景调用规则。它不覆盖当前任务、事实边界、转化目标、发布硬约束或用户明确指令；冲突时以当前指令为准，并把冲突作为声音画像候选证据。

外部 sponsor brief、项目推广 brief 或产品资料必须先分层，不得整包吸收：

- **官方叙事**：只能作为素材来源或表达边界，不能直接变成作者口吻。
- **硬性限制**：合规、禁区、事实边界、CTA 要求，必须保留并影响写法。
- **可写事实**：数字、机制、流程、截图、用户动作和可引用观察，优先进入正文。
- **作者声音**：用户原话、亲自改稿、吐槽、取舍和不完整表达，优先保护。
- **待补材料**：需要真实经历、截图、交易细节、来源或最新状态的部分，只能标成缺口，不混进正文。

## 工作流

1. **定合同**：确认目标、读者、篇幅、形态、发布约束、主张、素材边界、事实边界、表达强度和 CTA。
2. **读真源**：默认读取 `profiles/voice-profile.md`；读取失败时继续执行并提示风险。检查 `profiles/content-assets/` 中 frontmatter 包含 `cflow-draft`，或 `triggers` / `use_when` 匹配当前题材、结构、交付形态的资产。
3. **定主任务和素材密度**：判断正文主要是在解释、说服、教程、转化、包装正文内部部件、传播正文内部部件、内容品牌、搜索正文、案例或复盘中完成哪一个主任务。估计素材实际支持的字数区间；素材不足时缩短交付、请求补素材，或说明当前只能写成中短稿。
4. **定主结构并排序素材**：用户已有大纲时严格按大纲写；没有大纲时从本文件结构库选择一个主结构。优先放大用户原话里的疑问、吐槽、犹豫、判断、动作、阻碍和现场反应。
5. **写稿并自检**：先写具体例子、场景、动作和阻碍，再抽象总结。销售稿保留销售语气。交付前执行质量闸门；命中问题时先删、缩、合并、重排、补具体动作、回到素材边界或标注缺口。

默认把用户素材当作可用素材推进。只有用户要求核查、来源、严谨审稿、合规、品牌安全或事实证明时，才标注事实状态或收窄承诺。未联网核查时，不假装查过；普通创作里也不要主动输出大段风控说明。

## 输出格式

写长内容时返回：

- brief 假设
- 草稿
- 可继续放大的卖点、张力或素材缺口
- 仅在用户要求核查时输出待核查事实
- 下一步编辑或包装建议

先给方向时返回：

- 推荐方向
- 备选方向
- 每个方向的核心主张
- 适合的篇幅、交付形态或题材
- 推荐理由

如果用户只要正文，直接给正文；不要为了展示流程而输出冗余分析。

## 结构控制

成稿结构由 stable brief、用户大纲、题材任务和素材顺序决定，不由模型自动补全。

用户已经给出大纲、段落顺序或明确详略时，严格按该结构写。不得自行增加引言、总结、额外小标题、背景段、FAQ、价值升维或“下一步展望”。如果原大纲明显无法承载任务，先说明结构问题并给 1-2 个替代方案。

用户没有给大纲时，只能按题材结构库选择一个主结构，并让每个小节服务主任务。不要把材料写成“定义 -> 列表 -> 复述 -> 模糊未来”或“多个等权小标题 -> 每节小结 -> 结语”的默认骨架。

如果用户问结构、模型或输入明显缺结构，先推荐 2-4 个候选结构，并说明各自适合的读者路径、素材要求和风险；选定后只采用一个主结构推进。结构模型是组织素材的工具，不是框架名录。

列表、小标题、类比、反问、括号旁注和破折号都是功能性工具。只有它们能帮助扫读、定位、澄清、补充边界或制造必要张力时才使用。

## 内容资产采用

匹配资产只提供结构、推进顺序、案例用法、资源包装、读者张力或结尾行动路径，不替代当前 brief 和用户素材。

采用规则：

- 不把资产中的人物、数字、案例、结果和权威背书写进当前草稿，除非用户素材已经提供。
- 如果资产适用条件不满足，只使用其中的抽象机制，或放弃采用。
- 资产不能覆盖当前用户指令、事实边界、转化目标或平台硬约束。

## 题材结构库

### 公众号 / 博客长文原型

当用户要写中篇、长篇、公众号、博客文章、完整体验文、现象解读或方法论文章时，先判断是否命中下面五种长文原型。原型是成稿结构，不是作者个人风格；不得把特定作者的身份、固定口癖、固定尾部、固定标点禁令或固定公众号格式写进通用草稿。

- **调查实验型**：亲自下场做一件事，然后报道发现。适合购买体验、注册测试、服务调研、工具实测、亲自验证传闻或亲手做实验。没有亲自行动就不要使用。
- **产品体验型**：拿到产品实际使用，带着读者一起体验。重心是真实使用场景、过程演示、作者感受、自然对比；不要写成功能清单和参数说明。没有真实产品使用就不要使用。
- **现象解读型**：观察到一个现象，然后层层深入分析。路径是观察 -> 好奇 -> 验证 / 研究 -> 机制解释 -> 更大的参照。升维必须从材料里长出来。
- **工具分享型**：分享一个实用工具、prompt、资源或方法，但用个人处境和使用过程包裹。路径是问题 -> 工具出现 -> 实际使用 -> 结果或惊喜 -> 读者怎么试。
- **方法论分享型**：把长期经验和方法论系统分享出来。每一节都必须有读者今天能执行的动作，同时坦诚学习成本、时间曲线和常见失败点。

### 销售和转化稿

AIDA 销售稿适合销售、转化或强说服：

```text
Attention
Interest
Desire
Objection handling
Proof
Action
```

先建立 desire，再引入产品、价格或 CTA。销售稿允许强 urgency、强利益、强对比和强 CTA；只有用户要求严谨、合规、发布限制或品牌安全时，才检查不可兑现承诺、过度浮夸和证据无法承载的确定性。

渠道情报型转化稿适合入口、福利、活动、窗口变化：

```text
截止时间 / 窗口变化
入口对象
稀缺性
内行信息差
利益点列表
强对比
福利补强
操作 CTA
```

保留短句、列表、符号、消息感、紧迫感和直接 CTA；不要写成完整产品介绍。

故事销售型适合产品、社群、服务或 offer 需要通过故事定位：

```text
客户或创作者场景
问题或压力
失败解决方案
转折点
guide、工具或机制
新结果
说服动作
行动
```

客户是 hero。品牌、产品或社群是 guide。除非格式明确是产品演示，不要让产品成为主角。

### 诊断和指南

诊断型适合把常见问题拆到根因，并给出新的判断路径：

```text
症状
错误诊断
根因
机制
应该怎么做
例子
收束句
```

实用指南型适合教程、操作指南、避坑文和方法应用：

```text
问题
常见建议为什么失败
原则
步骤
例子
陷阱
下一步动作
```

原则不能停在抽象层，每一节都要落到读者今天能执行的动作、判断问题、练习方式或避坑清单。

### 工具和教程文章

创作者教程 / 工具上手稿适合教程文章、工具上手、使用体验或面向粉丝的实用指南。除非用户明确要求手册、文档、速查表或 FAQ，否则默认写成创作者文章。

```text
为什么现在值得关心
读者的具体处境
一个真实使用场景
核心操作或关键机制
作者判断和取舍
容易踩的坑
下一步可以怎么试
```

普通工具发现稿适合“偶然发现一个工具还不错，介绍一下”。不要升级成观点文、教程文、开源生态观察或 AI 工作流复盘。

```text
怎么碰到它
原本以为什么会发生
实际发现了什么
它大概是什么
个人用为什么方便
怎么自己试
```

工具和教程写法纪律：

- 不把资料平铺成完整功能清单。先选最能服务读者行动和阅读理由的信息。
- 命令表、快捷键、FAQ、参数说明和长清单默认后置、压缩或作为附录；只有用户明确要手册时才放进正文主结构。
- 教程也要有作者判断：什么最值得先试、什么新手容易误解、什么场景真的有用、什么不必一开始学。
- 解释型内容按读者认知轨迹推进，不按教科书知识逻辑铺垫。
- 先写具体使用场景，再解释功能。不要从“它支持什么”开始一路介绍到结尾。
- 口语化不是本人味。不要把说明书腔简单改成过度随便的聊天腔；声音不清时用自然、直接、有判断的中文。
- 普通发现稿允许轻发现口吻，保留“叫什么、还真、挺好、免费、好用、且行且珍惜”这类直接判断；不要把“免费、好用、方便”改写成“降低门槛、提升效率、形成基础设施”。

### 观点、故事和源头资产

观点型适合判断、评论、现象解释和立场文：

```text
主张
为什么重要
别人忽略了什么
推理
影响
反方观点
最终立场
```

讲观点时先把反方或普通读者处境具体化，并承认其合理性，再切入自己的不同视角。

故事到洞察型适合亲历、客户故事、案例故事和复盘：

```text
场景
张力
变化
洞察
经验
应用
结尾
```

先写人、动作、阻碍和物件，再抽象成判断。不要把案例刚抛出来就总结为概念句。

源头资产型长文适合建立内容飞轮、知识资产、个人品牌主线，或后续要拆成短内容、短脚本或短发布文案：

```text
读者正在付出的代价
本篇核心主张
一个具体场景或亲历问题
机制解释
可执行路径
异议或失败做法
可复用判断
下一步行动或后续拆分方向
```

源头资产必须先作为完整资产成立。每个小节最好能独立承载一个判断、场景、清单、案例或反常识；结尾给出可拆分单元，不要在长文里塞满多个短文案。普通介绍、记录和发现型文章不默认需要 CTA。

## 长文推进纪律

长文不是把信息铺长，而是让读者一路跟着主线走。

- **主线波动**：允许围绕主线短暂偏出去，给读者案例、知识、喘息或情绪落点，但必须高频拉回主线。
- **层层剥开**：先写现象，再写表面解释，再追问更深一层，最后压出核心洞察。
- **反向论证**：揭示核心观点前，可以先满足读者原有期待，再打破它。语气应是“我也曾经这样想”，不是“你们都错了”。
- **疑问句转向**：疑问句用于让读者停一下，准备接收新信息或进入新解释。反问不能空转，问完必须给出具体例子、解释或下一步。
- **句式断裂**：极短句或短语可以独立成段，用于强转折、情绪落点、关键判断或行动提示。连续短段必须检查每段是否有独立功能。
- **回环呼应**：开头或中段埋下的意象、问题、句子或小钩子，后文要以变体形式响一次。
- **逐一展示和升番**：多个产品、模型、案例、报价、玩法或结果不要一次性罗列结论。先逐一展示，每轮给一句具体判断；最强、最意外或最能承担 payoff 的样本放后面。

长文、脚本或故事型内容如果读起来太平，检查是否有情绪地图和升番推进。升番必须来自新素材、新场景、新反差或新行动，不能只靠更强形容词。

## 素材纪律

- **亲自下场优先**：如果用户提供了真实行动、测试、购买、体验、踩坑或调研，优先把它作为正文推进骨架。写出动作、阻碍、结果和现场反应。
- **不得伪造亲历**：没有真实经历时，不要写“比如有一次”这类伪亲历。可以写成假设场景，或标注需要补真实案例。
- **知识随手掏**：知识、历史、学科背景或文化参照要像从当前材料里自然想起。只讲到能解释当前问题为止，讲完立刻回到主线。
- **私人视角连接公共议题**：有作者经历时，用作者如何被影响、如何误判、如何被打动来连接公共问题；不要默认写成“这给我们的启示是”。
- **人物画像法**：从数据、评论、付款数、岗位数或行为信号出发时，可以用 3-5 句话快速代入一个具体普通人。人物画像是共情工具，不是编造事实；要标明这是合理想象或基于素材的推断。
- **文化升维**：具体事件之后可以连接到历史、文化、哲学或社会参照，但必须说明结构相似点，并回到当前问题。
- **案例人物公正性**：使用真实人物或历史案例时，不能只截取有利片段。至少交代完整故事弧、关键限制和不可复制条件。
- **领域细节要像内行**：涉及游戏、金融、开发、设计、影视、运营或其他垂直领域时，必须使用该领域真实用户会用的细节和语言。缺少细节时先补素材，不要用外行概括。

用户提供了明确素材时，不新增未被素材支撑的事实、功能、服务、承诺、运营范围或案例结果。为了转化、包装或叙事需要补信息时，只能标成“建议补充”，不要混进正文。

## 写作纪律

- **生产优先级**：第一，不要 AI 味；第二，使用可迁移写作模板；第三，提高传播度。模板和传播都必须服务素材、作者判断和读者任务，不能把正文写成固定腔调、平台腔、爆款模板或空金句。
- **一个主轴**：一篇完整草稿先服务一个核心主张、任务或动作。副任务只能服务主任务，不能抢主线。
- **读者具体**：先知道谁会看、为什么现在要看、读完要发生什么。
- **三段读者行为**：生产前先设计读者为什么停下来、为什么继续看、看完是否需要动作。没有自然动作时，最后一个有信息功能的段落结束就停。
- **具体先于抽象**：场景、例子、动作、读者处境、前后变化优先于概念总结。
- **用户原话是素材**：用户原始表达里的疑问、吐槽、犹豫、判断、脾气和不完整句，优先当作声音和现场素材处理。不得只抽取事实后改写成中性说明、概念总结或咨询腔判断；除非用户明确要求降温或正式化。
- **用户改稿优先于 AI 原稿**：用户亲自删掉、降级、重排或保留的句子，默认代表审美和判断边界。后续成稿不得从官方 brief、旧稿或 AI 原稿里恢复这些被用户移除的品牌话术、升维总结和模板 CTA。
- **故事先于概念**：生活故事、历史故事和普通人场景进入正文时，先写人、动作、阻碍和物件，再抽象成判断。
- **每句话有功能**：推进注意力、理解、情绪、欲望、信任、记忆或行动；没有功能就删、移或改。
- **直接进入内容**：除非交付物本身是教程、课程或流程说明，不要用“下面来拆解、你需要知道的是、接下来我们看”这类元话语开场。第一句应该承担事实、场景、判断、冲突或读者处境。
- **信息密度优先于篇幅**：篇幅要求不是填充许可。字数由信息量决定；要达到更长篇幅，必须补真实材料、案例、步骤、对比、数据或操作过程。
- **强表达不自动降温**：强利益、强判断、强情绪、强 CTA、强对比不是天然问题。只有用户要求严谨、合规、品牌安全或发布限制时，才收窄承诺和表达。
- **爆款要资产化**：个人内容品牌建设默认不反爆款。设计高传播内容时同时检查：这次传播之后，读者会记住作者的什么判断、方法、栏目承诺、人格气质或可信度；有没有可承接的复述句、后续选题、主页入口、私信路径或栏目资产。
- **传播强度服务品牌资产**：追求点击、转发、评论和二创时不自动降温，但要检查读者会记住作者的什么判断、方法、栏目承诺、人格气质或可信度；如果会吸引错误人群、破坏可信度、偏离作者声音或无法被账号承接，才收窄表达或调整传播路径。
- **品牌要有内在驱动力**：内容品牌不只是定位、栏目、爆款承接和 CTA，也要保留作者持续关心的问题、真实欲望、反感对象、判断代价和风险经验。
- **呼吸感不是降温**：强句之后给具体落点、例子、停顿或行动句。
- **排版密度是功能**：换行、单句成段、列表和空行都必须承担强调、转折、停顿、扫读或结构功能；不得默认一句一行。
- **完整不等于有效**：功能清单、FAQ、参数表、背景说明和长铺垫只有在任务需要时才进入主结构。
- **自然不是随便**：不要把“像人”误判成口水化、废话化或过度聊天腔。目标是自然、清楚、有判断、有现场感。
- **少用二分总结**：避免连续用二分句替代观察和推理。需要改写时，优先改成具体动作、作者判断、转折推进或场景落点。
- **重要性必须有支撑**：不要把普通事实写成关键转折、重大趋势、基础设施变化或行业启示。除非素材里有证据、对比、影响范围或作者明确判断，否则只说事实本身。
- **归因必须落地**：需要来源时，用具体来源、具体观察、用户素材或明确的“待核查”状态；不要用“专家认为、行业观察者、一些资料显示”这类模糊归因补洞。
- **风格词要落地**：“颗粒感、呼吸感、冒犯感、褶皱、体感、人味”等词只能作为诊断标签，交付时要翻译成删对称结构、补具体场景、保留不确定性、加强判断代价、压缩空总结或调整段落密度等动作。
- **风格词不是目标函数**：不得为了追求风格标签新增无素材支撑的细节、故意挑衅、制造假粗糙、加入口癖废话，或把需要的营销、传播、CTA 和强表达磨弱。
- **翻译边界清楚**：用户要求翻译时，默认保留原主张、事实、语气强度和信息边界。润色、本地化、发布约束改写和重写是更高权限动作。
- **平台不生成风格**：平台名只能提供外部限制，不能生成写法。不要因为出现某个平台名就自动套用口语腔、职场腔、种草腔、串联短帖腔、爆款腔或其他平台模板。
- **默认中文输出**：除非用户明确要求英文、翻译成英文、保留英文原文风格，或交付场景本身明确是英文发布，否则 CFlow 默认输出中文。

## 营销和引流

有转化目标的草稿要保留销售语气。不要把硬广、direct response、渠道情报或活动推广自动改成中性说明、FAQ、费用说明或免责声明。

销售或教育型草稿要把关键异议放进正文流动里，不要全部堆到结尾。CTA 前要先建立 desire；异议只在影响转化时处理。

如果内容自然适合承接用户提供的个人资产或 profile，单篇默认只插一个主入口，不把所有链接堆到文末。具体资产清单、链接、邀请码和私有入口来自用户 profile 或资产档案，不写进通用成稿规则。引流会破坏正文节奏时，只在交付后给一句提醒，不强行写入正文；用户明确要求纯内容、不加 CTA 时，不主动插入。

## 长文格式纪律

- 如果 frontmatter 已经有 `title`，正文不要再重复一个 `# H1`。直接从开篇段落或 `##` 小节开始。
- 标题不要承担正文解释功能。标题只放核心概念，具体范围、背景和技术名词放到正文第一段自然引出。
- 小节标题用来帮助读者定位，不用编号制造机械感。除非用户明确要教程编号或文档目录，否则不要写“一、二、三”或“1. 2. 3.”式标题。
- 开篇要尽早点名主角、目标读者和这篇文章要解决的问题。不要用“本文将从多个维度深入探讨”这类空铺垫。
- 文章结尾自然收束。最后一节讲完就可以停，不需要强行加“总结”“最后”“结语”“写在最后”，也不要补文章定位说明或收藏 CTA。
- 文末链接默认服务行动路径。只有用户要求长文阅读体验或归档整洁时，才克制重复链接。

## 质量闸门

出稿前必须自检这些会改变结果的问题：

```text
生产优先级是否满足：先反 AI 味，再结构模板，再传播度：
素材实际支持的字数区间：
目标字数 / 篇幅是否被素材支撑：
需要补充的真实材料：
是否只有一个核心主张：
目标读者是否清楚：
题材结构是否服务主任务：
具体素材是否被充分放大：
用户原话里的强疑问、吐槽、判断和现场反应是否被保留：
是否存在连续 3 个以上无功能短段落：
删掉最后一段后是否更干净：
是否存在重要性膨胀、模糊归因或猜测补洞：
是否存在抽象名词代替人和动作：
是否存在宣布句、假反转、总结句、二分句或边界说明假装推进：
资料型文本是否存在宣传腔、聊天残留、虚假来源或格式残留：
是否为了完整感强行凑三项、挑战展望或通用积极结论：
第一句是否直接进入事实、场景、判断或冲突：
非版本文档是否仍在叙述“新增 / 替代 / 改进”：
是否有一句值得被记住或复述的话：

强句后是否有具体落点、例子、后果或行动：
```

命中失败项时，先处理再交付。不要把检查表完整输出给用户，除非用户要求看诊断过程。

默认 AI 文体的处理方式是结构动作，不是表层人味：删、缩、合并、重排、保留原话、补具体动作、回到素材边界，或标注需要补材料。不要通过故意加废话、错字、口头禅、无素材细节、emoji、机械粗体冒号列表或固定结论来制造人味。
