# 营销转化系统

## 共享合同

营销转化受 `$cflow` 的 `references/content-production-contract.md` 约束。本文件只维护 offer、funnel、CTA 策略、转化桥和营销形态。强表达规则是共享合同在转化场景里的应用。

`cflow-marketing` 只决定转化策略：这次要不要营销化、面向哪个 funnel stage、offer 是什么、主 CTA 是什么、CTA 强度到哪里、转化路径怎么接。已经确定策略后的标题、hook、opening、短发布文案和 CTA 文案变体，交给 `$cflow-package`。

## 夸张边界

营销文案不反感夸张。夸张是制造注意力、紧迫感和欲望的工具，不是天然错误。

应该保留并打磨：

- 强 urgency：最后窗口、即将关闭、这次之后不确定。
- 强利益：门槛低、路径短、成本少、体验顺。
- 强对比：别人还在找渠道，你已经可以直接操作。
- 强 CTA：现在办、看完直接做、别拖到窗口关闭。

默认不处理，除非用户要求严谨、合规、发布限制或品牌安全：

- 不可兑现承诺：绝对安全、稳赚、不亏一分钱。
- 用户明确要求事实严谨时，才检查证据无法承载的确定性。
- 诈骗感话术：连续堆叠封死、错过就完、没有下一批、百分百保证。
- 说明书语气：费用这里要说清楚、值得看一眼、这不是投资建议。

处理原则：

- 不把强营销改成保守说明。
- 用更有压迫感、更能行动的强表达替代无效废话。
- 风险和异议只在用户要求或明显影响转化时处理，不默认放到结尾当免责声明。

例子：

```text
不亏一分钱 -> 汇率损耗比传统换汇路径轻很多
唯一通道 -> 现在对大陆用户最稀缺的一类合规美元卡入口
永久关闭，下次真没了 -> 这次窗口一关，后面能不能再开没人能保证
这张卡值得看一眼 -> 有海外支付、订阅、稳定币消费需求的人，今天就该办完
```

## 营销形态

### 渠道情报 / 机会窗口

适合限时入口、资格窗口、邀请码、注册链接、教程、福利活动、支付/出入金/工具机会。

特征：

- 开头先抛截止时间、入口变化或稀缺窗口。
- 语气像“内行消息”或“群里甩出来的机会”，不是系统产品介绍。
- 直接点名读者能省掉的麻烦、门槛、损耗或时间。
- 使用短句、列表、符号、强对比和明确 CTA。
- 粗糙感可能是资产，只要它增加消息感和行动感。

常用结构：

```text
明天几点关闭 / 只剩多久
这是什么入口
为什么现在稀缺
你能立刻解决什么问题
利益点列表
别人还在找 X，你可以直接 Y
福利补强
邀请码 / 注册链接 / 教程链接
```

不要做：

- 改成“本文介绍某产品”的说明型文章。
- 用完整过渡句稀释短句压力。
- 把利益点列表改成长段落解释。
- 套用 AIDA 导致截止时间、入口和 CTA 后置。
- 因为文案粗糙就抹掉内行感、优越感和紧迫感。

### 入口型转化 / 多链接排序

适合注册链接、返佣链接、邀请码、社群入口、教程入口、领取入口和活动入口。

先判断这次真正要读者点击或执行哪一个动作。排序默认是：

1. 主 CTA：最直接产生转化的链接、邀请码或入口。
2. Offer 补强：为什么现在点、能省什么、少走什么弯路、行动成本有多低。
3. 辅助入口：教程、社群、频道、资料入口等次级动作。
4. 风控信息：防骗、限制、禁言规则、风险提醒。

高意向入口可以链接前置。读者已经接近注册、领取、开户、加群或购买时，不要为了铺垫把主链接藏到最后。

风险提醒要保留，但不要抢首屏。除非用户目标就是风控公告，否则风险提醒默认后置、短句化、只保留会影响行动安全和发布限制的内容。

多链接不要糊成链接堆。每个链接前后只保留能帮助读者判断的最短标签：

```text
主入口：
辅助入口：
防骗提醒：
```

如果用户说“链接前置”“邀请链接前置”“入口前置”，不要按字面猜链接类型。先从上下文判断主 CTA；不确定时给一句判断说明。

### 硬广

适合高意向人群或明确转化场景。

特征：

- 产品、offer 或购买动作直接出现
- CTA 清晰
- 利益、压迫感和行动路径密度高
- 不假装自己不是广告

风险：

- 对冷流量容易显得冒犯
- 欲望不足时会变成强推

### 软广

适合冷流量、内容分发、信任建设或品牌内容。

特征：

- 先服务读者问题
- 产品或 offer 后置
- 用故事、案例、方法或经验建立 desire
- CTA 可以更轻

风险：

- 太软会没有转化动作
- 只讲故事但没有 offer，会浪费营销目标

### Advertorial / Native Ad

适合需要像内容一样被阅读、但仍有明确转化目标的场景。

特征：

- 读起来像文章、案例或报道
- 结构服务转化
- 内容和 offer 之间有自然桥
- 标题和开头不应暴露得像低质量广告

### Direct Response

适合明确要成交、预约、领取、咨询或注册。

特征：

- 目标动作单一
- 使用 AIDA、PAS、故事销售或问题-机制-证明-行动
- 强调 proof、objection handling、urgency 和 CTA

## Funnel Stage

### 冷流量

读者还没有信任或强需求。

优先：

- 读者处境
- 问题命名
- 故事和案例
- 低摩擦 CTA
- lead magnet

避免：

- 过早要求购买
- 直接堆产品功能
- 需要太多前置信任的动作

### 暖流量

读者知道问题，也开始相信作者或品牌。

优先：

- 机制解释
- 对比
- 案例
- 常见异议
- 中摩擦 CTA

### 高意向

读者已经接近行动。

优先：

- Offer 细节
- 价格或方案
- 风险逆转
- FAQ
- 强 CTA
- 购买、预约或咨询路径

## Offer 表达

一个 offer 至少回答：

```text
给谁：
解决什么问题：
交付什么结果：
为什么现在想行动：
为什么现在行动：
下一步是什么：
```

弱 offer 气味：

- 只描述产品，不描述结果
- 只讲功能，不讲读者处境
- 没有能让人立刻动心的理由
- 没有明确下一步
- 对所有人都适用
- 行动成本和读者信任阶段不匹配

## 创作者价值阶梯

当用户要把个人经验、方法论、课程、社群、模板、咨询或软件化工具变成商业系统时，先检查价值阶梯，而不是只写一条强 CTA。

常见层级：

- **免费内容**：命名问题、建立信任、展示判断和吸引对的人。
- **低摩擦产品**：模板、清单、短课、工具包或小额产品，解决一个具体技术问题。
- **高承诺产品**：课程、社群、咨询、训练营或服务，承诺更完整的身份、能力或结果转变。
- **资产化产品**：软件、订阅、数据库、工作流系统或长期工具，把已验证方法固化成可重复使用的资产。

验证纪律：

- “我解决过自己的问题”只是 offer 原料，不等于市场已经验证。
- 上架前至少要确认目标读者、痛点强度、现有替代方案、支付意愿和可交付结果。
- 低价产品优先解决窄问题，高价产品必须有更强 proof、陪伴、反馈或结果路径。
- 软件化和订阅化只适合已经有重复工作流、持续使用场景或迁移成本的问题；不要把没验证的方法过早包装成工具壁垒。
- 如果缺少市场信号，先交给 `$cflow-topic` 找痛点，或交给 `$cflow-benchmark` 拆竞品和对标转化路径。

## CTA 策略

### 低摩擦 CTA

适合冷流量和信任不足时：

- 收藏
- 回复关键词
- 私下领取
- 下载清单
- 查看案例
- 关注后续

### 中摩擦 CTA

适合暖流量：

- 填表
- 加入 waitlist
- 预约诊断
- 领取试用
- 观看 demo
- 加群或进社群

### 高摩擦 CTA

适合高意向：

- 购买
- 付费咨询
- 申请加入
- 签约
- 预约销售电话

CTA 规则：

- 一个内容通常只保留一个主要 CTA。
- CTA 强度必须匹配转化目标；高意向和限时场景可以直接强 CTA。
- CTA 文案要说明动作后会发生什么。
- CTA 文案的具体变体、句式、hook 化包装和发布包落地交给 `$cflow-package`。
- 不要用多个不同目标互相稀释。
- 如果用户提供个人引流资产档案或 profile，选择一个主引流动作。不要把所有链接堆到文末。
- 用户明确说明不方便放链接时，用资料入口、置顶入口、回复关键词、私下领取或账号资料入口做迂回 CTA。

## 个人引流资产调用

默认使用原则：

- 只有用户提供、项目已有或上下文明示个人引流资产时才调用；不要在通用规则里维护具体链接、邀请码或私有资产清单。
- 内容目标和资产明显匹配时，可以提醒用户插入或直接写一个自然 CTA。
- 单篇内容默认只接一个主资产。
- 发布包、资源合集、教程入口和渠道情报可以使用多个入口，但要分层展示。
- 不要为了插入链接破坏正文节奏。先完成内容目标，再选择引流动作。
- 如果用户没有要求引流，提醒要轻，不要每次都输出。

## 转化桥

从内容到行动之间，通常需要一个或多个桥：

- 读者痛点被准确命名
- 失败解决方案被解释
- 机制被说明
- 卖点被具体化
- 案例、故事或场景让行动更想发生
- 异议被提前处理
- 结果被具体化
- 犹豫被压低
- 下一步被讲清楚

如果内容有价值但不转化，通常不是内容不够好，而是缺少转化桥。

产品链接、offer 或付费入口不要突然出现。软广、创始人故事、案例和方法论内容里，优先用真实故事、前后时间对比、结果变化、读者处境或失败解决方案，把行动自然导向产品入口；如果这些素材不存在，标注需要补素材，不要编造经历、结果或截图。

## 常用结构

### PAS

```text
Problem
Agitate
Solution
Proof
Action
```

适合短广告、短推广文案或 landing page 开头。

### AIDA

```text
Attention
Interest
Desire
Action
```

适合 sales copy、advertorial、长广告。

### 故事销售

```text
场景
压力
失败解决方案
转折
机制
结果
offer
CTA
```

适合软广、案例、创始人故事、社群或服务转化。

### 案例转化

```text
客户处境
阻碍
做了什么
结果
为什么有效
读者如何复制
CTA
```

适合 B2B、咨询、社群、课程、服务和工具。

## 交接规则

- 需要生成正文：交给 `$cflow-draft`。
- 需要寻找案例、客户故事、未来预演或反面案例：交给 `$cflow-case`。
- 需要标题、hook、opening、短发布文案或 CTA 文案变体：交给 `$cflow-package`。
- 需要封面、插图、配图或视觉 brief：交给 `$cflow-image`。
- 需要判断是否值得营销化：交给 `$cflow-angle` 或 `$cflow-topic`。
- 需要分析转化结果：交给 `$cflow-review`。
