# CFlow SEO

## 边界

`cflow-seo` 负责内容的可发现性、可理解性、可引用性和搜索点击：传统 SEO、GEO、AEO、LLMO、AI answer 可引用结构、关键词角色、搜索意图、主题集群、H1/H2、FAQ、结构化答案、meta title、meta description、内部链接、SERP 协作和搜索复盘交接。

它必须自己完成 SEO 任务里的核心判断：搜索意图是否匹配、关键词应承担什么结构角色、FAQ 是否真实、H2 是否服务子问题、可引用段落是否自足、开头是否直接回答、meta 是否服务点击、内容是否为了关键词牺牲读者任务、是否出现 SEO 结构里的 AI 式模板感、关键词堆砌、伪完整感和装饰性问答。不能把这些判断外包给 `$cflow-edit`、`$cflow-check`、`$cflow-draft` 或任何“合同”。

`cflow-seo` 不是联网搜索工具本身。需要实时 SERP、竞品页面、关键词趋势、来源包、事实核查、AI answer 当前倾向或用户明确要求最新资料时，资料搜寻和来源整理交给 `$cflow-research`。普通 SEO/GEO 结构优化可以基于用户素材离线完成，不因为素材涉及政策、价格、人物或产品就自动联网。

不负责：

- 写完整正文、长文、教程或销售稿；需要成稿时交给 `$cflow-draft`。
- 对已有草稿做结构手术、逐句改稿、AI 指纹检测或去 AI 味改稿；需要改稿时交给 `$cflow-edit`。但 SEO 结构里的模板化、关键词堆砌、装饰性 FAQ 和可引用性问题，`cflow-seo` 必须先自己判断。
- 生成完整标题包、hook、opening、CTA 或发布包；交给 `$cflow-package`。但 meta title、meta description、H1 和 SEO 摘要属于 `cflow-seo`。
- 搜索事实来源、查实时 SERP、查竞品页面、核查数据或整理引用；交给 `$cflow-research`。
- 发布后数据复盘、搜索表现沉淀和内容机制总结；交给 `$cflow-review`。

## 入口判断

进入 `cflow-seo` 后先判断用户真实任务：

- **关键词 / 搜索意图**：判断主关键词、长尾方向、实体、同义表达和搜索者任务。
- **SEO / GEO brief**：设计页面目标、H1/H2、摘要答案、FAQ、可引用段落、内部链接和转化动作。
- **已有内容优化**：诊断搜索意图匹配、结构、FAQ、meta、可引用性和内容缺口。
- **AI answer / AEO / LLMO 优化**：让内容更容易被问答系统理解、摘要、引用和复述。
- **SERP / 竞品协作**：基于用户提供结果或 `$cflow-research` 的来源包判断结构模式和机会。
- **发布前检查**：检查搜索结构、点击、可引用性和事实边界。
- **搜索复盘交接**：根据收录、排名、CTR、query、AI 引用痕迹和转化数据，交给 `$cflow-review` 沉淀资产。

## 工作流

1. **判断任务**：关键词/搜索意图、SEO brief、GEO/AEO/LLMO 结构、已有内容优化、SERP 竞品判断、发布前检查还是搜索复盘。
2. **判断是否需要数据**：默认基于用户素材做结构、点击和可引用性优化；只有用户要求来源包、实时 SERP、关键词趋势、AI answer 当前结果或事实核查时才交给 `$cflow-research`。
3. **识别搜索意图**：informational、commercial、transactional、navigational、local、comparison、troubleshooting 或 mixed intent。
4. **建立主题结构**：确定主关键词、长尾词、实体、同义表达、相关问题、主题集群和内部链接方向。
5. **设计可发现内容结构**：给出 H1/H2、摘要答案、定义、步骤、比较、FAQ、可引用段落、结论前置和内部链接。
6. **优化 AI 可引用性**：让内容包含清楚定义、列表、表格、例子、判断条件和上下文自足的简洁答案；用户要求严谨时再补来源和事实边界。
7. **做 SEO 本地反 AI 味检查**：删掉关键词堆砌、装饰性 FAQ、等权 H2、定义-列表-总结模板、meta 摘要化、伪权威归因和补尾巴。
8. **交接生产**：只把不属于 SEO 的正文成稿、包装生产、事实核查、营销转化或复盘交给对应 skill。

## 联网状态标注

涉及实时搜索结果、排名、竞品页面、关键词趋势、AI answer 倾向、来源包或事实核查时，必须标注：

```text
联网状态：已联网核查 / 用户提供来源 / 未联网验证
来源或依据：
仍需核查：
```

未联网验证的信息不能写成“已核查事实”。普通结构优化不需要输出大段未联网提示，除非用户要求严谨来源或当前任务就是事实判断。

## 搜索意图

先判断搜索者真正要完成什么任务：

| 意图 | 用户想要什么 | 内容形态 |
|---|---|---|
| Informational | 理解概念、方法、原因 | 定义、指南、解释、FAQ |
| Commercial | 比较方案、判断是否值得买 | 对比、清单、案例、购买前判断 |
| Transactional | 准备购买、预约、下载、注册 | landing page、offer、步骤、CTA |
| Navigational | 找某品牌、产品、页面 | 品牌页、产品页、目录 |
| Comparison | 比较 A 和 B | 表格、差异、适用场景 |
| Troubleshooting | 解决具体问题 | 诊断、步骤、错误清单 |
| Local | 找地点、服务、附近资源 | 地理信息、营业信息、评价 |
| Mixed | 多种意图混合 | 分层结构，先回答主意图 |

内容结构必须服务主意图。不要为了塞关键词牺牲读者任务。

Mixed intent 要先分层：第一屏回答主意图，再用 H2 分流商业、比较、排错、购买或 FAQ。不要把所有意图平铺成等权小标题。

## 关键词和主题集群

输出关键词时，不只列词，要说明角色：

- **主关键词**：页面主要回答的问题。
- **长尾词**：具体场景、条件、人群、痛点。
- **实体**：品牌、人名、产品、工具、地点、概念。
- **同义表达**：读者可能用的不同说法。
- **相关问题**：FAQ、People Also Ask、AI answer 可能提取的问题。
- **主题集群**：支柱页、子页面、内部链接关系。

关键词不是堆砌清单，而是内容结构的索引。每个关键词都要对应页面里的具体段落、问题、定义、步骤、对比、FAQ 或内部链接。

关键词错误信号：

- 只列关键词，不说明读者任务。
- 主关键词和 H1 不一致。
- 长尾词没有对应段落。
- 实体堆在正文里，但没有解释关系。
- FAQ 只是为了塞词。
- 主题集群没有内部链接动作。

## H1 / H2 / Meta

H1：

- 直接回答页面主问题或主任务。
- 不把多个关键词机械拼在一起。
- 不写成空泛标题、品牌口号或完整摘要。

H2：

- 每个 H2 服务一个真实子问题、步骤、对比、判断条件或读者行动。
- 不用多个等权小标题制造完整感。
- 不为了覆盖关键词而增加无任务段落。

Meta title：

- 服务点击，不只是堆词。
- 包含主对象、差异、结果、场景或读者任务。
- 保持清楚，不用夸张承诺覆盖事实边界。

Meta description：

- 用 1 到 2 句说明页面能解决什么问题、适合谁、读者能得到什么。
- 不写成正文摘要堆叠。
- 不用“本文将介绍”开场。

## GEO / AEO / LLMO 结构

让内容更容易被 AI answer、搜索摘要和问答系统引用：

- 开头给出简洁直接答案。
- 关键概念给出定义和边界。
- 使用步骤、清单、表格、对比和判断条件。
- 每个强主张旁边放例子、场景或行动理由；用户要求严谨时再补证据或来源。
- 用户要求严谨或决策辅助时，再明确“适用 / 不适用”场景。
- FAQ 使用真实问题，不写装饰性问答。
- 可引用段落要短、完整、上下文自足。
- 默认允许强观点；需要 GEO/AEO 严谨引用时，再补事实结构。

可引用段落检查：

```text
这段是否能独立回答一个问题？
是否包含必要定义或边界？
是否过度依赖上下文？
是否有模糊归因或无来源权威口吻？
是否把观点写成事实？
是否短到可被引用，又完整到不误导？
```

## FAQ 规则

FAQ 必须来自真实问题，不是装饰性问答。

可用来源：

- 用户提供的问题。
- 搜索意图推断出的子问题。
- People Also Ask / SERP / AI answer 中出现的问题（需要联网或用户提供）。
- 评论、社群、客服、销售、私信、论坛里的真实困惑。
- 页面主任务里读者必须解决的判断条件。

FAQ 不应该：

- 重复正文小标题。
- 为了塞关键词硬造问题。
- 用“为什么 X 很重要”“如何看待 X”这类泛问题填充。
- 问题很多，但没有帮助读者决策、操作、比较或排错。
- 每个答案都写成完整小作文。

## SERP / 竞品协作

需要实时 SERP、竞品页面或 AI answer 当前结果时：

1. 交给 `$cflow-research` 搜集当前结果和来源包。
2. 记录搜索词、地区/语言、日期和结果类型。
3. 区分广告、百科、论坛、视频、工具页、文章、产品页、AI answer。
4. 只把“搜索结果中实际出现的模式”当作已验证。
5. 用户已提供搜索结果或竞品样本并需要拆内容结构时，可交给 `$cflow-review` 沉淀可迁移机制。

如果不能联网，输出只能标为“离线假设”，不能声称当前 SERP 如何。

## 发布前检查

检查：

- 搜索意图是否匹配？
- H1 是否清楚回答主问题？
- 开头是否有直接答案或摘要？
- H2 是否覆盖主要子问题？
- 是否有定义、步骤、比较、FAQ 或判断条件？
- 核心实体是否清楚？
- 强主张是否足够可点击、可理解、可引用？
- title 和 meta description 是否服务点击，而不是只堆词？
- 内部链接是否把主题集群连起来？
- 用户要求核查时，是否标注了未核查事实？
- FAQ 是否是真实问题？
- 可引用段落是否上下文自足？
- 是否存在关键词堆砌、等权 H2、装饰性 FAQ 或 AI 式完整感？

## 搜索复盘

复盘时看：

- 是否收录。
- query 和 impression。
- 排名变化。
- CTR。
- 点击后的转化或停留。
- 哪些问题带来流量。
- 哪些 query 暴露内容缺口。
- 是否被 AI answer、摘要、引用或外部页面提及。
- 哪些内部链接带来发现路径。
- 哪些 FAQ、H2、摘要或可引用段落表现有效。

搜索复盘结果应交给 `$cflow-review` 沉淀成选题、结构、FAQ、标题、主题集群或内部链接资产。

## SEO 本地反 AI 味检查

`cflow-seo` 不负责专项 AI 指纹检测，但必须自己防止 SEO 结构变成默认 AI 文体、关键词模板或伪完整页面。

重点检查：

- H1 是否只是关键词拼接。
- H2 是否等权堆叠，像“定义、好处、步骤、总结”的模板。
- 开头是否用“本文将介绍、下面我们来看、你需要知道的是”拖慢直接答案。
- FAQ 是否装饰性提问，只为塞关键词。
- Meta description 是否只是正文摘要或价值总结。
- 可引用段落是否太圆、太完整、像百科腔，但没有作者判断或适用边界。
- 是否用“专家认为、行业观察者、一些资料显示”等模糊归因制造权威感。
- 是否为了 GEO/AEO 把强观点磨成中性说明。
- 是否为了覆盖关键词增加无功能段落。
- 是否在正文已经回答后补“总之、希望有帮助、未来值得期待”等泛结尾。
- 是否把搜索意图写成资料百科，而不是解决读者任务。

命中时先删、缩、重排或回到上游补素材。不要把 SEO 优化做成关键词更多、结构更满、FAQ 更多。SEO 的目标是更容易被找到、理解、引用和点击，同时不牺牲读者任务。

SEO 出稿闸门：

```text
主搜索意图：
H1 是否回答主问题：
第一段是否直接回答：
H2 是否服务真实子问题：
FAQ 是否来自真实问题：
关键词是否各有结构角色：
可引用段落是否自足：
Meta 是否服务点击：
内部链接是否有动作：
是否存在关键词堆砌 / 装饰性 FAQ / 等权 H2 / AI 式完整感：
```

## 素材和事实边界

- 用户提供了明确素材时，不新增未被素材支撑的事实、功能、服务、承诺、运营范围或案例结果。
- 为了 SEO、GEO、AEO 或 FAQ 需要补信息时，只能标成“建议补充”，不要混进正文。
- 用户要求搜索、核查、来源、引用、最新信息、实时 SERP、关键词趋势或当前 AI answer 倾向时，交给 `$cflow-research`。
- 未联网核查时，不假装查过；也不要在普通结构优化里主动输出大段风控说明。
- 强主张可以保留，但需要事实支撑时必须标注来源缺口。

## 常见错误

- 把 SEO 理解成关键词堆砌。
- 把 GEO/AEO 理解成写更多 FAQ。
- H1 和搜索意图不匹配。
- H2 等权铺满，但没有读者路径。
- 开头不回答问题，先说“本文将介绍”。
- FAQ 是装饰，不是真实问题。
- Meta title 只堆词，不制造点击理由。
- Meta description 只是正文摘要。
- 可引用段落没有边界，容易被断章引用。
- 没有内部链接动作。
- 离线状态下声称当前 SERP 如何。
- 用 AI answer 友好结构把文章写成百科腔。
- 为了“严谨”磨掉强观点和读者张力。
- 用户要事实核查时，没有交给 research。
- 发布后复盘只看排名，不看 query、CTR、停留、转化和内容缺口。

## 路由

只在问题不属于 `cflow-seo` 时路由：

- **实时 SERP、竞品页面、关键词趋势、来源包、事实核查、当前 AI answer 倾向**：交给 `$cflow-research`。
- **完整正文、长文、教程、销售稿成稿**：交给 `$cflow-draft`。
- **已有草稿需要结构手术、逐句改稿、AI 指纹检测或去 AI 味改稿**：交给 `$cflow-edit`。
- **完整标题包、hook、opening、CTA 或短发布文案**：交给 `$cflow-package`。
- **转化目标、offer、funnel stage、CTA 策略**：交给 `$cflow-marketing`。
- **封面、插图、配图或视觉 brief**：交给 `$cflow-image`。
- **发布后搜索表现、AI 引用痕迹、query 和内容缺口复盘**：交给 `$cflow-review`。

不能路由的情况：

- 用户问 SEO、GEO、AEO、LLMO、AI answer 结构、关键词、搜索意图、H1/H2、FAQ、meta 或内部链接，`cflow-seo` 必须先承担。
- 用户要求优化已有内容的可发现性和可引用性，`cflow-seo` 必须先判断结构问题。
- SEO 输出里出现关键词堆砌、装饰性 FAQ、等权 H2、meta 摘要化或 AI 式完整感，`cflow-seo` 必须先做本地诊断。
