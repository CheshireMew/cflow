# SEO / GEO / AEO 系统

## 搜索意图

先判断搜索者真正要完成什么任务：

| 意图 | 用户想要什么 | 内容形态 |
|---|---|---|
| Informational | 理解概念、方法、原因 | 定义、指南、解释、FAQ |
| Commercial | 比较方案、判断是否值得买 | 对比、清单、案例、购买前判断 |
| Transactional | 准备购买、预约、下载、注册 | landing page、offer、步骤、CTA |
| Navigational | 找某品牌、产品、页面 | 品牌页、产品页、目录 |
| Comparison | 比较 A 和 B | 表格、差异、适用场景 |
| Troubleshooting | 解决具体问题 | 诊断、步骤、错误清单 |
| Local | 找地点、服务、附近资源 | 地理信息、营业信息、评价 |
| Mixed | 多种意图混合 | 分层结构，先回答主意图 |

内容结构必须服务主意图。不要为了塞关键词牺牲读者任务。

## 关键词和主题集群

输出关键词时，不只列词，要说明角色：

- **主关键词**：页面主要回答的问题。
- **长尾词**：具体场景、条件、人群、痛点。
- **实体**：品牌、人名、产品、工具、地点、概念。
- **同义表达**：读者可能用的不同说法。
- **相关问题**：FAQ、People Also Ask、AI answer 可能提取的问题。
- **主题集群**：支柱页、子页面、内部链接关系。

关键词不是堆砌清单，而是内容结构的索引。

## GEO / AEO / LLMO 结构

让内容更容易被 AI answer、搜索摘要和问答系统引用：

- 开头给出简洁直接答案。
- 关键概念给出定义和边界。
- 使用步骤、清单、表格、对比和判断条件。
- 每个强主张旁边放例子、场景或行动理由；用户要求严谨时再补证据或来源。
- 用户要求严谨或决策辅助时，再明确“适用 / 不适用”场景。
- FAQ 使用真实问题，不写装饰性问答。
- 可引用段落要短、完整、上下文自足。
- 默认允许强观点；需要 GEO/AEO 严谨引用时，再补事实结构。

## SERP / 竞品协作

需要实时 SERP 或竞品页面时：

1. 交给 `$cflow-research` 搜集当前结果和来源包。
2. 记录搜索词、地区/语言、日期和结果类型。
3. 区分广告、百科、论坛、视频、工具页、文章、产品页、AI answer。
4. 只把“搜索结果中实际出现的模式”当作已验证。
5. 深度拆内容结构时交给 `$cflow-benchmark`。

如果不能联网，输出只能标为“离线假设”，不能声称当前 SERP 如何。

## 发布前检查

- 搜索意图是否匹配？
- H1 是否清楚回答主问题？
- 开头是否有直接答案或摘要？
- H2 是否覆盖主要子问题？
- 是否有定义、步骤、比较、FAQ 或判断条件？
- 核心实体是否清楚？
- 强主张是否足够可点击、可理解、可引用？
- title 和 meta description 是否服务点击，而不是只堆词？
- 内部链接是否把主题集群连起来？
- 用户要求核查时，是否标注了未核查事实？

## 搜索复盘

复盘时看：

- 是否收录
- query 和 impression
- 排名变化
- CTR
- 点击后的转化或停留
- 哪些问题带来流量
- 哪些 query 暴露内容缺口
- 是否被 AI answer、摘要、引用或外部页面提及
- 哪些内部链接带来发现路径

搜索复盘结果应交给 `$cflow-review` 沉淀成选题、结构、FAQ、标题或主题集群资产。
