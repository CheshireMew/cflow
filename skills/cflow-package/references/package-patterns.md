# 包装模式

## 共享合同

包装受 `$cflow` 的 `references/content-production-contract.md` 约束。本文件只维护标题、hook、开头、CTA、caption 和平台包装的应用规则。

## 包装资产

- 标题
- Hook
- 开头段
- 副标题
- CTA
- Caption
- Thread 第一条
- 短视频前三秒
- 平台专用版本

## 强张力来源

- 读者错误
- 隐藏代价
- 前后对比转变
- 反直觉区分
- 具体受众处境
- 决策取舍
- 具体结果
- 被经验挑战的常见认知

## Copywriting 机制

- **Mind the gap**：制造一个具体、未解决的张力，让读者必须继续看。Hook 不能只是总结内容。
- **Punch first**：第一句要能打断注意力。除非平台奖励上下文，否则不要软铺垫。
- **Slippery slope**：把共享合同里的“每句话有功能”应用到包装资产上，让下一句自然被读下去。
- **用标题筛选读者**：标题可以点名窄人群、身份、地点、状态、问题或欲望。无关读者不点进来是好事。
- **具体性强化强烈程度**：用具体门槛、场景、身份和素材承载强表达，不要只加形容词。
- **Open loop 先抓住人**：默认优先制造继续看的冲动；只有用户要求严谨包装或品牌安全时，才严格审查兑现边界。

## 标题和 Hook 策略标签

生成选项时，每个选项至少标注一个策略：

- **认知冲突**：打破读者已有判断。
- **好奇缺口**：点出未解释的信息差。
- **恐惧/损失**：命名读者正在付出的代价。
- **身份代入**：直接点名人群、处境、阶段或角色。
- **数字锚定**：用数量、时间、门槛、比例形成抓手。
- **结果承诺**：说明读者会得到的具体结果。
- **社会证明**：引用特定人群、案例、数据或可见反馈。
- **争议/挑衅**：挑战流行观点，把读者拖进判断。
- **场景/条件**：把内容放进具体使用场景。
- **行动号召**：直接要求下一步，通常配合 CTA。

策略标签不是装饰。标不出策略的选项，大概率只是同义改写。

## Hook 生成和重做检查

生成标题、开头、前三秒或推广文案时，先检查 hook 是否真的制造了进入理由，而不是只把原文概括得更顺。用户要求“更吸引人”“有点击欲”“反常识”“有技巧”，或反馈“平淡”“像提醒”“没有 hook”时，默认属于包装策略失败，要换策略组重做。

优先检查：

- 是否点名具体读者、身份、阶段、场景或任务。
- 是否说出读者正在付出的痛点、代价、风险或错误。
- 是否在第一屏给出潜在利益，让读者知道继续看会发生什么变化。
- 是否用具体数字、时间、门槛、结果、金额、比例或步骤承载强表达。
- 是否有真实素材支撑 social proof；没有素材时不要编结果、截图、资质或群体反馈。
- 警告、劝诫和避坑是否来自经验、案例、常见错误或合理推断，而不是空泛恐吓。
- 自信语气是否匹配任务和事实边界。观点、营销和短内容可以强；研究、事实判断、合规和高风险内容要保留必要限定。
- 是否有 pattern interrupt：反常识、句式断点、强对比、异常数字、视觉排版或第一句打断，但不能为了打断而牺牲理解。

重做时至少覆盖 3 种不同策略，例如认知冲突、损失规避、身份差距、信息差或行动压力。不要输出 5 个同义提醒句；每个候选都要能说明它为什么会让目标读者继续看或点击。

## 开头质量门槛

短视频或社交平台开头必须独立成立。不要假设读者已经看过标题、视觉资产或上下文。

好开头通常同时包含：

```text
话题：这条内容在说什么
Hook：为什么现在要听
行动理由：为什么读者现在应该继续看
```

前三秒不要只重复标题。开头应带来新信息、新张力或新场景。

## AIDA 销售包装

当内容有销售或转化目标时使用 AIDA：

```text
Attention：打断准确读者
Interest：描述熟悉处境或未解决问题
Desire：建立信念、转变、利益和情绪拉力
Action：欲望存在后再要求下一步
```

不要在读者还没有理由关心前就抛产品、价格或 CTA。价格必须出现时，把它放进结果或体验里，而不是裸折扣。

例外：渠道情报型、机会窗口型、限时入口型文案按 `$cflow-marketing` 的入口型转化规则处理；它的关注理由就是入口、截止时间、资格和可操作链接本身，不要为了 AIDA 把产品和 CTA 后置。

## 渠道情报型包装

渠道情报、机会窗口和入口型转化的完整判断归 `$cflow-marketing`。`cflow-package` 只负责把已确定的主入口、窗口变化、读者利益和行动压力包装成标题、首句、前三秒或 CTA。

包装侧保留：

- 消息感、短句、列表、压迫感和信息差。
- 主入口靠前，风险提醒后置压缩。
- 标题和首句不要改成中性产品介绍。

## Pressure Before Claims

包装产品、服务或说服型内容时，优先把强主张落到可感知素材上：

- 前后对比
- 截图或指标
- 具体客户场景
- 来自特定人群的 social proof
- 能回答异议的个人轶事
- 可见转变，而不是产品描述

如果素材不够，广告、短视频、小红书、viral 和限时活动场景仍先产出强版本。只有严肃论证、研究型内容、事实判断或用户主动要求时，才标出证据缺口。

## 推广和分享文案

当用户要为文章、newsletter、blog 或外部链接写推广文案时，包装目标不是复述全文，而是找到一个强、准、能让人点开的进入点。

- 不要摘要全文。推广文案只需要暴露最值得点开的张力、问题、判断或具体细节。
- 链接是自然下一步，不是硬贴附件。读者读完前文应知道为什么继续点开。
- 文案必须自洽。读者即使暂时不点链接，也应该知道这条内容的价值是什么。
- 默认基于原文素材放大，不另造新信息、数据、案例或结论；用户要求严谨包装时，再检查 hook 和原文支撑关系。
- 每个候选要使用不同进入点，例如一个从反常识进入，一个从具体场景进入，一个从读者损失进入；不要只是换同义词。
- 如果原文没有足够张力，先从读者损失、场景、反常识、身份或行动压力里找更锋利的进入点。只有用户要求严谨包装时，才把支撑缺口作为问题展开。

判断推广 hook 是否成立：

```text
这句话是否足够让目标读者想点开？
读者是否知道为什么要点开？
这句话是否只是摘要，而不是进入点？
删掉链接后，文案是否仍然有信息价值？
```

## 个人引流 CTA 包装

当内容适合接作者个人引流资产时，资产清单以用户提供的 profile 或资产档案为准。`cflow-package` 只负责把入口包装得自然、短、适合平台，不维护具体链接、邀请码或私有资产清单。

常用包装方式：

- **直接链接**：适合允许裸链、且链接不会破坏阅读的平台。
- **主页简介**：适合 X、视频号、小红书等不方便放链接或链接会影响阅读的平台。
- **评论关键词**：适合短视频、小红书、私域承接。
- **私信关键词**：适合需要筛选意向或不想公开链接时。
- **置顶入口**：适合系列内容、长期资源或多个链接并存时。

包装纪律：

- 单篇内容默认只保留一个主引流动作。
- CTA 要接内容场景，不要机械写“欢迎关注/欢迎订阅”。
- 不方便放链接时，不要硬塞裸链，改成“入口在主页简介”“置顶里有”“私信我关键词”。
- 如果内容不适合引流，只在交付后轻提醒，不强行写进正文。

## 平台模式

### 小红书/RED

- 读者和利益要具体。
- 文案要方便扫读。
- 避免模糊的成长、效率、逆袭承诺。

### 短视频

- 从张力或场景开始。
- 用口语。
- 避免长铺垫。
- 一句话一个拍点。
- 高留存脚本要在观众离开前，用新细节、转折或 open loop 刷新注意力。

### LinkedIn

- 使用职业张力。
- 自信要匹配作者和平台语境。克制不是降温；锋利判断、明确立场和强结果仍然可以使用。
- 避免无功能假脆弱。强叙述、强反差和强判断可以保留。

### Twitter/X

- 压缩主张。
- 每条只推进一个想法。
- 第一条要制造好奇，但不能隐藏主题。

## 翻译和本地化边界

当用户要求翻译、英文版或跨语言发布时，先区分任务权限：

- **翻译**：保留原文主张、事实、语气强度和信息顺序，优先自然准确。
- **润色**：在不改变主张和事实边界的前提下，让目标语言更顺。
- **本地化**：允许替换不自然表达和平台习惯，但不新增原文没有的事实、案例、承诺或结论。
- **平台重写**：可以重排、压缩、强化 hook 或 CTA，但必须是用户明确要求或任务显然需要。

不要把“翻译成英文”自动做成 Tech Twitter 爆款改写。没有用户授权时，避免新增平台俚语、夸张隐喻、emoji、行业黑话、具体人物案例或原文没有的判断。

### Newsletter 或 Blog

- 优先耐用承诺和清晰范围。
- 避免和正文气质不匹配的社交平台式兴奋；如果内容目标是推广、招募或限时转化，可以保留更强的标题压力和 CTA。

## 变体规则

- 生成不同策略的选项，不要只换同义词。
- 保持主张有冲击力。
- 只有用户要求严谨、合规或品牌安全时，才检查事实和承诺边界。
- 具体性用来承载刺激感，而不是替代刺激感。
- 让最佳选项容易被选择。
- 区分 hook 质量和正文质量：弱 hook 会杀死强内容，强 hook 也救不了空内容。
