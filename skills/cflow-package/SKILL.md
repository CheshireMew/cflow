# CFlow Package

## 边界

只负责文本呈现和包装资产。默认可以为了点击、停留和行动压力重排表达；只有用户要求最小改动、严谨包装或作者声音时，才限制改动幅度。封面、插图、配图、thumbnail text、cover text、视觉 brief 和图片 prompt 归 `$cflow-image`。硬广/软广、offer、funnel stage、CTA 类型、CTA 强度和转化路径归 `$cflow-marketing`。作者人格、表达禁区和 voice profile 归 `$cflow-voice`。

`cflow-package` 是包装表达层，不是转化策略层。它可以把已经明确的 CTA 策略写成更自然、更有点击欲或更有行动压力的文案变体，但不独立决定 offer、主 CTA、funnel stage 或转化路径。CTA 策略不清时，先交给 `$cflow-marketing`。

普通介绍、记录、发现型文章不自动补 CTA 或收藏提醒。只有任务明确是包装、发布包、营销、资源型内容，或 brief 已定义主动作时，才生成 CTA。不得在正文已经自然结束后顺手补“如果你也……可以收藏”。

包装默认放大冲击力、点击欲和行动欲。强标题、强 hook、强 CTA、强刺激不是问题；只有用户要求严谨、合规、品牌安全或发布限制时，才检查承诺是否过度、正文是否完全兑现。

包装前先判断可放大的张力。弱 hook 会杀死内容；如果素材不够，先用现有素材生成最有冲击力的版本。广告、viral 和限时活动场景里，不要因为“刺激”就自动降温。

包装前按 `$cflow` 的 profile 发现规则检查 `profiles/content-assets/` 是否有匹配的包装、hook、CTA、资源包装或短发布文案资产。匹配资产只提供策略和结构，不替代当前素材张力。

用户要求“更吸引人”“有点击欲”“反常识”“有技巧”，或反馈“平淡”“像提醒”“没有 hook”时，必须按不同策略重做候选。不要只把原句改顺；至少给出 3 种策略不同的 hook，并标注策略来源。

包装也受共享合同里的“防止默认 AI 文体”生产约束。`cflow-package` 只保留包装场景里的执行重点：标题、opening、CTA 必须来自素材里的真实张力、作者判断、读者代价或行动压力；用户要求检测哪里像 AI 时，交给 `$cflow-edit`，不要在 package 里直接做“去 AI 味”。

用户亲自修改标题、hook、opening、CTA 或短发布文案时，不能只评价“更好”。必须反向提炼：用户加了什么、删了什么、张力从哪里变强、哪些词更贴作者声音，以及这条改动属于通用包装机制还是个人 voice 偏好。亲历发现型文章优先保留用户原话里的主语和动作，不要为了标题简洁删掉“我让、我试、我发现、结果”这类现场结构。

## 工作流

1. 明确读者、核心主张、篇幅、交付形态、发布约束和希望读者采取的行动。
2. 检查是否有匹配的内容资产，并读取当前任务需要的资产卡片或模式。
3. 检查内容有哪些可放大的张力、利益和行动压力。
4. 从内容中提取最可点击、最能推动行动的张力。
5. 按类型生成包装选项：标题、hook、opening、subtitle、CTA 或短发布文案；只有主动作明确时才生成 CTA。
6. 每个选项标注策略来源，例如认知冲突、好奇缺口、身份代入、数字锚定、恐惧损失、结果承诺、社会证明、场景条件、行动号召。
7. 选项要策略不同，不要只是同义改写。
8. 如果用户已经反馈上一版平淡或没技巧，必须换策略组，不要沿用同一种提醒式表达。
9. 用户给出修改版时，先提炼修改机制，再基于机制继续优化；不要只说“这个更好”。
10. 按共享合同检查是否套模板、磨平作者气口、用总结句或空泛冲突替代真实张力。
11. 用户要求“能不能发、发哪版、怎么发”时，交给 `$cflow-check` 做发布前质检；`cflow-package` 只接收质检后的包装任务，例如标题、hook、opening、CTA 或短发布文案。
12. 标出最佳选项，并简要说明选择标准。
13. 只有用户要求作者声音时，才把标题、hook 或 CTA 交给 `$cflow-voice` 校准。
14. 如果 CTA 类型、CTA 强度、offer、funnel stage 或转化路径不清，先交给 `$cflow-marketing`。
15. 发布后有数据时交给 `$cflow-review`。

## 输出

标题或 hook 请求：

- 最佳选项
- 备选项
- 每个选项的策略标签
- 为什么最佳
- 可以继续加压的方向

发布包请求：

- 标题或 headline
- 开头或 hook
- 必要的正文框架
- CTA
- 发布约束说明
- 策略说明

发布前质检请求：

- 交给 `$cflow-check`
- 如果质检结论是包装问题，再接收标题、hook、opening、CTA 或短发布文案任务
