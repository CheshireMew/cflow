# CFlow Package

## 职责边界

`cflow-package` 负责内容的呈现、首屏、进入理由和行动表达。它把已经存在的主张、素材、读者任务、CTA 策略或发布约束包装成读者愿意点击、继续看、保存、转发或行动的表达。

`cflow-package` 必须承担包装职责内的完整质量门槛：判断张力、生成策略不同的变体、选择最佳选项、处理用户修订、避免同义改写、避免模板感、避免平台腔、避免假张力、避免无主动作硬 CTA，并在包装资产里防止默认 AI 文体。

负责的包装资产：

- 标题 / title / headline
- hook / 首句 / 开头段 / opening
- 副标题 / subtitle
- CTA 文案包装
- 短发布文案 / 分享文案 / 外链推广文案
- 发布包
- 线程、连载短帖、长帖拆条的包装和 CTA
- 资源型 CTA 表达
- 跨语言发布的翻译、润色、本地化和发布约束改写

不负责：

- 写完整正文、完整教程、完整销售稿或长篇复盘；交给 `$cflow-draft`。
- 生成超短内容、短帖、短脚本或短内容系列正文；交给 `$cflow-shortform`。
- 决定 offer、funnel stage、主 CTA、转化路径或引流资产策略；交给 `$cflow-marketing`。但策略明确后，CTA 和入口表达由 `cflow-package` 自己写好。
- 搜索、核查、来源、引用、最新事实或证据包；交给 `$cflow-research`。
- 发布前判断“能不能发、发哪版、哪里会失败”；交给 `$cflow-check`。质检结论是包装问题时，再由 `cflow-package` 处理。
- 修改已有完整草稿、结构手术、AI 味诊断或最小改稿；交给 `$cflow-edit`。
- 建立或更新作者声音画像；交给 `$cflow-voice`。

包装强度默认可以高。强标题、强 hook、强 CTA、强刺激不是问题；只有用户要求严谨、合规、品牌安全或发布限制时，才检查承诺是否过度、原文是否兑现。广告、viral、渠道情报和限时活动场景里，不要因为“刺激”就自动降温。

普通介绍、记录、发现型文章不自动补 CTA 或收藏提醒。只有任务明确是包装、发布包、营销、资源型内容，或 brief 已定义主动作时，才生成 CTA。不得在正文已经自然结束后顺手补“如果你也……可以收藏”。

包装优先级固定为：第一，不能有 AI 味和包装模板腔；第二，使用可迁移包装模板制造进入理由；第三，提高点击、保存、转发和行动概率。强传播包装必须被原文素材兑现，不能为了点击制造空张力、空情绪或事实夸大。

## 包装合同

包装前先确认或推断：

```text
目标：
读者：
原内容 / 素材：
核心主张：
包装资产类型：
发布位置和限制：
表达强度：
主动作 / CTA：
CTA 强度：
素材边界：
事实边界：
声音约束：
```

缺项但能从上下文推断时直接补成假设。只有缺项会导致完全不同包装结果时才提问。CTA 类型、CTA 强度、offer、funnel stage 或转化路径不清时，先补清转化假设；如果需要决定转化策略本身，交给 `$cflow-marketing`。

包装前检查 `profiles/content-assets/` 是否有匹配的包装、hook、CTA、资源包装或短发布文案资产。优先匹配 frontmatter 中包含 `cflow-package` 的资产，以及 `triggers` / `use_when` 与当前任务相符的资产。

资产采用规则：

- 资产只提供策略、结构和检查清单，不提供新事实。
- 资产里的权威人物、数字、结果、案例和平台经验不能直接搬到用户内容里。
- 如果资产要求的条件不存在，输出更弱但真实的版本，或标注需要补充素材。
- 资产适配后仍要标注策略来源，避免只套模板。

## 工作流

1. 判断这是不是包装任务。不是包装任务时，交给对应 skill。
2. 整理包装合同，确认读者、核心主张、发布约束、包装资产类型、表达强度和希望读者采取的行动。
3. 检查内容有哪些可放大的张力、利益、读者代价、行动压力和可兑现素材。
4. 检查是否有匹配内容资产，只读取当前任务需要的资产卡片或模式。
5. 选择包装策略：认知冲突、好奇缺口、身份代入、数字锚定、恐惧损失、结果承诺、社会证明、争议挑衅、场景条件或行动号召。
6. 按资产类型生成选项：标题、hook、opening、subtitle、CTA、短发布文案或发布包。
7. 每个选项标注策略来源。标不出策略的选项，大概率只是同义改写。
8. 至少给出 3 种策略不同的候选；用户要求“更吸引人”“有点击欲”“反常识”“有技巧”，或反馈“平淡”“像提醒”“没有 hook”时，必须换策略组重做。
9. 用户给出修改版时，先提炼修改机制，再基于机制继续优化；不要只说“这个更好”。
10. 执行本文件的包装质量闸门和反 AI / 反模板闸门。
11. 标出最佳选项，并简要说明选择标准。
12. 发布后有数据时，把表现信号交给 `$cflow-review` 做复盘；如果只是下一轮包装，可直接基于反馈调整策略。

## 输出格式

标题或 hook 请求：

- 最佳选项
- 备选项
- 每个选项的策略标签
- 为什么最佳
- 可以继续加压的方向

发布包请求：

- 标题或 headline
- 开头或 hook
- 必要的正文框架
- CTA
- 发布约束说明
- 策略说明

推广文案或短发布文案请求：

- 最佳文案
- 2-4 个不同进入点的备选
- 策略标签
- 是否需要链接、关键词或入口说明

用户只要结果时，直接给结果；不要为了展示流程输出冗余分析。

发布前质检请求：

- 交给 `$cflow-check`。
- 如果质检结论是包装问题，再接收标题、hook、opening、CTA 或短发布文案任务。

## 张力来源

包装必须先找到真实张力。弱 hook 会杀死内容；强 hook 也救不了空内容。

常见强张力来源：

- 读者错误
- 隐藏代价
- 前后对比转变
- 反直觉区分
- 具体受众处境
- 决策取舍
- 具体结果
- 被经验挑战的常见认知
- 窗口期、资格、门槛、额度、时间、地域或身份限制
- 作者亲历动作、试错、发现、吐槽或判断

包装时优先把强表达落到具体素材上，而不是只加形容词。可以用具体门槛、场景、身份、数字、动作和读者代价承载刺激感。

## Copywriting 机制

- **Mind the gap**：制造一个具体、未解决的张力，让读者必须继续看。Hook 不能只是总结内容。
- **Punch first**：第一句要能打断注意力。除非用户明确要求保留上下文，否则不要软铺垫。
- **Slippery slope**：每句话都让下一句自然被读下去。包装资产里没有功能的句子直接删。
- **用标题筛选读者**：标题可以点名窄人群、身份、地点、状态、问题或欲望。无关读者不点进来是好事。
- **具体性强化强烈程度**：用具体门槛、场景、身份和素材承载强表达，不要只加形容词。
- **Open loop 先抓住人**：默认优先制造继续看的冲动；只有用户要求严谨包装或品牌安全时，才严格审查兑现边界。

## 策略标签

生成选项时，每个选项至少标注一个策略：

- **认知冲突**：打破读者已有判断。
- **好奇缺口**：点出未解释的信息差。
- **恐惧 / 损失**：命名读者正在付出的代价。
- **身份代入**：直接点名人群、处境、阶段或角色。
- **数字锚定**：用数量、时间、门槛、比例形成抓手。
- **结果承诺**：说明读者会得到的具体结果。
- **社会证明**：引用特定人群、案例、数据或可见反馈。
- **争议 / 挑衅**：挑战流行观点，把读者拖进判断。
- **场景 / 条件**：把内容放进具体使用场景。
- **行动号召**：直接要求下一步，通常配合 CTA。

策略标签不是装饰。不要输出 5 个同义提醒句；每个候选都要能说明它为什么会让目标读者继续看、点击、保存、转发或行动。

## 用户修订反推

用户亲自修改标题、hook、opening、CTA 或短发布文案时，优先把它当成高质量包装反馈。不要只评价“更好”，必须反向提炼机制：

```text
用户加了什么：
用户删了什么：
张力从哪里变强：
哪些词更贴作者声音：
通用包装机制：
voice 候选证据：
```

亲历发现型文章的标题，优先测试“我做了什么 -> 结果发现什么”的结构。它通常比旁观判断更强，因为它保留了现场、动作和转折。

示例机制：

- “我让”比省略主语更强，因为它把标题变成亲历现场。
- “结果它竟然用”比“竟然用的是”更有发现过程和转折感。
- 感叹号只有在正文语气已有惊讶、吐槽或“更离谱的是”时才成立；不要推广成所有标题默认加感叹号。

## 后果翻译型 Hook

包装新技术、新政策、新平台动作、制度缝隙、机构失误或圈内风向时，优先把 hook 做成“变化带来的具体后果”，不要只写“某事发生了”。

可用进入点：

- **情绪定性入口**：先用一句极短态度词给事件定性，例如荒诞、历史性、好家伙、该来的来了、价格战开打；后文必须立刻接事实，不要只喊情绪。
- **旧规则被打破**：以前必须 A，现在可以 B。
- **新门槛出现**：从某个日期、额度、身份、区域或资格开始，读者会被重新筛选。
- **高位主体低级错误**：本该专业的系统犯了低级错，并造成具体后果。
- **二阶后果**：表面是产品、政策或新闻，真正变化的是谁被绕过、谁被替代、谁获得入口。
- **具体动作**：扫房、开户、下单、入金、出境、招聘、迁移、套利、限制模式等。
- **检测方式变化**：从身份、IP、定位、KYC、额度、费率或时间窗口切入，让读者看到自己会被怎样重新筛选。

检查问题：

```text
读者是否知道这件事和自己有什么关系？
hook 是否说出了一个具体后果，而不是只复述新闻？
首句的情绪定性是否准确规定了读法，还是只是空泛增强？
有没有数字、日期、额度、比例或门槛支撑张力？
能不能把 hook 改写成一个具体动作或限制，而不是一个抽象名词？
结尾判断是否能被读者复述？
```

素材没有支撑时，不要为了增强信息差编造信源姿态、行业内幕、确定性结论或执行力度。

## 高可信证据 Hook

包装论文、数据、图表、回测、报告或专业观察时，首屏要把“可信”和“离谱”同时做出来。

默认检查：

```text
是否先给出可信信号，而不是只喊观点。
能否把复杂机制压成单变量反转。
极端数字、走势或前后对比是否能一眼看懂。
情绪定性是否服务读法，并立刻被事实兑现。
是否自然落到读者自身处境、身份或利益。
是否保留真实争议入口，而不是把证据边界说死。
```

可用包装结构：

```text
情绪定性 / 悬念
-> 可信来源
-> 单变量 A / B
-> 极端结果差
-> 读者处境落点
```

硬数据负责可信度、反差和讨论门槛；情绪负责停留、代入和转发冲动。两者缺一边时，hook 要么像干摘要，要么像空煽动。

## Hook 生成和重做

生成标题、开头、CTA 或短发布文案时，先检查 hook 是否真的制造了进入理由，而不是只把原文概括得更顺。

优先检查：

- 是否点名具体读者、身份、阶段、场景或任务。
- 是否说出读者正在付出的痛点、代价、风险或错误。
- 是否在第一屏给出潜在利益，让读者知道继续看会发生什么变化。
- 是否用具体数字、时间、门槛、结果、金额、比例或步骤承载强表达。
- 是否有真实素材支撑 social proof；没有素材时不要编结果、截图、资质或群体反馈。
- 警告、劝诫和避坑是否来自经验、案例、常见错误或合理推断，而不是空泛恐吓。
- 自信语气是否匹配任务和事实边界。观点、营销和短内容可以强；研究、事实判断、合规和高风险内容要保留必要限定。
- 是否有 pattern interrupt：反常识、句式断点、强对比、异常数字、视觉排版或第一句打断，但不能为了打断而牺牲理解。

重做时至少覆盖 3 种不同策略，例如认知冲突、损失规避、身份差距、信息差或行动压力。不要沿用同一种提醒式表达。

## Hook 变体

可以从已验证 hook、swipe file 或对标样本中学习呈现方式，但不能把别人的人物、数字、成果、经历或权威背书直接搬进用户内容。

Hook 变体必须同时满足：

- 目标读者准确。
- 用户素材能兑现。
- 正文有 payoff。
- 不误导可信度。

包装 thread、短内容系列或连载短帖时，可以调用 `profiles/content-assets/patterns/killer-thread-quality-gate.md` 做 hook 兑现检查。强 hook 只解决点击和继续读的入口；如果正文没有具体、可执行、可复述的 payoff，先回到 `$cflow-shortform` 或 `$cflow-check`，不要继续加大 hook 承诺。

可用变体动作：

- **改写**：保留张力机制，换成当前主题、读者和素材。
- **组合**：把两个已验证 hook 的结构、动词、节奏或 open loop 组合成新入口。
- **从宽到窄 / 从窄到宽**：根据内容目标调整受众宽度；追求传播时可以扩大第一眼相关性，但正文必须筛回目标读者。
- **个人元素**：加入作者真实经历、投入、低谷、发现或结果，让 hook 不只是模板。
- **悬念保留**：打开问题但不提前泄露答案；不能制造正文无法兑现的好奇缺口。

如果 hook 的吸引力来自名人、专家、权威机构、夸张数字或结果承诺，必须有真实素材支撑；否则改成弱一点但真实的版本，或标注需要补充 / 核验。

## 开头质量

开头必须独立成立。不要假设读者已经看过标题、视觉资产或上下文。

长文、体验文、现象解读、工具分享和故事型内容的开头，优先从具体、当下、可观察的事件或场景进入。第一句最好让读者自然产生“然后呢”的冲动，而不是先给背景、定义、价值判断或时代判断。

常见有效入口：

- **叙事启动**：直接进入事情怎么发生。
- **荒诞事实**：抛出一个和常识不一致、让人想确认的事实。
- **热点现场**：点出最近正在发生、读者可能刚看到的现象。
- **好奇心驱动**：从作者刚刷到、刚试过、刚发现、刚被卡住的具体东西切入。
- **感性事件**：从一个让作者有反应的瞬间进入，再把它拉回主张。

不要把具体事件开头误用成伪亲历。没有真实行动、观察或素材时，只能写成读者处境、公开现象或待验证假设，不要编“我刚刚经历了”。

好开头通常同时包含：

```text
话题：这条内容在说什么
Hook：为什么现在要听
行动理由：为什么读者现在应该继续看
```

开头不要只重复标题。开头应带来新信息、新张力或新场景。

## 销售包装

当内容有销售或转化目标时使用 AIDA：

```text
Attention：打断准确读者
Interest：描述熟悉处境或未解决问题
Desire：建立信念、转变、利益和情绪拉力
Action：欲望存在后再要求下一步
```

不要在读者还没有理由关心前就抛产品、价格或 CTA。价格必须出现时，把它放进结果或体验里，而不是裸折扣。

包装产品、服务或说服型内容时，优先把强主张落到可感知素材上：

- 前后对比
- 截图或指标
- 具体客户场景
- 来自特定人群的 social proof
- 能回答异议的个人轶事
- 可见转变，而不是产品描述

如果素材不够，广告、viral 和限时活动场景仍先产出强版本。只有严肃论证、研究型内容、事实判断或用户主动要求时，才标出证据缺口。

## 渠道情报型包装

渠道情报、机会窗口和入口型转化的完整判断归 `$cflow-marketing`。`cflow-package` 只负责把已确定的主入口、窗口变化、读者利益和行动压力包装成标题、首句、短发布文案或 CTA。

包装侧保留：

- 消息感、短句、列表、压迫感和信息差。
- 主入口靠前，风险提醒后置压缩。
- 标题和首句不要改成中性产品介绍。

入口型转化的关注理由就是入口、截止时间、资格和可操作链接本身，不要为了 AIDA 把产品和 CTA 后置。

## 推广和分享文案

当用户要为文章、长内容或外部链接写短发布文案时，包装目标不是复述全文，而是找到一个强、准、能让人点开的进入点。

- 不要摘要全文。推广文案只需要暴露最值得点开的张力、问题、判断或具体细节。
- 链接是自然下一步，不是硬贴附件。读者读完前文应知道为什么继续点开。
- 文案必须自洽。读者即使暂时不点链接，也应该知道这条内容的价值是什么。
- 默认基于原文素材放大，不另造新信息、数据、案例或结论；用户要求严谨包装时，再检查 hook 和原文支撑关系。
- 每个候选要使用不同进入点，例如一个从反常识进入，一个从具体场景进入，一个从读者损失进入；不要只是换同义词。
- 如果原文没有足够张力，先从读者损失、场景、反常识、身份或行动压力里找更锋利的进入点。只有用户要求严谨包装时，才把支撑缺口作为问题展开。

判断推广 hook 是否成立：

```text
这句话是否足够让目标读者想点开？
读者是否知道为什么要点开？
这句话是否只是摘要，而不是进入点？
删掉链接后，文案是否仍然有信息价值？
```

## 个人引流 CTA 包装

当内容适合接作者个人引流资产时，资产清单以用户提供的 profile 或资产档案为准。`cflow-package` 只负责把入口包装得自然、短、符合用户明确提出的发布约束，不维护具体链接、邀请码或私有资产清单。

常用包装方式：

- **直接链接**：适合用户明确允许裸链、且链接不会破坏阅读的交付物。
- **资料入口**：适合用户明确说明不方便放链接或链接会影响阅读时。
- **回复关键词**：适合需要承接、筛选意向或不想公开链接时。
- **私下关键词**：适合需要筛选意向或不想公开链接时。
- **置顶入口**：适合系列内容、长期资源或多个链接并存时。

包装纪律：

- 单篇内容默认只保留一个主引流动作。
- CTA 要接内容场景，不要机械写“欢迎关注 / 欢迎订阅”。
- 用户明确说明不方便放链接时，不要硬塞裸链，改成用户可执行的低摩擦入口。
- 如果内容不适合引流，只在交付后轻提醒，不强行写进正文。

## 社交线程 CTA 包装

包装线程、连载短帖、长帖拆条或社交平台发布包时，先减少读者要同时处理的动作。显性 CTA 默认只保留一个主动作，或一个天然同向的主动作簇，例如关注后续和转发完整线程。评论、点赞、收藏、关注、转发不要在结尾堆成任务清单。

次级互动可以放进正文机制，而不是都写成命令：

- **评论**：用与话题相关的问题、站队空间、经验征集或反例邀请承接。
- **收藏**：只在内容确实有长期查阅、清单、教程、方法论或资源价值时前置提醒。
- **点赞**：通常不作为显性主 CTA，除非用户明确要求活动机制或平台文案风格。
- **转发**：给出读者为什么愿意帮别人看到的理由，例如避坑、节省时间、降低试错或替他表达立场。
- **关注**：说明后续会持续获得什么，而不是机械写“欢迎关注”。

长线程可以在开头放收藏或保存类提示，但必须接内容价值；结尾可以用价值回顾加低摩擦回馈请求，必要时指回线程开头，方便读者转发完整内容。CTA 的互惠理由要讲清楚：作者提供了什么高价值内容，读者通过一个简单动作能帮到作者或帮到同样需要的人。

## 资源型 CTA 表达

包装视频、访谈、演讲、备忘录、报告、文章、清单或资料时，先判断资源的表达入口是长期参考型还是时效窗口型，不要默认都写成收藏 / 保存。这里处理的是 CTA 文案表达；如果要决定该资源是否承担转化目标、主 CTA 或 funnel stage，交给 `$cflow-marketing`。

- **长期参考型资源**：经典演讲、常青教程、历史备忘录、方法论清单、可反复查阅资料，适合 CTA：收藏、保存、留着看、之后需要时翻出来。
- **时效窗口型资源**：IPO roadshow、发布会、财报、政策解读、市场窗口、限时活动、正在发生的争议或决策材料，适合 CTA：现在看、先看完、别只看二手解读、趁窗口还在先过一遍。

判断规则：

- 如果资源关系到当前决策、市场窗口、发布节点或信息差，优先号召观看或立即处理。
- 如果资源主要价值是长期学习、复盘或反复查阅，优先号召收藏或保存。
- 收藏和观看可以同时存在，但只能有一个主动作；时效性强时，“观看”是主动作，“保存”只能作为次要动作。

## 发布前质检交接

发布前质检归 `$cflow-check`，不在包装系统维护第二套“能不能发”标准。

`cflow-package` 只接收质检后的包装任务：

- 标题、hook、opening、CTA 或短发布文案弱。
- 多个包装版本需要选择最佳。
- 内容已经值得发，只差首屏、点击、行动压力或包装兑现。

如果质检发现主张、素材、读者任务、AI 指纹、传播机制、转化路径或事实边界才是根因，先交给对应专项 skill，不在 package 内把它包装成“看起来能发”。

## 翻译和本地化

当用户要求翻译、英文版或跨语言发布时，先区分任务权限：

- **翻译**：保留原文主张、事实、语气强度和信息顺序，优先自然准确。
- **润色**：在不改变主张和事实边界的前提下，让目标语言更顺。
- **本地化**：允许替换不自然表达，但不新增原文没有的事实、案例、承诺或结论。
- **发布约束改写**：可以按用户明确提出的字数、链接、审核、媒介或入口限制重排、压缩、强化 hook 或 CTA。

不要把“翻译成英文”自动做成爆款改写。没有用户授权时，避免新增俚语、夸张隐喻、emoji、行业黑话、具体人物案例或原文没有的判断。

## 本地包装纪律

- **一个主轴**：一个包装资产先服务一个核心主张、任务或动作。
- **读者具体**：先知道谁会看、为什么现在要看、看完是否需要动作。
- **三段读者行为**：包装前先设计读者为什么停下来、为什么继续看、看完是否需要动作。
- **具体先于抽象**：场景、例子、动作、读者处境、前后变化优先于概念总结。
- **用户原话是素材**：用户原始表达里的疑问、吐槽、犹豫、判断、脾气和不完整句，优先当作包装声音和现场素材处理。
- **强表达不自动降温**：强利益、强判断、强情绪、强 CTA、强对比不是天然问题。
- **爆款要资产化**：高传播包装要检查读者会记住作者的什么判断、方法、栏目承诺、人格气质或可信度。
- **传播强度服务品牌资产**：追求点击、转发、评论和二创时不自动降温；只有吸引明显错误人群、破坏可信度、严重偏离作者声音、无法被账号承接或用户明确要求时，才收窄表达。
- **重要性必须有支撑**：不要把普通事实包装成重大趋势、关键转折或行业启示，除非素材里有证据、对比、影响范围或作者明确判断。
- **归因必须落地**：需要来源时，用具体来源、具体观察、用户素材或明确的“待核查”状态；不要用模糊归因伪装来源。
- **排版密度是功能**：换行、单句成段、列表和空行都必须承担强调、转折、停顿、扫读或结构功能；不得默认一句一行。
- **结构工具有成本**：列表、小标题、类比、反问、破折号和括号旁注只能在承担扫读、定位、澄清、补充边界或制造必要张力时使用。
- **自然不是随便**：不要把“像人”误判成口水化、废话化或过度聊天腔。
- **少用二分总结**：避免连续用二分句替代观察和推理。
- **声音不是表层词汇**：voice profile 可约束包装声音，但不要只替换几个词伪装作者声音。
- **评价先于夸奖**：诊断标题、hook、CTA 或发布文案时，先指出根因、风险和下一刀；不要用“高级、出色、很抓人”替代判断。
- **风格词要落地**：“颗粒感、呼吸感、冒犯感、人味”等词只能作为诊断标签，交付时要翻译成可执行动作。
- **风格词不是目标函数**：不得为了追求风格标签新增无素材支撑的细节、故意挑衅、制造假粗糙或削弱本来需要的营销、传播、CTA 和强表达。
- **平台不生成风格**：平台名只能提供外部限制，不能自动生成平台腔、口头禅、套话或固定结构。
- **默认中文输出**：除非用户明确要求英文、翻译成英文、保留英文原文风格，或交付场景明确是英文发布，否则默认中文输出。

## 反 AI / 反模板闸门

`cflow-package` 必须防止自己产出默认 AI 文体和包装模板感。这里不是“伪装成人”，也不是把“去 AI 味”当成独立目标；目标是让标题、hook、opening、CTA 和短发布文案回到当前素材的真实张力、作者判断、读者代价和行动压力。

包装、重做、润色、翻译发布包或生成变体时，`cflow-package` 自己负责识别并修掉以下问题：

1. 只把原文概括得更顺，没有制造进入理由。
2. 多个候选只是同义改写，没有策略差异。
3. 用“值得关注、很有启发、意义重大、未来可期”替代真实张力。
4. 用“这不是 X，而是 Y”“真正重要的是 Y”“正式进入 Z”包装普通事实。
5. 默认一句一行、清单化、平台腔或爆款模板。
6. 把用户原话里的主语、动作、吐槽、惊讶和发现过程磨成中性说明。
7. 无主动作时硬加 CTA、收藏、关注、咨询或链接。
8. 正文已经自然结束后补尾巴、定位说明或硬 CTA。
9. 编造 social proof、名人背书、群体反馈、数据、截图、结果或行业内幕。
10. 用模糊归因、猜测补洞或无来源权威口吻制造信息差。
11. 用重要性膨胀、泛泛积极结尾或元话语开场制造正式感。
12. 在非版本文档里用“新增 / 替代 / 改进”叙述替代当前对象本身。
13. 用“真正重要的是、这意味着、值得关注、不是 X 而是 Y”包装普通事实，却没有说出读者的具体代价、动作、门槛或结果。
14. 把标题、hook 或 CTA 写成无主语的抽象判断，没有人、对象、场景或动作。
15. 为了显得有力，把每个候选都写成同一种短促金句，读者看不出进入点差异。

命中这些问题时，先做包装动作：换策略、删尾巴、保留原话、补具体场景、压缩价值总结、改成更弱但真实的版本，或标注需要补素材。不要只用“更口语、更有毛边、更像人”的表层目标改写；也不要通过故意加废话、错字、口头禅或无素材细节制造人味。

如果用户明确要求“标题别有 AI 味 / hook 不要像模板 / CTA 更像人 / 发布文案别太 AI”，仍由 `cflow-package` 完成，因为这是包装质量要求。

只有用户提供的是已有完整草稿，并且任务只是“检测哪里像 AI、诊断 AI 味、判断像不像我、做改稿手术”，才交给 `$cflow-edit`。如果用户在 `$cflow-package` 中要求包装资产不要 AI 味，不得转交。

## 包装质量闸门

出稿前自检：

```text
包装资产类型：
目标读者：
核心主张：
主动作 / CTA 是否明确：
最强真实张力来自哪里：
是否至少覆盖 3 种不同策略：
候选是否只是同义改写：
hook 是否制造进入理由，而不是摘要：
opening 是否独立成立：
CTA 是否接内容场景：
是否无主动作硬加 CTA：
是否编造 social proof、数字、结果或信源姿态：
是否存在平台腔、模板腔或 AI 式顺滑：
是否存在宣布句、假反转、空泛重要性或无主语抽象判断：
是否磨平用户原话里的主语、动作和现场反应：
删掉最后一句后是否更干净：
最佳选项为什么最佳：
```

不要把检查表完整输出给用户，除非用户要求看诊断过程。

## 常见反模式

- 摘要代替包装：只复述内容，没有给读者进入理由。
- 同义词候选：5 个标题只有词不同，策略完全一样。
- 平台腔污染：根据平台名自动生成固定语气、排版、口头禅、套话或内容结构。
- 假反常识：把普通判断包装成“多数人都错了”，正文却没有反转。
- 假信息差：用“内幕、少有人知道、我发现了”制造姿态，但素材没有支撑。
- 假 social proof：编造用户反馈、截图、群体、数据、专家或权威机构。
- 价值总结当 hook：用“值得关注、很有启发、意义重大”替代具体动作和代价。
- 补尾巴：内容已经结束，却又补收藏、关注、咨询、链接或定位说明。
- 硬 CTA：主动作不清时强行让读者买、领、私信、关注或收藏。
- 过度降温：广告、viral、渠道情报或限时活动本来需要强刺激，却被改成中性说明。
- 过度承诺：严谨、合规或品牌安全场景里，标题承诺超过正文和素材能兑现的范围。
- 正确但没生命力：标题顺、开头稳、CTA 礼貌，但没有记忆点、现场感、动作或张力。
- 风格标签空转：只说“加颗粒感、加人味、去 AI 味”，没有定位具体包装动作。
- 改动叙述锚定：非 changelog、release note 或迁移指南里，把正文写成“这次新增 / 替代 / 改进了什么”，而不是描述当前对象本身。

## 交接规则

只在问题不属于包装职责，或继续包装会掩盖根因时交接：

- 需要完整正文、教程、销售稿、长篇复盘或可归档内容：`$cflow-draft`。
- 需要短帖、短脚本、短内容系列正文：`$cflow-shortform`。
- offer、funnel stage、主 CTA、转化路径、引流资产策略不清：`$cflow-marketing`。
- 需要搜索、来源、引用、最新事实或证据包：`$cflow-research`。
- 需要真实案例、故事设计或案例筛选：`$cflow-case`。
- 需要发布前判断“能不能发、发哪版、哪里失败”：`$cflow-check`。
- 需要修改已有完整草稿、结构手术、AI 味诊断或最小改稿：`$cflow-edit`。
- 作者声音画像缺失、冲突或需要更新：`$cflow-voice`。
- 发布后表现数据复盘、提炼可迁移机制或下一轮栏目调整：`$cflow-review`。
- 需要传播机制设计，而不只是包装表达：`$cflow-viral`。
- 需要 SEO / GEO / AEO / LLMO 结构，不只是标题或搜索结果页包装：`$cflow-seo`。

包装任务内部的标题策略、hook 强度、opening 进入理由、CTA 表达、短发布文案、发布包、反模板、反默认 AI 文体、同义改写识别和最佳选项判断，不交接。
