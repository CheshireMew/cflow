# CFlow 作者声音

## 边界

负责“作者是谁，以及他会怎样表达”。不要替代 `$cflow-draft` 写完整草稿，也不要替代 `$cflow-edit` 做完整改稿。

`cflow-voice` 产出并维护唯一可复用的作者声音画像，供其他 CFlow skill 调用。唯一持久化位置是 `profiles/voice-profile.md`；不要按题材、平台、项目或文章创建多个 voice profile。题材差异只能写进同一个 profile 的场景调用规则。

`cflow-voice` 有权限创建和更新 `profiles/voice-profile.md`。用户明确说“记住这个写法”“更新我的 voice profile”“以后都按这个来”“这就是我的写法”时，也只能把可复用的底层表达偏好写入核心画像；单次样本或单次反感反馈默认不扩写 profile，也不把候选证据写入 profile，稳定复现后再升级为核心画像。

写入前必须做归属审计、抽象层级审计和反膨胀审计。`voice-profile.md` 是运行时调用资产，只能记录作者表达偏好、思维动作、价值判断、表达禁区、句子节奏和场景调用规则。不得写入 skill 流程、工具权限、路由规则、单篇文章事实、项目资料、API 细节、当前 brief、单篇标题、工具名、项目名、人物名、平台名、阅读数据、一次性强句、候选证据、更新记录或只在当前题材成立的特殊表达。发现这些内容时，拒绝写入 profile，并交给 `$cflow-maintain`、`$cflow-brief`、`$cflow-research` 或对应专项 skill。

## 工作流

1. **收集样本**：读取用户提供的样稿、口述、历史文章、评论、笔记或反感示例。
2. **分离层级**：区分表层文风、句子节奏、思维方式、价值判断、情绪温度、表达禁区、单篇素材和 skill 流程规则。
3. **提炼稳定项**：只记录反复出现、可复用、能指导未来写作的特征；单次样本只能抽象到底层价值观、思维动作、表达禁区或调用规则，不能把原句和特殊素材搬进 profile。
4. **标记依据**：分析阶段可以说明样本依据，但不得把证据、日志或样本索引写入 `voice-profile.md`；需要追踪变更时依赖 git diff。
5. **定义禁区**：记录作者不会说、不能说、说了会不像本人的表达。
6. **区分 AI 味和本人味**：AI 味不是唯一问题；真正目标是让文本像作者本人，而不是只让文本“不像 AI”。
7. **生成 voice profile**：输出可被 draft/edit/package 调用的简洁画像。
8. **创建或更新画像资产**：需要持久化时，先过滤不该进入 profile 的内容，再写入唯一 `profiles/voice-profile.md`；优先合并、替换和压缩旧条目，不默认追加；与旧画像冲突时只在本次输出中说明冲突，等待用户确认，不直接覆盖。
9. **调用或交接**：需要成稿交给 `$cflow-draft`；需要改稿交给 `$cflow-edit`；需要标题和 CTA 交给 `$cflow-package`。

## 输出

建立画像时返回：

- 作者人格
- 思维倾向
- 价值取向
- 句子节奏
- 表达习惯
- 允许的毛边
- 表达禁区
- 不像本人的风险
- 可调用 voice profile

判断是否像本人时返回：

- 判断
- 像本人的部分
- 不像本人的部分
- 需要保留的原句
- 需要删除或改写的表达
- 修改方向
