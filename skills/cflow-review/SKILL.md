# CFlow Review

## 工作目标

把一次内容结果拆成清楚的判断：哪里有效，哪里失败，为什么，哪些经验下次还能用。

复盘不只是评价内容好坏，而是找出可重复的内容动作。

## 维护约束

- 正文不重复 description 已经说清的范围。
- 只写复盘本身负责的判断、拆解、资产沉淀和写入规则。
- 跨 skill 调度由主入口处理；本文只保留复盘规则。
- 模板字段必须是信息单元：证据、动作、机制、条件、下一次用法。
- 不把单篇案例、单个平台表现或作者身份写成通用规律。
- 先抽象底层动作，再保留领域条件；不要把证据来源误写成机制本身。

## 工作流

1. 判断复盘对象：优秀案例、已发布内容、失败草稿、评论反馈、内容库。
2. 拆内容本体：看选题、角度、开头、结构、证据、表达、结尾。
3. 看外部信号：指标、评论、转发、收藏、私信、创作者体感。
4. 提炼文案结构模板：把有效内容拆成可复用的信息顺序、推进动作和承接位置。
5. 抽象底层机制：把论文、市场、平台、行业、作者身份等表面领域替换成变量。
6. 区分可学模板、可学机制、待验证假设、不可复制条件。
7. 判断哪些经验应内化为 skill 原则，哪些只适合沉淀为内容资产。
8. 输出下一次内容动作；用户要求沉淀时，写入 `profiles/content-assets/`。

## 复盘对象

### 优秀案例

```text
它抓住了什么读者处境
开头用什么让人停下
正文按什么顺序推进
哪些事实、案例、数字或表达让它成立
哪些动作可以迁移到用户自己的内容
```

### 已发布内容

```text
原本目标是什么
实际信号是什么
内容本体哪里支撑了结果
内容本体哪里拖累了结果
下一次保留、删除或重做什么
```

### 失败草稿

```text
失败发生在选题、角度、开头、结构、证据、表达还是结尾
具体断点是什么
是否值得继续改
如果继续改，先改哪一个动作
```

### 评论反馈

```text
读者反复提到什么
读者误解了什么
读者真正想要什么
能不能变成下一轮选题、角度、证据或表达规则
```

### 内容库

```text
先按交付形态、内容目标、发布环境或栏目分桶
每个桶只抽代表样本深拆
桶内看稳定机制
跨桶只看反复出现的机制
```

## 内容本体

复盘时优先看具体内容动作，不写空泛评价。

```text
选题：它解决了读者哪个具体问题？
角度：它有没有判断、反差、冲突或新信息？
开头：第一句给了什么停下来的理由？
结构：每段是否推进了新信息？
证据：有没有案例、数字、场景、对比或原句支撑？
表达：哪些句子提高了密度、情绪、可信度或记忆点？
结尾：最后一句有没有信息增量？
```

坏复盘：

```text
结构清晰。
观点犀利。
很有共鸣。
标题吸引人。
```

改成：

```text
具体动作是什么。
它为什么有效。
换一个题材后是否还成立。
下次怎么复用。
```

## Copywork 颗粒度

拆优秀样本时，不要停在“结构清晰、观点犀利、情绪到位”。至少拆到具体动作。

```text
选题：为什么是这个题，不是更大的话题？
读者：标题和正文分别筛选了谁？
开头：第一眼或第一句用什么张力留人？
结构：每段、每条或每一镜在推进什么？
说服：用数据、故事、场景、对比、权威还是情绪推动？
节奏：哪里快，哪里慢，哪里转折？
语言：哪些句子服务表达强度，哪些服务篇幅效率？
行动：下一步动作被放在什么时机？
传播：哪些句子、截图段、清单或站队点能被读者带走？
承接：这条内容如何让读者记住作者、栏目、主页入口或后续内容？
```

如果只能得到“好看、顺、抓人、有共鸣”，说明拆得太粗。

## 双层复盘

优秀内容必须同时拆两层，不要互相替代。

```text
文案结构层：这条内容按什么信息顺序让读者停下、相信、代入、转发或行动。
底层机制层：这条结构背后调用了什么可迁移的人性、认知、信号、权力、身份、利益或情绪机制。
```

文案结构层要能落成模板，但模板只能是信息顺序和动作，不是固定句式。

```text
开场动作：
反差或冲突：
可信度来源：
情绪或利益解释：
读者代入点：
视觉或案例证据：
承接或下一步：
```

底层机制层要能升级规则，但不能把表面素材当机制。

```text
读者已有处境是什么？
内容释放了哪种既有情绪或未说出口的判断？
用了什么信号让读者觉得值得相信、值得转发或值得站队？
这个信号来自权威、稀缺信息、代价、身份、数据、视觉证据、第三方背书还是群体共识？
去掉原题材后，这个机制还能怎么命名？
```

如果用户要求“为什么文案好”，优先给结构模板；如果用户要求“为什么机制强”或“优化 skill 规则”，必须给底层机制。多数优秀案例应同时给出两者。

## 外部信号

外部信号只能验证或修正内容判断，不能替代内容拆解。

```text
低 reach、强反馈：可能是包装或分发问题。
高 reach、弱互动：可能是题太宽或角度太浅。
收藏高、评论低：有用，但不够可讨论。
评论困惑：主张、结构或表达不清。
转发高：可能有替读者表达的判断、提醒或信息差。
转化强、传播弱：题可能窄，但商业价值高。
```

有指标时先问：

```text
这个指标对应什么读者行为？
它支持还是推翻内容本体判断？
有没有样本量、平台、时间窗口或发布环境限制？
```

## 可学与不可学

可学的是内容动作，不是表面结果。

```text
可学机制：换题材后仍可能成立的选题、角度、结构、证据、表达或传播动作。
待验证假设：只有一个样本支持，但值得下次实验。
不可复制条件：作者身份、粉丝基础、热点时机、私有经历、稀缺资源、平台顺风。
```

判断标准：

```text
去掉原作者、原题材、原平台后，这个动作是否仍可能有效？
```

如果不能，就只记录为案例条件，不写成机制。

## 底层机制抽象

复盘有效内容时，必须先做一次同类替换。

```text
表面领域是什么？
证据来源是什么？
真正改变读者反应的动作是什么？
这个动作向读者发出了什么信号？
这个信号为什么能改变信任、情绪、身份、风险或行动判断？
把领域名换成别的同类材料后，这个动作是否仍成立？
机制应该怎么命名，才不会被原领域绑死？
```

常见误判：

```text
把“论文”误当机制；真正机制可能是高反差证据速译。
把“AI 新闻”误当机制；真正机制可能是复杂变化速译。
把“A 股”误当机制；真正机制可能是本土化落点。
把“图表”误当机制；真正机制可能是视觉证据前置。
把“数据很硬”误当机制；真正机制可能是高可信信号释放既有情绪。
```

资产命名优先使用底层动作，不优先使用领域名。

## 原则与资产分层

复盘得到的经验不要默认都写成资产。先判断它是否应该成为运行时默认原则。

```text
应内化到 skill 原则：会改变默认判断、工作流、质量门槛、输出字段或反模式；即使不读取内容资产，也必须稳定生效。
适合沉淀为内容资产：长模板、案例、触发词、适用条件、扩展检查清单、证据样本或只在特定场景调用的模式。
```

如果某条经验会影响 `$cflow-angle`、`$cflow-package`、`$cflow-viral`、`$cflow-draft` 等生产行为，复盘输出必须标明目标 skill 和应内化原则，不能只给资产卡片。

高门槛证据进入大众传播时，review 默认检查这组原则是否出现：

```text
能否压成单变量反转，而不是多变量解释。
是否有可信信号支撑离谱结论。
极端数字、图表或前后对比是否制造认知失衡。
是否释放读者已有情绪，而不是凭空煽动。
是否自然落到读者自身处境、身份或本土痛点。
是否存在真实争议空间，可带来评论、纠错和二次传播。
```

## 资产沉淀

复盘结束时判断是否值得沉淀。

```text
是否有明确证据？
是否能用于下一次内容生产？
是否跨题材或跨样本成立？
是否只是单篇案例条件？
```

用户没有要求保存、沉淀、写入或建档时，只输出资产卡片，不写文件。

用户明确要求写入时，写到 `profiles/content-assets/`。

### 资产归属

判断资产归属时，先看根行为，不看表面题材。

```text
读者反复提问 -> 选题池或栏目
运行时默认判断变化 -> 对应专项 skill 原则
某个冲突有效 -> 角度模式
某种结构推进顺 -> 文案结构模板
某个短链路、首屏推进或单点表达有效 -> 短文案资产
某个故事带来强反馈 -> 案例资产
某种表达动作有记忆点 -> 表达资产或 voice 证据
某个标题明显拉动点击 -> 包装策略
某个封面或配图明显拉动点击 -> 视觉策略
某个截图点、复述句或站队点有效 -> 传播模式
某个 CTA 带来转化 -> 转化路径经验
某个拆解 prompt 或采访问题反复提高产出质量 -> 复盘生产资产
某个发布环境持续不匹配 -> 发布约束经验
某个复盘暴露了 skill 行为缺陷 -> 维护建议或测试用例
```

资产归属用于填写资产卡片和 frontmatter 的 `skills` 字段，不是让复盘阶段展开生产。

## 资产卡片

```text
资产名称：
资产类型：文案结构模板 / 底层机制规则 / 复盘快照 / 优质样本 / 可迁移模式 / 实验记录
适用场景：
文案结构：
核心机制：
证据样本：
可迁移动作：
不可复制条件：
下一次使用方式：
是否写入文件：
```

资产卡片必须写出具体动作，不能只写“值得学习”“可以复用”。

## 写入规则

允许写入：

- `profiles/content-assets/` 下的复盘快照、优质样本、可迁移模式、实验记录。

写入文件必须带 frontmatter：

```yaml
---
asset_name:
asset_type:
skills:
  - cflow-review
triggers:
  - ""
use_when:
avoid_when:
evidence_level:
overuse_risk:
source: cflow-review
---
```

字段要求：

- `asset_name`：中文资产名。
- `asset_type`：文案结构模板、底层机制规则、复盘快照、优质样本、可迁移模式或实验记录。
- `skills`：真正会使用该资产的 skill。
- `triggers`：用户输入中可能触发该资产的词或场景。
- `use_when`：什么时候应该采用。
- `avoid_when`：什么时候不该采用。
- `evidence_level`：A / B / C / D 或待验证。
- `overuse_risk`：重复使用会带来的风险。
- `source`：固定写 `cflow-review`。

如果没有足够证据，只能写为待验证资产。

## 输出

按任务需要输出，不要机械填满字段。

```text
复盘对象：
已有证据：
内容本体判断：
外部信号判断：
可复用文案结构：
可学机制：
应内化 skill 原则：
不可复制条件：
下一次内容动作：
可沉淀资产：
```

如果用户只要结论，直接给结论。
