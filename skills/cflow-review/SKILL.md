# CFlow 复盘

## 边界

只负责产出后的学习。除非用户要求修改版本，否则不要重写内容。

复盘要区分证据和解释。浏览、评论、收藏、转发、watch time、回复、创作者体感是不同信号。

每次复盘都要尽量沉淀一个可复用资产。只得到“一篇内容表现好/不好”的结论不够；要转化成选题模式、案例素材、标题策略、读者洞察、voice 规则、平台判断或下次实验。

## 工作流

1. 记录原始内容目标、读者、平台和假设。
2. 区分信号：指标、评论、定性反馈、创作者笔记、缺失数据。
3. 对比预期反应和实际反应。
4. 诊断可能原因：选题、角度、证据、包装、营销转化、发布时间、平台适配或读者错位。
5. 提炼可复用经验。
6. 判断本次能沉淀成什么资产，并标注归属 skill。
7. 推荐下一步：重复、修改、复用、测试新角度或放弃。
8. 下一轮生产需要时，交给 `$cflow-topic`、`$cflow-angle`、`$cflow-marketing` 或 `$cflow-package`。

## 输出

返回：

- 已有证据
- 可能有效的部分
- 可能失败的部分
- 根因假设
- 应保留的经验
- 可沉淀资产
- 下一步内容动作
- 缺失数据
