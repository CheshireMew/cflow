# CFlow 复盘

## 边界

只负责从内容结果中学习。用户拿来表现好、质量高或值得模仿的内容时，优先拆内容本身为什么成立；指标、评论和发布表现是辅助证据，不是唯一入口。

除非用户要求修改版本，否则不要重写内容。复盘的交付物是机制、模式、资产和下一步生产建议，不是另一版成稿。

复盘要区分内容机制、外部信号和解释。选题入口、角度压力、hook 承诺、结构推进、案例证据、表达密度、情绪曲线、记忆点、传播点和转化点，是内容本体信号；浏览、评论、收藏、转发、watch time、回复、创作者体感，是外部反馈信号。

发布后传播表现也归 `$cflow-review`。已有转发、截图、评论复述、二创、跨环境搬运或传播路径证据时，先做 review；需要传播维度时调用 `$cflow-viral` 的分享动机、传播单元、截图点、复述句、二创入口和传播风险，不把完整复盘交回 viral。

每次复盘都要尽量沉淀一个可复用资产。只得到“一篇内容表现好/不好”的结论不够；要转化成优质内容样本、结构模式、表达动作、可迁移机制、实验记录或维护建议。

面对大规模、不同类型的内容库时，不要逐条平均复盘，也不要直接横向比较所有指标。先按交付形态、发布环境、内容目标、栏目或读者任务分桶，再抽样高表现、低表现、异常值和代表样本；桶内找规律，跨桶只提炼可迁移机制和内容组合判断。

复盘资产必须分层。具体发布环境、人物、行业、题材和单条案例不能直接升级成通用经验；先抽象到跨场景机制，再判断能否交给其他 skill 使用。

`$cflow-review` 默认只输出复盘，不自动写文件。用户明确要求保存、建档、沉淀、写入或创建资产库时，才可以创建或更新复盘资产文件。禁止直接修改 `skills/`、`SKILL.md`、`references/` 或 agent metadata；如果复盘发现需要更新 skill 规则，输出维护建议并交给 `$cflow-maintain`。

如果复盘发现某个机制不只是生产资产，而是会优化其他 CFlow skill 的长期行为、流程、边界或路由，必须输出维护交接包，提交给 `$cflow-maintain` 判断和执行。`$cflow-review` 只负责提供证据、可迁移机制和维护建议，不直接修改 skill 真源。

## 工作流

1. 判断复盘对象：优质内容样本、已发布内容、失败草稿、低表现内容、评论反馈、创作者笔记或内容库。
2. 如果是内容库，先盘点字段、分桶、抽样和归一化比较口径；只对代表样本做深拆，再综合栏目、组合和资产沉淀建议。
3. 如果是优质内容或表现好的内容，先拆内容本体：选题入口、角度压力、hook 承诺、结构推进、案例证据、表达密度、情绪曲线、记忆点、传播点和转化点。
4. 如果有指标、评论或表现数据，再用它们验证或修正内容本体判断；没有数据时不要假装有反馈。如果数据指向传播表现，按分享动机、传播单元、截图点、复述句、二创入口和传播路径拆解；这些维度来自 `$cflow-viral`，但复盘、资产沉淀和下一轮实验仍由 `$cflow-review` 收口。
5. 区分可学习机制和不可迁移条件：作者身份、题材红利、发布环境、粉丝基础、热点时机、素材稀缺性不能直接复制。
6. 提炼可迁移经验，并做跨场景抽象检查。
7. 执行沉淀动作判断：是否值得沉淀、沉淀成什么资产、归属哪个生产 skill、是否需要写入文件或交给维护入口。
8. 如果值得沉淀但用户没有要求写入，输出可直接复用的资产卡片；如果用户明确要求保存、建档、沉淀、写入或创建资产库，再进入写入流程。
9. 判断是否形成 skill 优化建议：只有会改变 CFlow 长期行为、流程、边界或路由时，才输出维护交接包；单次案例、账号私有条件、行业题材红利和未验证猜测不交给维护入口。
10. 推荐下一步：复用结构、换题重做、扩展成栏目、迁移到其他交付形态、保存资产、做对照实验或放弃。
11. 下一轮生产需要时，按机制归属交给 `$cflow-topic`、`$cflow-angle`、`$cflow-draft`、`$cflow-shortform`、`$cflow-package`、`$cflow-viral`、`$cflow-marketing` 或 `$cflow-case`；规则维护需要时交给 `$cflow-maintain`。

## 输出

返回：

- 已有证据
- 内容库分桶和抽样口径
- 内容本体拆解
- 最值得学的机制
- 不可直接复制的条件
- 可能有效的部分
- 可能失败或弱化的部分
- 根因假设
- 传播路径和传播单元表现
- 应保留的经验
- 可沉淀资产
- 资产卡片
- 维护交接包
- 下一步内容动作
- 缺失数据
