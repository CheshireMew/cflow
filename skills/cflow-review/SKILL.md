# CFlow 复盘

## 边界

只负责产出后的学习。除非用户要求修改版本，否则不要重写内容。

复盘要区分证据和解释。浏览、评论、收藏、转发、watch time、回复、创作者体感是不同信号。

每次复盘都要尽量沉淀一个可复用资产。只得到“一篇内容表现好/不好”的结论不够；要转化成复盘快照、案例样本、可迁移模式、实验记录或维护建议。

复盘资产必须分层。具体平台、人物、行业、题材和单条案例不能直接升级成通用经验；先抽象到跨场景机制，再判断能否交给其他 skill 使用。

`$cflow-review` 默认只输出复盘，不自动写文件。用户明确要求保存、建档、沉淀、写入或创建资产库时，才可以创建或更新复盘资产文件。禁止直接修改 `skills/`、`SKILL.md`、`references/` 或 agent metadata；如果复盘发现需要更新 skill 规则，输出维护建议并交给 `$cflow-maintain`。

## 工作流

1. 记录原始内容目标、读者、平台和假设。
2. 区分信号：指标、评论、定性反馈、创作者笔记、缺失数据。
3. 对比预期反应和实际反应。
4. 诊断可能原因：选题、角度、证据、包装、营销转化、发布时间、平台适配或读者错位。
5. 提炼可复用经验，并做跨场景抽象检查。
6. 判断本次能沉淀成什么层级的资产，并标注归属 skill 或维护入口。
7. 推荐下一步：重复、修改、复用、测试新角度、保存资产或放弃。
8. 下一轮生产需要时，交给 `$cflow-topic`、`$cflow-angle`、`$cflow-marketing` 或 `$cflow-package`；规则维护需要时交给 `$cflow-maintain`。

## 输出

返回：

- 已有证据
- 可能有效的部分
- 可能失败的部分
- 根因假设
- 应保留的经验
- 可沉淀资产
- 下一步内容动作
- 缺失数据
