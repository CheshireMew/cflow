# 复盘循环

## 复盘模式

先判断用户拿来的是什么，不要默认进入指标分析。

| 模式 | 适用输入 | 主问题 |
|---|---|---|
| 优质内容拆解 | 表现好、质量高、值得模仿的文章、脚本、短内容、发布包或案例 | 它为什么好，哪些机制能迁移到用户自己的内容生产 |
| 已发布内容复盘 | 用户自己的已发布内容、指标、评论、截图、后台数据或体感 | 实际表现和预期哪里一致或偏离，下一轮怎么改 |
| 失败草稿复盘 | 没发、发前觉得不对、改了很多版仍不成立的内容 | 内容本体哪里断，是否该改题、改角度、改结构或放弃 |
| 反馈回收 | 评论、私信、读者提问、内部反馈或用户纠偏 | 反馈暴露了什么读者需求、误读点、选题机会或生产规则 |
| 传播表现复盘 | 转发、截图、评论复述、二创、跨环境搬运、群聊传播或传播路径证据 | 哪个传播单元生效，读者替自己表达了什么，下一轮如何增强或降风险 |
| 内容库复盘 | 多篇文章、短视频、短帖、发布包、评论、后台数据或复盘快照混在一起 | 先分桶和抽样，再判断哪些栏目、机制和资产值得继续投入 |

用户给的是优质内容时，默认先做内容本体拆解。只有用户提供指标、评论或明确要求解释表现时，才把外部信号作为主轴。

## 内容库复盘

面对大规模、不同类型的内容库时，先做库级治理，再做内容拆解。不要把所有内容放在一张总榜里直接比较，也不要逐条平均复盘到失去重点。

### 盘点字段

先确认用户提供了哪些字段，缺失字段要标注，不要补造。

```text
内容 ID / 标题：
交付形态：长文 / 短文 / 短视频 / 长脚本 / 发布包 / 评论反馈 / 其他
发布环境：
栏目 / 系列 / 主题：
目标读者：
内容目标：reach / engagement / retention / conversion / trust / learning
发布时间：
生产成本：
内容链接或原文：
指标：
评论或定性反馈：
创作者笔记：
```

字段不完整时，可以先做低精度复盘，但必须说明哪些结论只是候选假设。缺少原文或关键片段时，只能分析指标分布、栏目组合和反馈信号，不能断言内容本体机制。

### 分桶顺序

按以下顺序分桶，直到每个桶内的内容可比较：

1. **交付形态**：长文、短帖、短视频、长脚本、发布包、评论反馈不要直接混比。
2. **内容目标**：拉新、留存、评论、收藏、转化、信任建设和学习沉淀的指标口径不同。
3. **发布环境**：不同平台、社群、私域、搜索入口或 newsletter 只在桶内比较表现。
4. **栏目或读者任务**：同一栏目内看稳定性，不同栏目之间看组合价值。
5. **生产成本**：高成本内容和低成本内容要同时看收益和复用价值。

如果样本太少，不要硬分太细；先保留粗桶，并把结论标为待验证。

### 抽样策略

内容库复盘默认不全量深拆。每个桶优先抽这些样本：

- **高表现样本**：找可重复机制，不直接照搬题材或身份条件。
- **低表现样本**：找结构、角度、包装、读者错位或发布约束问题。
- **异常样本**：低 reach 高转化、高 reach 低互动、高收藏低评论、高留存低转化、高成本低结果。
- **代表样本**：能代表稳定栏目、常见题材、常用结构或主要读者任务。
- **近期变化样本**：同一栏目近期突然变好或变差时，优先查假设变化。

抽样后先做桶内深拆，再做跨桶综合。没有抽到的内容只能作为分布背景，不能直接升级成机制证据。

### 归一化比较

跨类型内容只能比较机制和组合，不直接比较原始指标。需要比较时先归一化口径：

- 同一发布环境内看相对排名、分位、趋势或异常值。
- 同一内容目标内比较目标指标，不用 reach 替代 conversion，也不用点赞替代信任。
- 同一栏目内比较稳定性、复用成本和读者反馈质量。
- 跨交付形态只比较读者任务、角度机制、hook 动作、证据方式、传播单元和转化桥。

如果指标来自不同平台或不同时间窗口，必须标注“不可直接横比”。可以提出候选解释，但不能把它写成已验证规律。

### 簇内拆解

每个桶内至少回答：

```text
这个桶服务什么读者任务：
表现最好的一组内容共同点：
表现最弱的一组内容共同点：
异常样本暴露了什么：
可重复机制：
不可迁移条件：
应继续投入的栏目：
应停止或降级的栏目：
下一轮实验：
```

桶内结论要回到内容动作，不只写“这个题材好”“这个平台差”。如果发现根因属于选题、角度、结构、包装、传播、转化、案例或声音，按归属交给对应 skill。

### 跨桶综合

跨桶综合只输出三类结论：

- **可迁移机制**：多个桶中反复成立的注意力、理解、信任、情绪、记忆、传播或行动机制。
- **条件性机制**：只在某个交付形态、发布环境、读者任务或成本结构下成立的机制。
- **组合判断**：哪些栏目负责 reach，哪些负责 trust，哪些负责 conversion，哪些适合沉淀为长期资产。

不要把一个桶里的成功经验直接变成全库规则。至少经过同类替换测试；只有多个桶或多个周期反复成立，才标为可迁移模式。

### 内容库输出

内容库复盘返回：

```text
内容库范围：
已有字段：
缺失字段：
分桶方式：
抽样口径：
不可横比的指标：
桶内发现：
跨桶机制：
条件性机制：
栏目组合判断：
应保留 / 扩大 / 降级 / 停止的内容类型：
可沉淀资产合并建议：
下一轮实验矩阵：
需要交给其他 skill 的任务：
```

### 资产合并

内容库复盘很容易生成过多资产卡片。沉淀前先合并同源机制：

- 同一个机制出现在多个样本中，合并为一张可迁移模式卡，不为每条内容各写一张。
- 同一栏目下的多个样本，优先沉淀栏目模式或实验记录，不拆成零散结论。
- 只在单条内容成立的发现，保留为优质内容样本或复盘快照。
- 指标异常但缺少原文证据的发现，标为待验证假设，不沉淀为生产资产。
- 会改变 CFlow 长期行为的发现，只输出维护建议，交给 `$cflow-maintain`。

## 优质内容拆解

拆好内容时，不要只说“有共鸣”“结构清楚”“标题吸引人”。必须指出具体内容动作。

按这些维度检查：

- **选题入口**：它抓住了哪个具体读者处境、欲望、痛点、误解、时机或未被说透的问题？
- **角度压力**：它有没有清楚的主张、反差、冲突、判断或读者张力？读者为什么不能一眼划走？
- **Hook 承诺**：开头承诺了什么收益、答案、故事、冲突、情绪或身份表达？正文有没有兑现？
- **结构推进**：内容是按问题递进、故事推进、反差展开、清单堆叠、证据累积还是情绪加压？
- **案例和证据**：哪些具体细节让它可信、可感、可记？是否靠故事、数字、对比、截图、场景或个人经历支撑？
- **表达密度**：哪些句子承担了判断、转折、压缩、幽默、共鸣、金句或解释功能？有没有空泛铺垫？
- **情绪曲线**：读者从开头到结尾经历了好奇、被看见、紧张、释然、认同、想反驳还是想行动？
- **Payoff**：结尾是否兑现了开头承诺，并留下记忆点、行动理由、评论入口或转发理由？
- **传播点**：哪些地方适合截图、复述、转发、评论、站队、模仿或二创？
- **转化点**：如果内容服务转化，它如何建立 desire、proof、trust、urgency 或 action？

## 传播表现复盘

发布后传播表现归 `$cflow-review`，不交给 `$cflow-viral` 完整复盘。`$cflow-viral` 提供分析维度，`$cflow-review` 负责证据判断、资产沉淀和下一轮实验。

先检查：

- 谁在转发、截图、评论、标注朋友或二创。
- 读者转发时是在替自己表达什么身份、情绪、立场、利益或关系。
- 哪一句、哪一屏、哪个清单、哪个模板或哪个故事反转被复述。
- 传播发生在公开转发、评论区、私下转发、群聊截图、跨环境搬运还是二创模板。
- 传播带来的是正确人群、错误人群、误读、争议还是转化。

输出时区分：

```text
传播证据：
有效传播单元：
分享动机：
传播路径：
被复述 / 截图 / 二创的元素：
误读或风险：
可沉淀传播模式：
下一轮实验：
```

如果只是发布前想增强传播潜力，交给 `$cflow-viral`。如果已经有发布后证据，即使用户说“viral 复盘”，也先进入 `$cflow-review`。

### 可学与不可学

复盘优质内容时必须区分：

- **能学的机制**：选题结构、角度构造、开头动作、段落推进、案例用法、表达动作、CTA 位置、传播单元。
- **暂时只能观察的假设**：可能有效但证据不足的情绪点、发布时机、读者偏好或栏目规律。
- **不能直接复制的条件**：作者身份、粉丝基础、题材红利、热点时机、渠道分发、稀缺经历、私有数据、已有信任和个人口吻。

不要把“这个作者这么写有效”直接翻译成“用户也应该这么写”。先问：去掉作者身份、渠道优势和原题材后，留下的内容动作还成立吗？

## 内容本体失效诊断

复盘失败草稿或低表现内容时，先看内容本身，再看外部数据。

常见失效点：

- 题太泛：读者不知道这和自己有什么关系。
- 角度太平：没有反差、冲突、判断或新信息。
- Hook 和正文错位：开头承诺强，正文没有兑现。
- 结构散：每段都像有道理，但没有递进。
- 证据空：只有判断，没有场景、案例、数字、对比或经历。
- 具体感弱：没有让读者看见、听见、代入或复述的细节。
- 表达太均匀：没有重句、短句、转折、停顿、金句或情绪变化。
- Payoff 弱：读完没有获得新判断、新方法、新情绪或新行动。
- 传播点缺失：没有适合截图、评论、站队、转发或复述的内容单元。
- CTA 断裂：前文没有铺出行动理由，结尾突然要求行动。

## 外部信号类型

- **Reach**：发布环境是否分发？
- **Engagement**：是否有人点赞、评论、收藏、转发或回复？
- **Conversion**：是否产生预期下一步动作？
- **Retention**：读者或观众是否持续看下去？
- **定性反馈**：人们引用、质疑、追问了什么？
- **创作者笔记**：什么感觉困难、顺、假、可重复？
- **Hook retention**：观众或读者是否留下了开头或首屏？
- **Drop-off points**：注意力在哪里明显下跌？

不要把单一指标当成全部真相。

外部信号只能辅助判断，不能替代内容拆解。没有指标和评论时，可以做内容本体复盘；有指标和评论时，要用它们验证或推翻内容本体假设。

不同平台的指标先归一到读者行为，再进入诊断。常读用户数、关注转化、复访评论等优先看账号关系资产；完读率、watch time 和 drop-off 看 retention；点赞、收藏、评论看 engagement；转发、截图、复述和二创看 share / spread；点击、私信、购买、预约看 conversion。用户提供的赞阅比、转阅比、完读率等本地阈值只能作为该账号或该平台的 benchmark，不写成 CFlow 通用标准，也不能用阅读量单独判断内容好坏。

复盘短帖、X post 或消息流内容时，先把互动拆成读者行为：收藏高通常说明有资料、决策、门槛或操作价值；回复高通常说明有争议、共鸣、站队或待补充空间；转发高通常说明有替读者表达的判断、提醒或信息差；点赞高但收藏和转发低，可能只是情绪反应或热点顺风，不要直接沉淀为生产规则。

## 表现信号诊断地图

- 低 reach、强反馈：可能是包装或分发问题。
- 高 reach、弱 engagement：选题可能太宽，或角度太浅。
- 收藏高但评论低：有用，但不够可讨论。
- 评论里有困惑：主张或结构问题。
- 读者说“没感觉”或“太抽象”：可能缺少 `$cflow-case` 提供的案例故事、微场景或具体证据。
- 强回复来自错误人群：目标读者错位。
- 高投入、弱结果：生产成本问题。
- 开头或首屏 retention 弱：hook、开场场景或目标读者不匹配。
- 前期 retention 强、后期掉：hook 有效，但正文没有刷新张力或兑现 payoff。
- Watch time 高但 conversion 低：内容有趣，但 desire、proof 或 action 不够。
- 低 reach 但 conversion 强：题可能窄但有价值，值得用更好的包装重复这个栏目。
- 同文案不同视觉表现差异大：优先判断封面信息层级、主视觉、thumbnail text、系列识别和第一眼读者任务；只把视觉机制交给 `$cflow-image`，不要直接否定内容主张。
- 同系列视觉表现逐渐走弱：可能是模板疲劳、变化区不足、固定元素压过本期主张，或老读者识别强但新读者看不懂。

## 资产沉淀

复盘结束时，必须执行一次沉淀动作判断，而不是只写“可沉淀资产”。先判断是否值得沉淀，再决定沉淀成什么资产、归属哪个生产 skill、是否需要写入文件或交给 `$cflow-maintain`。

优质内容拆解优先沉淀内容机制和生产资产，不要把单条案例里的发布环境、行业、人物、题材、作者身份或对象直接写成通用经验。

### 沉淀动作判断

按顺序判断：

1. **是否值得沉淀**：这个机制是否能用于下一次选题、角度、结构、包装、传播、转化、案例或声音判断？
2. **沉淀成什么**：优质内容样本、可迁移模式、生产资产、实验记录、voice 证据、维护建议，还是暂不沉淀？
3. **证据够不够**：只有一个样本时标为待验证；多个样本反复成立时才标为可迁移模式。
4. **归属哪里**：按根行为交给对应生产 skill，不按题材表面归属。
5. **是否写入**：用户没有明确要求保存、建档、沉淀、写入或创建资产库时，不自动写文件，默认输出资产卡片。
6. **是否维护规则**：如果资产会改变 CFlow 长期行为、流程、边界或路由，输出维护交接包并交给 `$cflow-maintain`，不能由 `$cflow-review` 修改 `skills/`。

如果值得沉淀但不写入，必须输出资产卡片；如果不值得沉淀，明确写“暂不沉淀”，并说明还缺什么信号或样本。

### 资产卡片

资产卡片是默认沉淀动作。它不是写文件，而是在本次回复里给出一张可复用记录，方便后续交给其他 skill 使用。

```text
资产名称：
资产类型：
适用场景：
核心机制：
证据样本：
可迁移模板：
不可复制条件：
归属 skill：
下一次使用方式：
是否需要写入文件：
是否需要交给 cflow-maintain：
```

资产卡片必须足够具体，不能只写“值得学习”“可复用”。如果是短内容机制，要写出可以再次套用的结构或表达动作。

### 可发现元数据

写入 `profiles/content-assets/` 的资产文件必须带 frontmatter，方便 `$cflow` 和相关生产 skill 发现。资产 frontmatter 是运行资产发现真源，必须通过 `scripts/quick_validate.py` 校验。

```yaml
---
asset_name:
asset_type:
skills:
  - cflow-package
triggers:
  - ""
use_when:
avoid_when:
evidence_level:
overuse_risk:
source: cflow-review
---
```

字段规则：

- `asset_name`：资产名，使用中文。
- `asset_type`：优质内容样本、可迁移模式、生产资产、实验记录、voice 证据或复盘快照。
- `skills`：可采用该资产的 skill 列表，只写真正相关的生产 skill。
- `triggers`：用户任务或素材中可能出现的触发词、场景、动作或内容类型。
- `use_when`：什么时候应该读取并采用。
- `avoid_when`：什么时候不该采用，避免模板误用。
- `evidence_level`：资产证据强度，建议使用 A / B / C / D 或“待验证”。A 表示多次复现且有指标或样本支撑；B 表示有明确样本和部分表现证据；C 表示内容机制清楚但证据弱；D / 待验证表示只适合候选参考。
- `overuse_risk`：过度套用风险，说明什么时候重复使用会模板化、污染作者声音、误导事实边界或让栏目变腻。
- `source`：默认写 `cflow-review`，说明资产来自复盘沉淀。

没有 frontmatter 或缺少必填字段的资产不是稳定可发现资产，应补齐元数据后再进入自动发现。

### 资产层级

| 层级 | 存什么 | 边界 |
|---|---|---|
| 复盘快照 | 单次内容的事实、指标、评论、截图、创作者体感、缺失数据 | 只记录证据和当次解释，不写成模式 |
| 优质内容样本 | 这条内容体现了什么机制，以及它在原语境中为什么可能有效 | 仍然绑定具体语境，不能直接迁移成规则 |
| 可迁移模式 | 去掉发布环境、行业、人物、题材后仍成立的注意力、理解、传播或转化机制 | 可以交给对应 skill 复用，但仍不是 skill 规则 |
| 生产资产 | 可复用的选题模板、角度结构、段落推进、表达动作、案例用法、hook 机制或传播单元 | 用于下一轮生产，但需要继续验证 |
| 长期规则 | 会长期约束 CFlow 行为的规则、流程或边界 | `$cflow-review` 只能提出维护建议，必须交给 `$cflow-maintain` 修改 |

### 抽象检查

沉淀资产前先做同类替换测试：

```text
把案例中的发布环境、交付形态、人物、行业、题材或具体素材替换成同类变量后，这个经验是否仍成立？
```

- 只能在原案例中成立：标为优质内容样本或单次案例样本。
- 换场景后仍可能成立，但证据只有一次：标为待验证模式。
- 多个样本反复成立：标为可迁移模式。
- 会约束 CFlow 以后如何行动：标为维护建议，交给 `$cflow-maintain`。

### 归属判断

判断资产归属时，先看根行为，不看表面题材：

| 复盘发现 | 沉淀为 | 归属 |
|---|---|---|
| 某类读者反复提问 | 选题池或栏目 | `$cflow-topic` |
| 某个冲突特别有效 | 角度模式 | `$cflow-angle` |
| 某种结构推进特别顺 | 结构模式 | `$cflow-draft` |
| 某个短链路、首屏推进、单点表达或段落密度有效 | 短内容生产资产 | `$cflow-shortform` |
| 某个故事带来强反馈 | 案例库 | `$cflow-case` |
| 某种表达动作特别有记忆点 | 表达资产或 voice 证据 | `$cflow-voice` |
| 某个标题明显拉动点击 | 包装策略 | `$cflow-package` |
| 某个封面或配图明显拉动点击 | 视觉策略 | `$cflow-image` |
| 某个截图点、复述句或站队点有效 | 传播模式 | `$cflow-viral` |
| 某个 CTA 带来转化 | 转化路径规则 | `$cflow-marketing` |
| 某段话特别像作者 | Voice profile 证据 | `$cflow-voice` |
| 某个拆解 prompt 或采访问题反复提高产出质量 | 生产资产 | `$cflow-benchmark` |
| 某个发布环境持续不匹配 | 发布约束判断 | `$cflow` |
| 某个复盘暴露了 skill 行为缺陷 | 维护建议或测试用例 | `$cflow-maintain` |

如果没有足够证据沉淀资产，要明确写“暂不沉淀”，并说明还缺什么反馈。

输出 `可沉淀资产` 时必须写清：

```text
资产层级：
可迁移机制：
具体证据：
同类替换测试：
归属：
沉淀动作：
是否需要写入文件：
是否需要交给 cflow-maintain：
```

### 生产资产

复盘发现某个结构、hook 机制、拆解 prompt、采访问题或变体生成流程持续有效时，可以沉淀为生产资产。沉淀为生产资产时，默认先输出资产卡片；只有用户明确要求保存、建档、沉淀、写入或创建资产库时，才进入写入流程。

生产资产不是 skill 规则。先记录：

- 它解决了哪个生产问题。
- 依赖哪些输入素材和上下文。
- 哪些发布环境、交付形态或读者场景已经验证过。
- 哪些部分只是单次案例，不能直接泛化。
- 下一次如何复用和验证。

如果生产资产要变成长期 CFlow 行为约束，必须作为维护建议交给 `$cflow-maintain`，不能由 `$cflow-review` 直接写入 `skills/`。

### 维护交接包

复盘发现会优化其他 CFlow skill 时，不要停在“建议更新某 skill”。必须输出一份维护交接包，交给 `$cflow-maintain` 继续做归属判断、反膨胀审计、审批计划和实际修改。

触发条件：

- 某个机制反复出现，且会长期改变选题、角度、结构、hook、短内容、传播、转化、案例、声音、SEO 或复盘流程。
- 复盘暴露了已有 skill 的流程缺口、边界缺口、路由缺口或资产发现缺口。
- 复盘发现某条已有规则未执行，需要作为测试用例或执行提醒交给维护入口。

不触发条件：

- 只在单条内容、单个账号、单个行业、特定热点、私有信源或作者身份条件下成立。
- 只是普通生产资产，能写入 `profiles/content-assets/` 或输出资产卡片解决。
- 证据不足，只能作为待验证假设。

维护交接包格式：

```text
维护交接包：
来源证据：
复盘对象：
可迁移机制：
不可复制条件：
为什么不是普通资产：
建议影响 skill：
建议动作：新增 / 收紧 / 移动 / 删除 / 补测试 / 仅提醒执行
建议规则：
同类替换测试：
证据强度：单样本 / 多样本 / 多周期 / 反复执行失败
交给：$cflow-maintain
```

交接包只提出维护建议，不替 `$cflow-maintain` 做最终修改决定。是否进入通用规则、作为测试用例、作为例子、合并旧规则、移动规则或拒绝沉淀，由 `$cflow-maintain` 继续判断。

## 写入权限

`$cflow-review` 默认只输出复盘，不自动写文件。用户明确要求保存、建档、沉淀、写入或创建资产库时，才可以创建或更新复盘资产文件。

允许写入：

- 复盘快照
- 案例样本
- 模式笔记
- 实验记录
- 评论或反馈摘要

禁止写入：

- `skills/`
- `SKILL.md`
- `references/`
- `agents/openai.yaml`
- 任何会改变 CFlow 规则真源的文件

如果当前仓库没有资产目录，第一次创建目录前先说明目录方案，获得用户明确批准后再创建。默认不要把内容资产放进 `skills/`。

如果复盘发现需要更新 skill 规则、流程、边界或路由，只输出维护交接包，并交给 `$cflow-maintain` 处理。

## 长脚本 / 影音稿复盘

有指标时检查：

- 3 秒或首屏 retention
- 发布环境提供时看 5 秒 retention
- 第一个明显 drop-off 时间点
- 平均观看时长
- 完播率
- 关注或转化率

用 drop-off 时间点判断哪里需要加入新细节、转折、证据、open loop 或更快 payoff。不要在 retention 曲线证明无聊前，就假设视频太长。

## 下一步选择

- 同一栏目换例子重复。
- 保留选题，换角度。
- 保留主张，补案例故事。
- 保留角度，换包装。
- 复用到更合适的交付形态或发布环境。
- 把评论变成后续选题。
- 记录经验，停止投入这个栏目。
