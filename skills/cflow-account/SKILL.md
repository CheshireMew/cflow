# CFlow Account

## 边界

`cflow-account` 负责诊断用户自己的内容账号、主页、栏目组合、内容样本、发布节奏、互动反馈、表现数据和转化路径。交付物是账号级根因判断、证据分级、优先级建议和下一步实验，不是直接写完整内容。

账号诊断不是样本拆解。用户已提供可学习样本、爆款内容或 copywork 对象时，交给 `$cflow-review` 拆机制；复盘单篇内容、已发布内容库或发布结果也交给 `$cflow-review`。设计 offer、CTA 和完整转化路径时，交给 `$cflow-marketing`。

默认可以基于用户提供的账号描述、截图转述、主页文案、内容样本、后台数据、评论或创作者体感做诊断。没有数据时可以做低证据诊断，但必须标注假设性质和需要补充的信息；不得假装知道平台分发、真实受众或隐藏指标。

只有用户要求查看当前账号页面、实时竞品、平台趋势、公开数据或来源核查时，资料搜集交给 `$cflow-research`。用户只提供离线材料时，不主动联网。

## 工作流

1. 判断诊断对象：主页、账号定位、内容栏目、单个平台账号、多平台账号、数据表现、商业化路径或生产系统。
2. 盘点输入证据：账号目标、目标读者、主页信息、内容样本、栏目、发布节奏、指标、评论反馈、转化动作和创作者体感。
3. 标注证据等级：有原文、有截图、有数据、有评论、只有描述、只有体感；缺什么就写清楚。
4. 明确账号任务：增长、建立信任、筛选客户、教育市场、销售转化、社群运营、个人品牌、作品集展示或内容实验。
5. 做账号级根因诊断：定位、目标读者、主页承诺、栏目组合、选题质量、角度强度、包装、内容结构、发布节奏、互动反馈、转化路径和生产系统。
6. 有数据时先统一口径，再判断 reach、engagement、retention、conversion、trust 和生产成本；不同平台、不同时间窗口、不同内容目标不可直接横比。
7. 无数据时基于内容本体和账号结构提出候选假设，不下确定性表现结论。
8. 收口到少数关键问题：区分主因、次因、证据不足的假设和暂不处理的噪音。
9. 给出优先级建议：先修能改变账号理解、内容供给或转化路径的动作，再修局部文案和细节。
10. 需要专项执行时，交给对应 CFlow skill，而不是在账号诊断里硬做所有产物。

## 诊断入口

先判断用户给来的是什么，不要默认进入数据分析。

| 输入 | 主问题 |
|---|---|
| 账号主页、简介、置顶内容 | 陌生人是否能理解这个账号为谁解决什么问题 |
| 多篇内容样本 | 内容供给是否稳定，栏目和读者任务是否清楚 |
| 后台数据、截图、表格 | 表现问题更像分发、互动、留存、转化还是生产成本 |
| 评论、私信、用户反馈 | 受众是否准确，读者到底在追问什么 |
| 创作者体感 | 生产系统哪里卡住，是否有定位或栏目错配 |
| 无数据描述 | 只能做结构诊断和候选假设，不能断言真实表现 |

用户只说“帮我看看账号”时，先根据已有材料推进低证据诊断，不要把流程卡死在追问里；但必须说明哪些判断需要补证据。

## 证据协议

账号诊断必须区分证据强弱。

| 等级 | 证据 | 可做判断 |
|---|---|---|
| A | 原文、主页截图、内容样本、指标、评论齐全 | 可以做账号级根因诊断和优先级排序 |
| B | 有内容样本和部分指标 | 可以判断内容机制和表现假设 |
| C | 有主页或内容样本，无指标 | 可以判断定位、栏目、包装和内容本体 |
| D | 只有用户描述或体感 | 只能输出候选假设和补充清单 |

低证据诊断也要有用，但不要把“可能”写成“已经证明”。

无数据或弱数据时必须输出：

- 当前判断性质：低证据诊断 / 候选假设 / 基于用户材料。
- 不能确认的部分。
- 最值得补充的 1 到 3 个信息。

## 账号任务

账号不是天然为了涨粉。先确认它现在承担什么任务：

- **Reach**：让更多陌生人看见。
- **Trust**：建立专业、审美、判断或人格信任。
- **Engagement**：让读者评论、收藏、转发、私信或参与讨论。
- **Conversion**：让读者预约、购买、进群、留资、咨询或订阅。
- **Learning**：通过发布测试选题、受众、表达和 offer。
- **Portfolio**：展示作品、案例、方法和可信度。
- **Community**：维系社群关系、回答问题、推动互动。

同一个账号可以有多个任务，但诊断时要先找当前主任务。用涨粉指标评估高意向转化账号，或者用转化指标评估早期定位探索账号，都会误诊。

## 根因地图

账号问题优先按账号级根因收口，而不是按单条内容现象修补。

### 定位和主页

常见问题：

- 陌生人看不出账号为谁服务。
- 主页承诺太抽象，只说身份、价值观或宏大领域。
- 账号名称、简介、置顶内容和真实发布内容互相不支持。
- 主页只表达创作者想说什么，没有表达读者为什么要关注。
- CTA 太早或太重，账号还没有铺出足够信任。

账号主页是陌生人判断是否信任、关注或继续了解的第一层证据。诊断主页时，不只看简介是否顺口，也要看个人资料里的每个元素是否共同支持一个清楚的关注理由。

检查维度：

- **定位标签**：账号是否快速说明自己是谁、为谁提供什么、凭什么值得关注。标签要帮助读者理解关注理由，不只是堆身份。
- **视觉一致性**：头像、头图、配色、内容配图和产品视觉是否形成识别感。视觉一致性服务专业感和记忆点，不等于必须使用亮色或复杂设计。
- **品牌符号**：emoji、符号、固定称呼、口头标记或视觉锚点是否强化识别。符号只有在反复出现并服务账号记忆时才有价值，不能为了装饰而加。
- **简介可信度**：简介是否用真实角色、经历、作品、成果、失败经验、客户对象或项目经验支撑可信度。成就、履历、结果、身份和项目经验必须来自用户素材，不得为了增强合法性编造。
- **置顶内容**：置顶内容是否承担作品证明、可信度、个人故事、核心主张、代表作或转化承接，而不是随意置顶高互动内容。

如果个人资料第一印象弱，先判断根因：看不懂定位、缺少视觉识别、缺少可信度证据、置顶内容不承接主页承诺，还是 CTA 与当前信任程度不匹配。不要直接建议“换头像”“加 emoji”或“重写简介”。视觉、包装、可信度素材和转化承接问题按协作路由分流。

检查问题：

```text
目标读者是谁：
他们来这里想解决什么问题：
主页承诺了什么：
最近内容是否持续兑现这个承诺：
关注理由是否能在 5 秒内看懂：
下一步动作是否自然：
视觉和符号是否形成识别感：
简介和置顶内容是否提供可信度证据：
```

### 内容供给

常见问题：

- 栏目太散，读者不知道关注后会持续得到什么。
- 选题只从创作者想表达的概念出发，不从读者处境出发。
- 同一账号里混杂多个不兼容读者任务。
- 内容有观点但没有案例、场景或证据。
- 内容单条看还行，组合起来没有账号记忆点。
- 发布节奏看似勤奋，但没有稳定栏目和复用机制。

检查栏目时，不要只数主题标签。要看每个栏目服务哪个读者任务、是否能重复生产、是否有足够素材来源、是否支撑账号主任务。

内容支柱不是兴趣分类表，也不是限制创作者只能写固定话题。少数稳定支柱的作用是让读者逐渐知道这个账号长期会提供什么判断、方法、故事、审美或资源。诊断内容支柱时，先看它们是否共同形成账号识别和复访预期，而不是机械要求 3 到 5 个分类。

检查内容支柱：

```text
每个支柱服务哪个读者任务：
每个支柱能否持续产出选题：
支柱之间是否共享同一批目标读者：
爆款是否能回流到某个支柱或栏目：
是否有支柱只是创作者兴趣，但读者不知道为什么要关注：
```

### 复访理由

账号粘性不是单条内容互动高，也不是偶发爆款。诊断时要区分内容吸引力和账号关系资产：

- 内容吸引力：读者因为某条信息、故事、热点、资料或观点停留、点赞、收藏、转发。
- 账号关系资产：读者反复回来找这个账号的判断、筛选、解释、审美、人格或方法。

常见问题：

- 账号像高质量信息雷达，但缺少稳定世界观，读者记住素材而不是记住账号。
- 内容经常解释“他们发生了什么”，但很少持续说明“这件事跟目标读者有什么关系”。
- 单条内容可以出圈，但栏目之间没有形成复访预期，读者不知道下次还能得到什么。
- 账号有观点但缺少可重复的判断标准，读者无法形成“我想知道这个人怎么看”的关系。
- 爆款吸引泛人群，主页、置顶和后续内容没有把泛注意力转成关注理由。
- 账号有内容支柱、对标模板和稳定发布，但看不出作者为什么非讲这些不可，缺少持续的问题意识、反感对象、风险经验或人格吸引。

检查问题：

```text
读者回来是为了看信息，还是为了看这个账号的判断：
账号是否有稳定世界观和判断标准：
作者持续关心的问题是什么：
作者反复反对、害怕或不愿回到的状态是什么：
哪些内容体现了作者的风险经验、判断代价或真实欲望：
是否明确持续服务同一批目标读者：
是否有读者能记住的固定栏目或系列：
爆款之后是否有承接内容把新读者留下：
哪些内容带来关注、评论复访、私信或连续互动：
```

### 包装和首屏

常见问题：

- 标题、封面、开头没有筛选目标读者。
- Hook 承诺和正文兑现错位。
- 账号主页强，单条内容第一眼弱。
- 内容本体有价值，但包装没有显示具体收益、冲突、场景或身份表达。

包装问题交给 `$cflow-package` 或 `$cflow-image` 执行，不在账号诊断里批量生成标题和封面。

### 数据和反馈

数据先按目标解释：

| 信号 | 可能问题 |
|---|---|
| 低 reach、强私信或转化 | 包装或分发弱，但题和人群可能窄而有价值 |
| 高 reach、低关注 | 单条内容吸引泛人群，账号承诺或主页接不住 |
| 高 reach、低互动 | 可能是泛曝光、跨圈层曝光、语言或语境错配、互动入口弱；不能直接判断为限流 |
| 高收藏、低评论 | 有用但不够可讨论，可能缺观点压力或互动入口 |
| 高评论、低转化 | 讨论强，但 offer、信任或行动路径不足 |
| 高完读或高停留、低行动 | 内容有吸引力，但 desire、proof 或 CTA 不够 |
| 强互动来自非目标人群 | 选题或包装筛错人 |
| 浏览来自跨语言或跨圈层人群 | 先拆成看见、理解、互动、关注和转化几层；翻译或跨圈层推荐只能作为候选假设，需要互动用户画像、评论语言、关注转化或链接点击验证 |
| 同栏目波动大 | 角度、包装、发布时间或样本太少，不能直接下结论 |

不同平台、不同时间窗口、不同内容目标不可直接横比。可以比较相对排名、趋势、异常值和同栏目样本，不要用总点赞替代账号健康度。

判断粉丝粘性时，不要只看总浏览、总点赞或单条爆款。优先看中位表现、关注转化、评论复访、私信质量、收藏后的后续行动、同一批读者是否连续互动，以及爆款后主页和后续内容是否承接住新读者。

### 转化路径

内容账号服务商业目标时，检查：

```text
账号吸引谁：
内容建立什么信任：
读者下一步动作是什么：
主页、置顶、私信、链接或评论是否承接：
offer 是否清楚：
行动摩擦是否匹配信任程度：
```

如果 offer、CTA 或 funnel stage 不清，交给 `$cflow-marketing`。如果只是主页简介或置顶文案需要改写，交给 `$cflow-package` 或 `$cflow-edit`。

### 生产系统

账号长期不起色不一定是单条内容差，也可能是生产系统问题：

- 没有稳定选题来源。
- 没有栏目复用结构。
- 每条都从零开始，生产成本过高。
- 缺少复盘循环，发布后没有把评论和数据变成下一轮素材。
- 对标过多导致声音、读者和栏目漂移。
- 创作者擅长的素材形态和选择的平台不匹配。

生产系统建议要落到下一步动作，例如建立栏目、复用结构、降低发布成本、集中测试一个读者任务或停止低质量泛发。

## 优先级排序

账号诊断必须给优先级，不输出平均用力的建议清单。

按这个顺序排序：

1. **理解问题**：陌生人看不懂账号为谁服务，先修主页、定位和栏目承诺。
2. **供给问题**：内容持续性差、栏目散、读者任务混乱，先修内容组合。
3. **选题和角度问题**：读者处境弱、主张平，交给 `$cflow-topic` 和 `$cflow-angle`。
4. **包装问题**：内容成立但第一眼弱，交给 `$cflow-package` 或 `$cflow-image`。
5. **信任和证据问题**：观点多但案例少，交给 `$cflow-case`、`$cflow-draft` 或 `$cflow-edit`。
6. **转化问题**：有注意力但没有行动，交给 `$cflow-marketing`。
7. **生产问题**：成本高、不可持续，调整栏目、模板和复盘循环。

如果定位和栏目不清，不要先建议日更、改封面、追热点或换平台。局部优化不能替代账号级理解。

## 30 天实验

账号诊断建议要能进入实验，不只写原则。

一个 30 天实验至少包含：

```text
主假设：
目标读者：
要测试的栏目：
内容数量：
每条内容的共同约束：
要观察的指标：
要收集的评论或私信信号：
要记录的互动用户画像：
要验证的复访或关注转化信号：
停止条件：
下一次复盘时间：
```

没有数据时，30 天实验用于补证据；有数据时，30 天实验用于验证根因修法。

## 协作路由

账号诊断只负责判断和排序。执行时交给专项 skill：

| 诊断发现 | 交给 |
|---|---|
| 目标读者和栏目不清 | `$cflow-interview`、`$cflow-topic` |
| 选题泛、没有读者处境 | `$cflow-topic` |
| 观点平、没有张力 | `$cflow-angle` |
| 内容样本结构散 | `$cflow-edit`、`$cflow-draft` |
| 缺案例、缺证据、太抽象 | `$cflow-case` |
| 短内容链路弱 | `$cflow-shortform` |
| 标题、开头、主页表达弱 | `$cflow-package` |
| 头像、头图、配色、视觉锚点不统一 | `$cflow-image` |
| 封面、头图、视觉识别弱 | `$cflow-image` |
| 缺少可信度素材、作品证明或个人故事 | `$cflow-interview`、`$cflow-case` |
| 分享、转发、评论入口弱 | `$cflow-viral` |
| 主页承诺、offer、CTA、私信或购买路径弱 | `$cflow-marketing` |
| 需要复盘已发布内容库 | `$cflow-review` |
| 需要查当前账号或竞品事实 | `$cflow-research` |
