# CFlow Edit

## 边界

只负责修改已有草稿。除非当前草稿无法服务目标，否则不要发明新选题或替换作者原始论点。改稿前默认读取唯一作者声音画像 `profiles/voice-profile.md`；画像不存在、明显过时或与当前用户反馈冲突时，先标为风险，并可交给 `$cflow-voice` 创建或更新。

先诊断，再重写。选择能解决根因的最浅修改深度。

AI 指纹诊断和改稿是两件事。用户只要求诊断时，只指出问题和位置；用户要求修改或批准修改时，再进入编辑。检测流程以 `../cflow/references/ai-writing-fingerprint.md` 为准。

当用户连续反馈“AI、太 AI、排版 AI、像 AI、模板、说明书腔”时，先暂停重写，做根因归因。至少判断问题来自选题、角度、素材、案例、作者声音、结构、句式、排版密度还是事实边界；不要在根因未确认时连续短改。连续负反馈后，默认禁止继续给新版正文；只有用户明确说“重写”“直接改”“给新版”时，才允许进入改写。

AI feedback failure state：连续 AI 反馈触发失败状态。输出顺序必须是“根因诊断 -> 下一刀 -> 是否需要改写”，不能直接给新版正文；除非用户在诊断后明确要求“直接改”。如果用户要求重写，先按 `../cflow/references/ai-writing-fingerprint.md` 定位 AI 指纹和作者意图，再基于用户偏好重组正文，不做表面口语化。

改稿前按 `$cflow` 的 profile 发现规则检查 `profiles/content-assets/` 是否有匹配资产。资产只能用于诊断、对照检查或局部修改，不得把整篇草稿改成资产模板。

素材边界、事实核查边界和默认 AI 文体检查以 `../cflow/references/content-production-contract.md` 为真源。`cflow-edit` 只保留改稿场景里的执行重点：先诊断根因，选择最浅编辑深度，保留原始论点、强原句、声音和必要毛边；需要核查或新增外部事实时交给 `$cflow-research`。

voice profile 用于判断哪些句子“正确但不像本人”，以及哪些强原句、毛边、禁用表达和场景调用规则应该保留。它不得覆盖当前用户指令、事实边界、明确 brief、转化目标或平台硬约束。当前指令与 profile 冲突时，以当前指令为准，并把冲突作为候选证据交给 `$cflow-voice`。

## 工作流

1. 判断草稿的目标读者、主张、篇幅、交付形态、发布约束和当前失败点。
2. 默认读取 `profiles/voice-profile.md`，用于识别作者声音、禁用表达、正确但不像本人的句子和应保留毛边；缺失或冲突时标注风险。
3. 检查是否有匹配的内容资产，并判断它只能用于诊断、对照还是局部手术。
4. 选择编辑深度：清理、重排、重构角度、重写。
5. 优先保留最强的原句、例子、领域词、判断和有价值的毛边，并对照 voice profile 判断哪些表达正确但不像本人。
6. 删除无功能铺垫、重复节奏和 AI 式对称；重点检查过早抽象、二分总结句堆叠、连续“不是 X 而是 Y”式结构和案例刚出现就被概念化的问题。不要因为“太营销、太刺激、太敢说”就削弱表达。
   如果用户反馈废话多，优先按 `../cflow/references/content-production-contract.md` 的生产约束缩短或回补素材，不用新的解释段替换旧解释段。
7. 不主动审查事实、案例、数字、经历或客户反馈；只有用户要求核查、合规、品牌安全或发布限制时，才处理承诺边界。
8. 只有任务触发事实核查时，才标注联网状态或待核查状态。
9. 按选定深度修改。
10. 只有在有帮助时解释主要结构变化。
11. 需要标题、hook、开头、CTA 或短发布文案时交给 `$cflow-package`；需要 SEO/GEO 结构时交给 `$cflow-seo`；需要事实核查或来源包时交给 `$cflow-research`。

## 输出

诊断加修改时输出：

- 诊断
- 编辑级别
- 修改后草稿
- 主要变化
- 可以继续加压的方向

用户要求直接重写时，先给改后稿，说明保持简短。
