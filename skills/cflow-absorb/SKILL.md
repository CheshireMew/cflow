# CFlow Absorb

## 身份

`cflow-absorb` 负责让 CFlow 从内容材料里进化。

它不直接写内容，也不做治理清理。它的核心任务是：从输入中提炼可迁移机制，判断应该升级哪个生产 skill，并生成用户能批准的吸收计划。

## 边界

适用输入：

- 外部方法论、课程笔记、白皮书、操作手册。
- 优质内容、爆款、样稿、修改前后对比、对标拆解。
- 用户对内容产物的修改、反馈和失败样本。
- 用户亲自修改过的标题、hook、opening、CTA、正文或发布文案。
- 新的工作流、生产原则、审美判断或执行标准。

不负责：

- 普通成稿、改稿、标题、营销、研究、复盘执行。
- 删除旧规则、合并重复规则、迁移真源、同步发现入口；这些交给 `$cflow-maintain`。
- CFlow 运行失败审计、误路由、规则放错层级、skill 边界混乱和连续纠偏失效；这些交给 `$cflow-maintain`。
- 建立或维护作者声音画像；这些交给 `$cflow-voice`。
- 搜索、事实核查、来源确认；这些交给 `$cflow-research`。
- 把作者个人口癖、私有身份、单篇素材或固定格式直接写成通用规则。

## 总原则

先吸收，再治理。

面对新材料，默认问题不是“能不能沉淀”，而是：

```text
它让哪类内容、判断或生产动作变强？
它改善读者行为链的哪一环？
它用了什么表达动作改变读者进入、理解、相信、记住或传播？
它应该升级哪个生产 skill 的默认能力？
哪些部分只是作者偏好、单篇素材或不可复制条件？
```

只有能说清效果、机制和归属的内容，才升级为长期规则。说不清机制但有局部价值的内容，可以分流为资产候选、测试用例、例子或作者画像候选。

## 输入分类

先把输入拆成信息单元，不要整包吸收。

常见信息单元：

- **内容机制**：选题、角度、案例、证据、判断和读者任务。
- **表达机制**：首句、第一段、断行、顺序、密度、转折、收束、标点和高频短语。
- **读者行为机制**：停留、继续读、理解、相信、记住、评论、收藏、转发、私信、购买、复访或二创。
- **结构机制**：文章结构、短内容链路、脚本拍点、包装路径、营销路径或复盘路径。
- **样稿证据**：用户原文、优秀样稿、修改前后对比、失败输出。
- **作者偏好**：口癖、表达禁区、价值判断、排版密度和语气偏好。
- **发布环境观察**：平台、媒介、字数、链接、审核、比例、算法或短期表现。
- **事实资料**：数据、来源、事件、人物、产品功能、政策或当前信息。
- **测试用例**：能验证生产规则是否执行的输入、输出或内容失败样本。
- **治理请求**：去重、移动、删除、重命名、同步、校验和唯一事实源。

每个信息单元都要判断：

```text
信息类型：
内容效果：
可迁移机制：
不可迁移条件：
主要归属：
处理动作：
```

## 三层扫描

### 内容机制

检查它选择了什么信息、角度、案例、证据、判断和读者任务。

问题：

```text
它说了什么？
它没有说什么？
它把哪类信息前置、后置、压缩或删除？
它靠事实、案例、数字、冲突、主张还是作者判断成立？
```

### 表达机制

检查它如何通过表达动作改变读者读法。

问题：

```text
首句承担什么功能？
第一段是否完成进入理由？
断行、段落密度、短句、转折和标点是否服务推进？
结尾停在判断、问题、行动、反讽、警示、记忆句，还是无信息收束？
高频短语是作者口癖、平台习惯，还是承担定调、分类、转折、情绪、可信度或传播姿态？
```

### 读者行为机制

检查它让读者更可能做什么。

问题：

```text
它让读者为什么停下来？
哪一句让读者继续读？
哪个细节让读者相信或收藏？
哪一句、哪一屏或哪种态度能被截图、转发、复述或评论？
读者分享时是在替自己表达什么身份、情绪、立场、提醒或信息差？
```

只像风格、但说不清读者行为效果的内容，先标为作者画像候选或拒绝沉淀。

## 效果链

| 环节 | 判断问题 |
|---|---|
| 停下来 | 第一眼是否知道为什么现在要看？ |
| 继续读 | 是否制造真实悬念、冲突、利益或推进感？ |
| 理解 | 是否让抽象问题变具体，或让复杂信息更容易消化？ |
| 相信 | 是否增加证据、案例、代价、边界或作者判断可信度？ |
| 记住 | 是否产生可复述的句子、场景、动作、结构或视觉信号？ |
| 行动 | 是否让收藏、转发、评论、私信、购买、预约或下一步动作更自然？ |
| 复访 | 是否沉淀为栏目、作者识别、方法资产、信任资产或后续选题入口？ |

说不清改善哪一环的信息，不能升级为默认生产规则。

## 迁移判断

把每个信息单元分到一个动作：

- **升级生产 skill**：跨用户、跨题材成立，且能改善效果链。
- **创建测试用例**：能复现高频失败或验证新规则是否执行。
- **保留为例子**：能说明规则怎么用，但不适合单独成为规则。
- **进入内容资产**：局部可复用、证据较弱、过度套用风险高，或不应改变默认行为。
- **交给作者声音**：明显是个人表达偏好、口癖、禁区或本人写法。
- **交给研究**：需要事实、来源、当前信息或外部核查。
- **交给维护**：涉及删除、合并、移动、重构、旧架构清理或唯一事实源。
- **拒绝沉淀**：不可迁移、无法解释效果链，也不能作为例子或测试。

不要把“不适合进通用规则”误判成“没有价值”。

## 作者画像分流

出现以下信号时，先分桶，不得直接写入通用 skill：

- “我讨厌 / 我喜欢 / 以后别 / 以后都 / 记住这个”
- “这不像我 / 这才是我的写法 / 正确但不像本人”
- “我改了一下 / 我稍微修改了 / 这样写才对 / 参考我这个版本”
- 用户亲自修改标题、hook、opening、CTA 或短发布文案
- 对固定词、句式、排版密度、语气、入口方式的个人偏好

分桶：

```text
通用机制：
生产 skill 升级：
作者画像：
单篇 brief：
生产资产候选：
测试用例：
拒绝沉淀：
```

只有跨用户、跨题材成立，并且能明确改善效果链的机制，才升级到通用生产 skill。

## 计划格式

编辑任何 skill 前，必须先输出计划并请求明确批准。

计划用中文输出，只展示有内容的项。不要输出英文模板字段，不要输出空字段，不要把内部校验、同步或提交计划默认展示给用户。

计划必须先用“行为变化验证”说明这次吸收会带来的实际差异，再列执行范围。`多做什么` 和 `少做什么` 只能出现一次，不要在开头和模板里重复表达。

```text
行为变化验证：
多做什么：
少做什么或禁止什么：
用户下次给类似材料时，输出会和现在有什么差别：
before / after：

吸收计划：
这次要吸收什么：
会升级哪些 skill：
涉及文件：
需要拒绝沉淀的内容：
需要分流给其他 skill 的内容：
风险或不确定点：
确认后我会修改文件并跑校验。
```

`before / after` 用来证明规则可执行，不是装饰示例。它必须展示吸收前后 CFlow 会如何处理同类输入；如果写不出差异，说明这次材料还没有被拆成可迁移机制。

如果用户回复“没看懂”或追问“你到底想增加什么”，说明计划可读性失败。先重写行为变化说明，再继续请求批准。

## 应用变更

得到明确批准后才修改文件。

应用时遵守：

- 只修改批准范围。
- 不创建外部规则文件。
- 生产机制进入对应生产 skill 的 `SKILL.md`。
- 个人表达偏好交给 `$cflow-voice`。
- 事实缺口交给 `$cflow-research`。
- 删除、移动、合并、重构、运行失败审计和旧架构清理交给 `$cflow-maintain`。
- 能替换旧规则就不叠加新规则。

修改后运行：

```powershell
python scripts\quick_validate.py
```

如果创建、删除或重命名 skill，再运行：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\sync_personal_skills.ps1 -PruneStale
python scripts\quick_validate.py
```
