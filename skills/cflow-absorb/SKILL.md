# CFlow Absorb

## 工作目标

把输入材料变成可执行的 CFlow 生产规则，并在用户批准后修改对应 `SKILL.md`。

吸收的重点不是保存材料原文，而是写出可重复动作：下次遇到什么输入，先判断什么，按什么顺序处理，删掉哪类坏输出。

## 维护约束

- 正文不重复 description 已经说清的范围。
- 只保留吸收、判断、写入 skill 的规则。
- 跨 skill 调度由主入口处理；本文只处理本次机制写入哪里。
- 新规则必须短、清楚、可执行，不能把样稿全文、单篇案例或口号写进 skill。
- 修改其他 skill 时，遵守目标 skill 的文档标准：能归类就归类，只写负责的事，模板字段必须是信息单元。
- 写入前必须检查是否被单个领域、样本、作者或素材来源过拟合。

## 工作流

1. 拆材料：找出用户真正想让 CFlow 学会的动作。
2. 分层吸收：区分文案结构模板和底层机制规则，不把两者混写。
3. 抽象机制：把领域、题材、人物、平台和素材来源替换成变量。
4. 判机制：判断它是否跨题材、跨任务成立。
5. 判写入层级和写入点：先确认应内化到哪个 skill 原则，还是只沉淀为内容资产。
6. 出计划：说明行为会怎么变，等用户批准。
7. 应用变更：修改文件并运行 `python scripts\quick_validate.py`。

## 可吸收机制

优先吸收这些：

- **判断规则**：以后遇到什么情况，先判断什么。
- **写法规则**：怎么开头、推进、收束、删减或改写。
- **质量规则**：什么算失败，命中后怎么修。
- **文案结构模板**：稳定的信息顺序、推进动作、承接位置或检查顺序。
- **底层机制规则**：信号、认知、人性、身份、权力、利益或情绪机制如何改变读者反应。
- **测试用例**：能复现高频失败的用户原话或输入形态。

不要直接吸收这些：

- 单篇素材里的事实、人物、产品、数字。
- 用户个人口癖、临时偏好或单次审美判断。
- 只有一个案例支撑、说不清机制的风格模仿。
- 只能当例子、不能改变默认行为的表达。

## 拆材料

先把材料拆成小块，不要整包写入。

每个候选机制只回答五个问题：

```text
它解决什么失败？
它改变哪个生产动作？
它是文案结构模板，还是底层机制规则？
如果是结构模板，它的信息顺序和推进动作是什么？
如果是底层机制，它向读者发出了什么信号？
它的底层规则是什么？
它应该写进哪个 skill？
它必须默认生效，还是只需要作为可选资产？
它是否需要测试用例？
```

如果回答不出来，不升级成长期规则。

## 对照纠偏吸收

当输入是外部模型回答、竞品分析、用户反驳或连续纠偏对话时，吸收对象不是对方答案全文，而是它暴露的能力缺口。

```text
外部答案补足了哪一层能力？
用户真正要求 CFlow 以后多做什么判断？
这是文案结构模板缺失，底层机制规则缺失，还是两者没有分层输出？
应该写入当前 skill，还是写入被纠偏的生产 skill？
```

如果用户拿外部答案指出“它看到了文案结构好”，不要只吸收外部答案的结论；要抽出可迁移的信息顺序、推进动作和输出字段。

如果用户指出“还要抽象底层机制、优化 skill 规则、信号理论”，不要只保留结构模板；要抽出信号、认知、人性、身份、权力、利益或情绪如何改变读者反应。

回归样例：

```text
我既需要 cflow-review 能看到文案结构好，也要能抽象底层机制，文案结构可以落成可复用的模板，底层机制可以优化 skill 的规则。
```

## 双层吸收

吸收优秀案例、样稿、方法论或用户纠偏时，先拆成两层。

```text
文案结构模板：材料里的有效信息顺序、段落推进、证据放置、情绪转折、承接动作。
底层机制规则：结构背后可迁移的人性、认知、信号、权力、身份、利益或情绪机制。
```

两层写入位置不同：

```text
文案结构模板 -> 写入负责生产该类内容的 skill，作为模板、检查顺序或输出字段。
底层机制规则 -> 写入负责判断该类问题的 skill，作为判断规则、质量门槛或反模式。
```

不要用机制抽象吞掉文案结构。用户指出“文案结构好、模板可复用”时，必须保留结构模板。

不要用结构模板替代底层机制。用户指出“这能优化 skill 规则、信号理论、人性机制”时，必须抽象机制。

## 原则优先

吸收时不要默认把经验写成 `profiles/content-assets/`。资产不是运行时默认能力，只有被读取时才生效。

```text
写入 skill 原则：这条经验会改变默认判断、工作流、质量门槛、输出字段、反模式或路由决策。
写入内容资产：这条经验主要是长模板、案例、触发词、适用条件、扩展检查清单或可选模式。
两者都需要：先把最小原则写进实际会被调用的 `SKILL.md`，再把长模板和样本写进资产。
```

如果用户说“让 skill 学会”“优化规则”“以后默认要会”，必须优先考虑写入对应 `skills/<name>/SKILL.md`，不能只沉淀资产。

高门槛证据大众传播类经验的最小原则是：

```text
单变量反转降低理解成本。
可信信号支撑离谱结论。
极端证据制造认知失衡。
既有情绪被证据释放。
本土或自我处境完成代入。
真实争议空间带来评论和二次传播。
```

## 反过拟合检查

写入规则或资产前，先把原材料里的表面元素替换成变量。

```text
领域：论文 / 金融 / AI / 平台 / 政策 / 历史 / 个人经历
对象：某作者 / 某公司 / 某产品 / 某市场 / 某账号
来源：论文 / 图表 / 截图 / 评论 / 数据 / 访谈 / 回测
动作：对比 / 前置 / 压缩 / 删除 / 转译 / 证明 / 命名
结果：停留 / 理解 / 相信 / 收藏 / 转发 / 关注 / 转化
信号：权威 / 稀缺信息 / 代价 / 身份 / 数据 / 视觉证据 / 第三方背书 / 群体共识
```

只有“动作 -> 结果”能跨变量成立，才写成通用规则。

如果是信号机制，还要确认“信号 -> 读者判断变化”成立：

```text
这个信号让读者更相信什么？
它改变了读者的身份感、风险感、利益判断还是行动理由？
去掉原领域后，同类信号是否仍能产生相似反应？
```

命名规则：

```text
优先用底层动作命名：高反差证据速译。
少用领域命名：论文速译、A 股模式、AI 新闻模板。
领域只写进 use_when / avoid_when，不写成机制本身。
```

## 写入标准

写入 `SKILL.md` 时只保留能改变行为的句子。

优先改现有规则：

1. 删除误导规则。
2. 合并重复规则。
3. 收紧过宽规则。
4. 补缺失判断。
5. 最后才新增小节。

模板必须是底层结构，不是固定文案。结构模板写信息顺序，机制规则写判断逻辑。

```text
好：事实 -> 差异 -> 动作
坏：最后加一句提醒 / 升华 / 这意味着
```

写入前先判定规则类型：

```text
如果它规定先讲什么、后讲什么、证据放哪里、在哪里转折 -> 文案结构模板。
如果它解释为什么读者会相信、代入、站队、转发或行动 -> 底层机制规则。
如果两者都成立，分成两条规则写入，不合并成一句泛化表述。
```

处理文风问题时，不要只写“去 AI 味”“不要套格式”。必须写清具体失败：

```text
具体失败是什么
为什么会导致失败
命中后怎么改
```

不要只列禁词，也不要依赖案例对照替代底层规则。

## 计划格式

编辑任何 skill 前，先给用户一个短计划。

```text
行为变化：
这次要写入什么机制：
可复用文案结构：
底层机制规则：
应内化 skill 原则：
只沉淀资产的部分：
涉及文件：
会删减 / 归类 / 收紧什么：
需要新增什么：
风险或不确定点：
确认后我会修改文件并跑校验。
```

计划必须具体到“下次同类任务会怎么不同”。如果说不清差异，说明还没有吸收到机制。

用户已经明确要求直接修改某个 skill 时，可以在该范围内执行。

## 应用变更

修改规则：

- 只改用户批准或明确指定的文件。
- 优先编辑 `skills/<name>/SKILL.md`。
- 不创建外部规则文件。
- 不把同一规则写到多个真源。
- 不保留旧规则的兼容说法。

修改后运行：

```powershell
python scripts\quick_validate.py
```

如果创建、删除或重命名 skill，再运行：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\sync_personal_skills.ps1 -PruneStale
python scripts\quick_validate.py
```
