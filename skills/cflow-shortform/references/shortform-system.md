# 短内容系统

## 短内容原则

- 一条只说一个点。
- 开头必须独立成立，不依赖标题、视觉资产或上下文。
- 先让读者知道“为什么现在要看”。
- 具体细节优先于抽象总结。
- 只保留能推进注意力、理解、情绪或行动的句子。
- 结尾不要强行升华，短内容可以停在判断、问题、行动或记忆点。
- 适合拆成系列时，不要硬塞进一条。
- 写给中文母语者时，自然和流畅优先。专业但不端着，少营销腔，少宏大词。
- 段落保持清爽。短内容里一段太长，通常就是没剪干净。
- 克制扩写冲动。能用一句说清，就不要铺三句。

## 常用结构

### 场景到判断

```text
具体场景
读者识别
判断
一句解释
结尾问题或行动
```

适合小红书、LinkedIn、朋友圈、短视频口播。

### 反常识到机制

```text
大家以为 X
但实际是 Y
为什么
一个例子
怎么用
```

适合观点短帖、X、LinkedIn、短视频。

### 问题到答案

```text
一个具体问题
直接答案
错误做法
正确做法
下一步
```

适合教学型短内容、私域、FAQ 式内容。

### 微故事到洞察

```text
一个短场景
转折
暴露的问题
洞察
可迁移一句话
```

适合有案例但篇幅不够展开时。

### 清单型

```text
对象或场景
3 到 7 个要点
使用条件
避坑提醒
```

适合小红书、LinkedIn、私域、图文。

### 对比型

```text
A 做法
B 做法
关键差异
适用场景
一句判断
```

适合解释误区、选择题、工具/方法比较。

### Thread 型

```text
第一条：主张 + 为什么值得看
中间：每条只推进一个子点
最后：总结、行动或资源
```

Thread 不是把长文切段。每条都要有推进功能。

## 平台差异

### 短视频

- 一句话一个拍点。
- 前三秒给场景、冲突或判断。
- 用口语，不写书面段落。
- 每 5 到 8 秒刷新一次信息：新细节、转折、例子、问题或画面。
- 结尾可以引导评论，但不要为了评论破坏主张。

### 小红书/RED

- 标题由 `$cflow-package` 处理，封面和配图由 `$cflow-image` 处理，正文要方便扫读。
- 读者处境要具体。
- 多用生活细节、步骤、清单、前后对比。
- 避免大而空的成长、效率、逆袭承诺。

### Twitter/X

- 单条要锋利，thread 要顺序推进。
- 不隐藏主题太久。
- 每条只承载一个判断或证据。
- 适合反常识、定义、对比、金句和短清单。

### LinkedIn

- 使用职业场景、决策张力、管理/团队/产品/行业语境。
- 克制表达，不要假脆弱。
- 用具体经历或判断建立可信度。

### 朋友圈 / 私域

- 更重关系感和真实近况。
- 不要像公域广告。
- 可以更短、更直接、更像人话。
- CTA 要低摩擦，适合引发私聊或回复。

## 长文拆短

长文拆短时，先找短内容单元：

- 一个强判断
- 一个具体场景
- 一个反常识
- 一个案例
- 一个清单
- 一个问题
- 一个对比
- 一个读者异议

每个单元单独成条。不要把长文摘要当短内容。

## 短内容质量检查

- 是否只有一个单点？
- 首句/前三秒是否独立成立？
- 有没有具体场景或细节？
- 是否删掉了长文式铺垫？
- 是否有自然停点？
- 是否适合目标平台？
- 是否保留作者声音？
- 是否需要交给 `$cflow-package` 做标题或 CTA？
- 是否需要交给 `$cflow-image` 做封面、插图或配图？

## 常见错误

- 把长文压缩成摘要。
- 一条里塞三个观点。
- 开头解释背景太久。
- 用标题承诺，正文不兑现。
- 为了短而删掉具体细节。
- 把所有平台都写成同一种社交帖。
- 用结尾升华替代清楚判断。
