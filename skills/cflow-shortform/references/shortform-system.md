# 短内容系统

## 共享合同

短内容受 `$cflow` 的 `references/content-production-contract.md` 约束。本文件只维护短帖、短视频、thread 和平台短格式的应用规则。

## 短内容原则

- 一条只说一个点。
- 开头必须独立成立，不依赖标题、视觉资产或上下文。
- 先让读者知道“为什么现在要看”。
- 开头弱时交给 `$cflow-package` 做 hook 机制检查，不要只把句子压短或改顺。
- 结尾不要强行升华，短内容可以停在判断、问题、行动或记忆点。
- 适合拆成系列时，不要硬塞进一条。
- 写给中文母语者时，先抓住注意力和行动欲。不要默认少营销腔；有转化目标时保留甚至强化有功能的销售语气。
- 段落保持清爽。短内容里一段太长，通常就是没剪干净。
- 短内容的呼吸感主要来自换行、短停顿、列表和自然停点。

## 常用结构

### 场景到判断

```text
具体场景
读者识别
判断
一句解释
结尾问题或行动
```

适合小红书、LinkedIn、朋友圈、短视频口播。

### 反常识到机制

```text
大家以为 X
但实际是 Y
为什么
一个例子
怎么用
```

适合观点短帖、X、LinkedIn、短视频。

### 问题到答案

```text
一个具体问题
直接答案
错误做法
正确做法
下一步
```

适合教学型短内容、私域、FAQ 式内容。

### 微故事到洞察

```text
一个短场景
转折
暴露的问题
洞察
可迁移一句话
```

适合有案例但篇幅不够展开时。

### 清单型

```text
对象或场景
3 到 7 个要点
使用条件
避坑提醒
```

适合小红书、LinkedIn、私域、图文。

### 渠道情报型

```text
截止时间
入口是什么
为什么稀缺
3 到 7 个强利益点
别人还在 X，你可以 Y
福利 / 邀请码 / 链接
直接操作
```

完整营销判断归 `$cflow-marketing`。短内容只负责把已确定的入口型转化压成短消息：短句、符号、列表、紧迫感和扫读冲击；不要改成产品说明。

### 对比型

```text
A 做法
B 做法
关键差异
适用场景
一句判断
```

适合解释误区、选择题、工具/方法比较。

### Thread 型

```text
第一条：主张 + 为什么值得看
中间：每条只推进一个子点
最后：总结、行动或资源
```

Thread 不是把长文切段。每条都要有推进功能。

## 平台差异

### 短视频

- 一句话一个拍点。
- 前三秒给场景、冲突或判断。
- 用口语，不写书面段落。
- 每 5 到 8 秒刷新一次信息：新细节、转折、例子、问题或画面。
- 结尾可以引导评论、私信或行动。默认优先完成内容目标。

### 小红书/RED

- 标题由 `$cflow-package` 处理，封面和配图由 `$cflow-image` 处理，正文要方便扫读。
- 读者处境要具体。
- 多用生活细节、步骤、清单、前后对比。
- 默认允许成长、效率、逆袭承诺，只要能制造点击或行动；用户要求严谨/品牌安全时再收窄。

### Twitter/X

- 单条要锋利，thread 要顺序推进。
- 不隐藏主题太久。
- 每条优先承载一个判断、情绪、利益或行动。
- 适合反常识、定义、对比、金句和短清单。

### LinkedIn

- 使用职业场景、决策张力、管理/团队/产品/行业语境。
- 克制只在用户要求职业可信度时使用。默认保留锋利判断和强立场。
- 用具体经历、判断或强表达建立停留和行动欲。

### 朋友圈 / 私域

- 私域可以重关系感，也可以重成交动作，按用户目标决定。
- 私域成交可以直接卖；如果用户要求关系感，再调整成真人对熟人说话。
- 可以更短、更直接、更像人话。
- CTA 要低摩擦，适合引发私聊或回复。

## 长文拆短

长文拆短时，先找短内容单元：

- 一个强判断
- 一个具体场景
- 一个反常识
- 一个案例
- 一个清单
- 一个问题
- 一个对比
- 一个读者异议

每个单元单独成条。不要把长文摘要当短内容。

## 源头资产降维分发

当输入是一篇 newsletter、blog、长视频稿、播客稿或深度文章时，先把它当作源头资产拆解，而不是平均切段。

常见分发映射：

- **Thread / LinkedIn 长帖**：提取主张链和小节推进，每条只推进一个子判断。
- **短帖 / X post / 朋友圈**：提取一个强判断、反常识、对比或金句，独立成立。
- **短视频脚本**：提取一个场景、冲突或问题，改成拍点和口语推进。
- **小红书图文**：提取步骤、清单、前后对比或读者处境，方便扫读和收藏。
- **金句图 / 社交配图**：提取可截图传播的一句话，交给 `$cflow-image` 设计视觉层级。

拆分纪律：

- 每条短内容都要有自己的首屏理由，不依赖读者看过原长文。
- 不把小节标题直接当 hook；先找读者损失、身份差距、具体结果或认知冲突。
- 同一个源头资产可以拆出多个单点，但每条都要换进入点，不要只是连续摘要。
- 高反馈短内容可以回流给 `$cflow-topic`、`$cflow-angle` 或 `$cflow-draft` 扩展成下一轮源头资产。

## 短内容验证长内容

短内容不只服务长文拆短，也可以反向验证选题、角度和表达单元。

适合先做短内容验证的情况：

- 用户有多个想法，但不知道哪个值得扩展成 newsletter、长文、视频或系列。
- 某个短判断、短故事、清单或反常识已经有互动、评论、收藏、转发或私信反馈。
- 用户想提高发布频率，同时保留后续扩展成长内容的可能。

验证规则：

- 高反馈单点可以交给 `$cflow-topic` 扩展成选题，交给 `$cflow-angle` 加压成主张，或交给 `$cflow-draft` 扩展成完整一稿。
- 低反馈不自动等于选题无效；先判断是包装、平台、发布时间、图像、目标读者还是正文单点的问题。
- 不要为了验证而把一条短内容塞满背景。验证的对象应该是一个清楚的单点、张力或读者反应。
- 同一核心内容可以生成多个短内容单元，但每条都必须独立成立，不能只是长文分段摘要。

## 短内容质量检查

- 是否只有一个单点？
- 首句/前三秒是否独立成立？
- 有没有具体场景或细节？
- 是否删掉了长文式铺垫？
- 是否有自然停点？
- 是否有呼吸感，而不是每句同一力度、同一密度？
- 是否适合目标平台？
- 用户要求 voice 时，是否保留作者声音？
- 是否需要交给 `$cflow-package` 做标题或 CTA？
- 是否需要交给 `$cflow-image` 做封面、插图或配图？

## 常见错误

- 把长文压缩成摘要。
- 一条里塞三个观点。
- 开头解释背景太久。
- 用户要求严谨包装时，用标题承诺但正文不兑现。
- 为了短而删掉具体细节。
- 把所有平台都写成同一种社交帖。
- 用结尾升华替代清楚判断。
