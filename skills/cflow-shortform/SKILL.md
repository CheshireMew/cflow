# CFlow Shortform

## 边界

负责短内容本体：一条短内容到底说什么、怎么推进、在哪里停。短内容不是长文缩短，而是单点内容、即时张力、短链路和短篇幅密度。

不要替代 `$cflow-package` 做普通标题、CTA 和发布包；不要替代 `$cflow-image` 做封面、插图或配图；不要替代 `$cflow-draft` 写完整长文或中篇；不要替代 `$cflow-viral` 设计完整传播机制；不要替代 `$cflow-marketing` 设计 offer 和转化路径。

短内容默认不克制。硬广、限时活动和成交型短内容可以保留强利益、强 urgency、强情绪和强 CTA；要删的是无功能铺垫。只有用户要求严谨、合规、发布限制或品牌安全时，才检查空泛营销腔和承诺边界。

默认直接基于用户素材写短内容。开始前检查 `profiles/content-assets/` 是否有匹配的短内容、短链路、首屏推进、传播单元或资源包装资产。也可以采用 `$cflow-review` 产出的短内容资产卡片，或 `$cflow-viral` 产出的分享动机、传播单元、截图点、复述句或二创模板；`$cflow-shortform` 只负责把这些机制压成短内容本体，不重新设计完整传播策略或复盘结论。只有用户要求核查、真实案例、来源或作者声音时，才交给 `$cflow-research`、`$cflow-case` 或 `$cflow-voice`。

## 工作流

1. **明确短内容任务**：超短、短内容、短篇幅脚本、短发布文案、短内容系列、长文拆短，还是把 review / viral 资产压成短内容。
2. **检查内容资产**：读取匹配的短内容资产、传播单元或可迁移模板。
3. **压成单点**：一条短内容只推进一个观点、一个场景、一个问题、一个判断或一个行动。
4. **选择开场方式**：场景、问题、反常识、判断、冲突、微故事、清单、对比或直接答案。
5. **设计推进链路**：首句抓住注意力，中段只保留能推进情绪、利益、转折或行动的句子，结尾形成记忆点、回应入口或下一步。
6. **匹配篇幅密度**：按超短、短内容或短系列决定段落密度、信息压缩和停顿位置；平台名只有在用户特意提及时才作为发布约束处理。
7. **检查短内容质量**：是否单点、是否首屏成立、是否有具体细节、是否足够强、是否没有硬塞长文逻辑。
8. **交接包装和图像**：需要标题、hook、CTA 或发布包时，交给 `$cflow-package`；需要封面、插图或配图时，交给 `$cflow-image`。

## 输出

单条短内容输出：

- 篇幅 / 交付形态
- 单点主张
- 开场方式
- 短内容正文或脚本
- 为什么这样写
- 可继续加压项
- 下一步包装建议

短内容系列输出：

- 系列主题
- 拆分逻辑
- 每条单点
- 推荐顺序
- 可复用结构
- 哪些内容适合另做一条

改写长文为短内容时输出：

- 原文可拆出的短内容单元
- 每条适合的篇幅或交付形态
- 每条核心张力
- 适合保留为长内容的部分
