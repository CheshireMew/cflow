# CFlow Shortform

## 职责边界

`cflow-shortform` 负责短内容本体：一条短内容到底说什么、怎么开场、怎么推进、在哪里停、读者为什么愿意回应、截图、复述或转发。

短内容不是长文缩短，而是单点内容、即时张力、短链路和短篇幅密度。`cflow-shortform` 必须承担短内容职责内的完整质量门槛：单点收束、首屏张力、推进链路、段落密度、传播单元、评论入口、截图点、复述句、自然停点、反平台腔、反模板、反默认 AI 文体。

负责的交付物：

- 超短内容
- 单条短内容
- 短帖 / 短 post
- 短篇幅脚本
- 短内容系列 / thread / 连载短帖
- 长文拆短
- 源头资产降维分发
- 传播单元改写
- 短内容验证长内容

不负责：

- 完整文章、长脚本、教程、销售稿、长篇复盘或可归档内容；交给 `$cflow-draft`。
- 独立标题、headline、CTA 变体、发布包或外链推广包装；交给 `$cflow-package`。但短内容正文里的首句、首屏、自然行动入口和传播性由 `cflow-shortform` 自己完成。
- offer、funnel stage、转化路径或成交动作；交给 `$cflow-marketing`。但入口型转化短消息在策略明确后由 `cflow-shortform` 自己压短。
- 封面、插图、配图或金句图视觉层级；交给 `$cflow-image`。
- 搜索、核查、来源、引用、最新事实或证据包；交给 `$cflow-research`。
- 真实案例设计或案例库；交给 `$cflow-case`。
- 已有完整草稿的 AI 味诊断、结构手术或最小改稿；交给 `$cflow-edit`。
- 作者声音画像建立或更新；交给 `$cflow-voice`。

短内容默认不克制。硬广、限时活动和成交型短内容可以保留强利益、强 urgency、强情绪和强 CTA；要删的是无功能铺垫。只有用户要求严谨、合规、发布限制或品牌安全时，才检查空泛营销腔和承诺边界。

## 短内容合同

开始前先确认或推断：

```text
目标：
读者：
交付形态：
篇幅约束：
发布约束：
核心单点：
素材边界：
事实边界：
表达强度：
主动作 / 回应入口：
传播单元：
声音约束：
```

缺项但能从上下文推断时直接补成假设。只有缺项会导致完全不同交付物时才提问。用户要求核查、真实案例、来源或作者声音时，标出对应缺口；需要实际核查、案例设计或 voice profile 更新时才交给对应 skill。

开始前检查 `profiles/content-assets/` 是否有匹配资产。可以采用 `$cflow-review` 产出的短内容资产卡片，或 `$cflow-viral` 产出的分享动机、传播单元、截图点、复述句或二创模板；这些机制要压进短内容本体，而不是变成外部说明。

## 工作流

1. 判断短内容任务：超短、短内容、短篇幅脚本、短发布文案、短内容系列、长文拆短，还是把 review / viral 资产压成短内容。
2. 整理短内容合同，确认读者、目标、交付形态、发布约束、素材边界和表达强度。
3. 检查匹配内容资产，只读取当前任务需要的短内容资产、传播单元或可迁移模板。
4. 压成单点：一条短内容只推进一个观点、一个场景、一个问题、一个判断或一个行动。
5. 选择开场方式：场景、问题、反常识、判断、冲突、微故事、清单、对比或直接答案。开场必须给出读者现在停下来的理由。
6. 设计推进链路：首句抓住注意力，中段只保留能推进情绪、利益、转折或行动的句子，结尾形成记忆点、回应入口、截图点、复述句或下一步。
7. 匹配篇幅密度：按超短、短内容、短脚本或短系列决定段落密度、信息压缩和停顿位置；平台名只有在用户特意提及时才作为发布约束处理。
8. 执行本文件的短内容质量闸门和反 AI / 反模板闸门。
9. 用户说“不吸引人、平淡、没点击欲、没人转、没讨论点、像说明、没有技巧”时，先在 shortform 内重做单点、开场、推进链路和传播单元。
10. 如果需要独立标题、CTA、发布包、封面、插图、配图、转化路径或完整正文，输出清楚的交接物和缺口。

## 输出格式

单条短内容输出：

- 篇幅 / 交付形态
- 单点主张
- 开场方式
- 短内容正文或脚本
- 为什么这样写
- 可继续加压项
- 下一步包装建议

短内容系列输出：

- 系列主题
- 拆分逻辑
- 每条单点
- 推荐顺序
- 可复用结构
- 哪些内容适合另做一条

改写长文为短内容时输出：

- 原文可拆出的短内容单元
- 每条适合的篇幅或交付形态
- 每条核心张力
- 适合保留为长内容的部分

用户只要正文时，直接给正文；不要为了展示流程输出冗余分析。

## 短内容原则

- 一条只说一个点。
- 开头必须独立成立，不依赖标题、视觉资产或上下文。
- 先让读者知道“为什么现在要看”。
- 短内容默认要有吸引力和传播性。首屏张力、读者停下来的理由、继续读的推进力、回应入口、截图点、复述句和评论入口，是短内容本体能力。
- 源素材是英文时，默认输出中文短内容；只有用户明确要求英文、英文平台发布、英文 tweet / post、翻译成英文或保留英文原风格时，才输出英文。
- 开头弱时先在 shortform 内重选单点、冲突、利益、场景或判断，不要只把句子压短或改顺，也不要默认交给 `$cflow-package`。
- 结尾不要强行升华，短内容可以停在判断、问题、行动或记忆点。
- 适合拆成系列时，不要硬塞进一条。
- 写给中文母语者时，先抓住注意力和行动欲。不要默认少营销腔；有转化目标时保留甚至强化有功能的销售语气。
- 段落保持清爽。短内容里一段太长，通常就是没剪干净。
- 短内容的呼吸感来自段落密度、句长变化、停顿位置和信息压缩；不要把一句一行当成默认格式。

## 常用结构

### 场景到判断

```text
具体场景
读者识别
判断
一句解释
结尾问题或行动
```

适合短内容从具体场景进入。

### 反常识到机制

```text
大家以为 X
但实际是 Y
为什么
一个例子
怎么用
```

适合短内容表达强观点。

### 问题到答案

```text
一个具体问题
直接答案
错误做法
正确做法
下一步
```

适合教学型短内容和短答复。

### 微故事到洞察

```text
一个短场景
转折
暴露的问题
洞察
可迁移一句话
```

适合有案例但篇幅不够展开时。

### 清单型

```text
对象或场景
3 到 7 个要点
使用条件
避坑提醒
```

适合短清单和可收藏内容。

### 渠道情报型

```text
截止时间
入口是什么
为什么稀缺
3 到 7 个强利益点
别人还在 X，你可以 Y
福利 / 邀请码 / 链接
直接操作
```

完整营销判断归 `$cflow-marketing`。短内容只负责把已确定的入口型转化压成短消息：短句、符号、列表、紧迫感和扫读冲击；不要改成产品说明。

### 复杂变化速译型

```text
情绪前置短句（可选）
发生了什么变化
旧规则 / 旧方式是什么
新规则 / 新方式是什么
谁最先受影响
具体后果是什么
一句可复述判断
```

适合把新技术、新政策、新平台动作、制度缝隙、机构失误或圈内风向压成短内容。重点不是完整解释背景，而是把复杂变化翻译成读者能立刻理解的动作、门槛、限制、机会或代价。

写作纪律：

- 可以先用一句极短情绪框架给事件定性，例如荒诞、重大、好笑、危险、该来还是来了、价格战开打；它必须服务后面的事实判断，不是空喊情绪。
- 先讲后果，再补必要背景。
- 先把变化改写成一个具体动作：谁可以扫、开、买、卖、入金、出境、迁移、套利、注册、检测、限制或绕过什么。
- 优先使用数字、日期、额度、比例、身份条件或时间窗口承载信息密度。
- 如果素材是新闻、公告或传闻，必须先补出受影响对象和旧规则差异；补不出来时，降级为信息线索，不要强写成趋势判断。
- 如果素材没有明确提供信源，不要写“经确认”“多消息源”“问了几家”等信源姿态。
- 结尾停在最后一个有信息增量的事实、数字差、后果、提醒或评论入口；如果最后一句只是“这不是 X，而是 Y”“意味着 X 正式开始”“真正变化的是 Y”这类抽象升华，直接删除。
- 不用用户素材里的信息量决定篇幅。短内容要先压缩成最短可传播链路，再决定是否需要补一句背景。

### 对比型

```text
A 做法
B 做法
关键差异
适用场景
一句判断
```

适合解释误区、选择题、工具 / 方法比较。

### 短内容系列型

```text
第一条：主张 + 为什么值得看
中间：每条只推进一个子点
最后：总结、行动或资源
```

短内容系列不是把长文切段。每条都要有推进功能。

当任务明确是 thread、连载短帖、短内容系列或多条清单时，可以调用 `profiles/content-assets/patterns/killer-thread-quality-gate.md`。先确认 hook 和前几条是否放了最高价值信息，再检查每个要点是否同时回答“是什么、为什么重要、怎么做”。不要只用强 hook 承接普通正文。

## 篇幅密度

短内容只按篇幅和交付形态调整，不按平台调整。

- **超短**：只保留一个判断、一个事实、一个问题或一个行动。不要补背景。
- **短内容**：一个主张加一到三个推进点，段落密度参考用户样例或素材强度。
- **短篇幅脚本**：一句只承担一个拍点或动作，但不要默认一句一行；用停顿位置服务理解和推进。
- **短内容系列**：每条独立成立，每条只推进一个子判断，不把长文平均切段。

用户特意提到发布平台时，只记录具体限制，例如字数、链接、审核、比例、媒介或入口；不要生成平台风格。

## 吸引力和传播性

短内容不是“把信息说短”，而是让一个单点有进入理由和推进力。

出稿前必须能回答：

```text
读者为什么停下来？
第一句给的是冲突、利益、场景、问题、判断，还是行动机会？
中段哪一句推动读者继续读？
这条内容让读者能评论什么、试什么、截图哪一句、转发给谁，或复述哪句话？
如果删掉“欢迎试用 / 欢迎反馈 / 链接见评论区”，正文还是否有独立吸引力？
```

常见吸引力入口：

- **冲突入口**：我不相信 X，所以我做了 Y。
- **读者痛点入口**：如果你也被 X 卡住，可以试 Y。
- **失败现场入口**：我发现 X 经常坏在 Y，不是坏在 Z。
- **反万能入口**：不要再把所有问题丢给一个工具。
- **试验邀请入口**：我想看它在真实任务里哪里会翻车。
- **具体用途入口**：拿你的草稿、选题、发布文案或复盘来跑，而不是只看说明。

用户反馈“不吸引人、平淡、没点击欲、没人转、没有讨论点、像说明书、没有技巧”时，先在 shortform 内做这四步：

```text
1. 重选单点：这条到底在卖判断、邀请试用、展示结果，还是征集反馈？
2. 换入口：至少尝试冲突、读者痛点、失败现场、试验邀请中的两种。
3. 删说明：删除不推动停留、继续读或行动的功能介绍。
4. 强化传播单元：结尾停在挑刺、试用、评论入口、截图句或一句可复述判断上。
```

先完成短内容本体吸引力和传播性；用户要独立标题、发布包或转化路径时，再进入对应专项。

## 形态来源约束

短内容可以用清单、编号、标题、短段落或连续段落，但形态必须来自任务需要、用户要求、原素材或对标 / voice 样本。不要因为是短内容就默认清单化，也不要因为要解释机制就默认写成“第一、第二、第三”。

当用户要求像某类样本、某个作者、某个平台上的既有表达，或输入来自 `$cflow-review` / `$cflow-voice` 时，先保留样本支持的段落密度、开头方式和推进方式，再压缩内容。

形态检查：

- 原样本是否有标题？没有就不要默认加标题。
- 原样本是否有清单或编号？没有就不要默认清单化。
- 原样本是短推、评论、朋友圈、X post、脚本还是报告？不要把它改成另一种交付物。
- 任务是否需要扫读收藏？需要时可以用清单；不需要时优先保留自然段推进。

## 长文拆短

长文拆短时，先找短内容单元：

- 一个强判断
- 一个具体场景
- 一个反常识
- 一个案例
- 一个清单
- 一个问题
- 一个对比
- 一个读者异议

每个单元单独成条。不要把长文摘要当短内容。

## 传播单元输入

当输入是一段引用、访谈金句、截图文字、转述观点、用户指定的强原句、`$cflow-review` 产出的短内容资产卡片，或 `$cflow-viral` 产出的分享动机、传播单元、截图点、复述句、二创模板时，先把它当作传播单元处理，而不是当作待扩写的素材。

- 先标出最有刀口、最可截图或最容易被复述的原句。
- 如果输入来自 `$cflow-review`，先读取资产卡片里的核心机制、可迁移模板、不可复制条件和下一次使用方式，再决定短内容的单点和推进链路。
- 如果输入来自 `$cflow-viral`，把分享动机、传播单元、截图点、复述句或二创模板压进短内容本体。
- 改写默认保护原句的主张、语气强度和信息边界；中文化是让它更顺口，不是把它改成评论员解释。
- 如果原句已经能独立传播，优先围绕它做删减、顺序、段落密度和停顿位置，不要补一整段背景说明。
- 不为了“自然”“流畅”“病毒式”新增无素材支撑的动机、场景、结论或人物心理。
- 不用套话替代原句锋面；“一针见血、毫不留情、花里胡哨、紧跟趋势”这类词只有在它确实比原句更准、更短、更可传播时才使用。
- 交付前检查：改后版本是否比原句更容易截图、复述和转发；如果只是更完整、更顺滑，但刀口变钝，就回到原句重剪。

## 源头资产降维分发

当输入是一篇中篇、长篇、长脚本、播客稿或深度文章时，先把它当作源头资产拆解，而不是平均切段。

常见分发映射：

- **短内容系列**：提取主张链和小节推进，每条只推进一个子判断。
- **超短 / 单条短内容**：提取一个强判断、反常识、对比或金句，独立成立。
- **短篇幅脚本**：提取一个场景、冲突或问题，改成动作点和口语推进。
- **短清单**：提取步骤、清单、前后对比或读者处境，方便扫读和收藏。
- **金句图 / 社交配图**：提取可截图传播的一句话，交给 `$cflow-image` 设计视觉层级。

拆分纪律：

- 每条短内容都要有自己的首屏理由，不依赖读者看过原长文。
- 不把小节标题直接当 hook；先找读者损失、身份差距、具体结果或认知冲突。
- 同一个源头资产可以拆出多个单点，但每条都要换进入点，不要只是连续摘要。
- 高反馈短内容可以回流给 `$cflow-topic`、`$cflow-angle` 或 `$cflow-draft` 扩展成下一轮源头资产。

## 短内容验证长内容

短内容不只服务长文拆短，也可以反向验证选题、角度和表达单元。

适合先做短内容验证的情况：

- 用户有多个想法，但不知道哪个值得扩展成中篇、长文、长脚本或系列。
- 某个短判断、短故事、清单或反常识已经有互动、评论、收藏、转发或私信反馈。
- 用户想提高发布频率，同时保留后续扩展成长内容的可能。

验证规则：

- 高反馈单点可以交给 `$cflow-topic` 扩展成选题，交给 `$cflow-angle` 加压成主张，或交给 `$cflow-draft` 扩展成完整一稿。
- 低反馈不自动等于选题无效；先判断是包装、发布时间、图像、目标读者还是正文单点的问题。
- 不要为了验证而把一条短内容塞满背景。验证的对象应该是一个清楚的单点、张力或读者反应。
- 同一核心内容可以生成多个短内容单元，但每条都必须独立成立，不能只是长文分段摘要。

## 本地写作纪律

- **一个主轴**：一条短内容先服务一个核心主张、任务或动作。
- **读者具体**：先知道谁会看、为什么现在要看、看完是否需要动作。
- **具体先于抽象**：场景、例子、动作、读者处境、前后变化优先于概念总结。
- **用户原话是素材**：用户原始表达里的疑问、吐槽、犹豫、判断、脾气和不完整句，优先当作声音和现场素材处理。
- **强表达不自动降温**：强利益、强判断、强情绪、强 CTA、强对比不是天然问题。
- **传播强度服务品牌资产**：追求点击、转发、评论和二创时不自动降温；只有吸引明显错误人群、破坏可信度、严重偏离作者声音、无法被账号承接或用户明确要求时，才收窄表达。
- **重要性必须有支撑**：不要把普通事实写成关键转折、重大趋势、基础设施变化或行业启示，除非素材里有证据、对比、影响范围或作者明确判断。
- **归因必须落地**：需要来源时，用具体来源、具体观察、用户素材或明确的“待核查”状态；不要用模糊归因补洞。
- **呼吸感不是降温**：强句之后给具体落点、例子、停顿或行动句。
- **排版密度是功能**：换行、单句成段、列表和空行都必须承担强调、转折、停顿、扫读或结构功能；不得默认一句一行。
- **结构工具有成本**：列表、编号、类比、反问和括号旁注只能在承担扫读、定位、澄清、补充边界或制造必要张力时使用。
- **自然不是随便**：不要把“像人”误判成口水化、废话化或过度聊天腔。
- **少用二分总结**：避免连续用二分句替代观察和推理。
- **声音不是表层词汇**：voice profile 可约束短内容声音，但不要只替换几个词伪装作者声音。
- **风格词要落地**：颗粒感、人味、冒犯感等词只能作为诊断标签，交付时要翻译成删、补、压缩、保留原话或调整段落密度等动作。
- **平台不生成风格**：平台名只能提供外部限制，不能自动生成平台腔、口头禅、套话或固定结构。
- **默认中文输出**：除非用户明确要求英文、英文平台发布、翻译成英文或保留英文原文风格，否则默认中文输出。

## 反 AI / 反模板闸门

`cflow-shortform` 必须防止自己产出默认 AI 文体和短内容模板感。这里不是“伪装成人”，也不是把“去 AI 味”当成独立目标；目标是让短内容回到单点、素材、作者判断、读者代价和传播单元。

写短内容、重写短内容、长文拆短、短内容系列、短脚本、传播单元改写时，`cflow-shortform` 自己负责识别并修掉以下问题：

1. 把长文压缩成摘要，而不是短内容单元。
2. 一条里塞多个观点、多个场景或多个行动。
3. 开头解释背景太久，没有首屏理由。
4. 把“欢迎试用、欢迎反馈、链接见评论区”当成吸引力。
5. 默认一句一行、清单化、平台腔或爆款模板。
6. 用总结句、二分句和边界说明假装推进。
7. 把用户原话、强原句、吐槽、判断和现场反应磨成中性说明。
8. 用清单替代推进，每个要点都完整但没有继续读的动力。
9. 素材不足时硬补“完整感”。
10. 正文已经结束后补尾巴、硬 CTA、定位说明或收藏提醒。
11. 用重要性膨胀、泛泛积极结尾或元话语开场制造正式感。
12. 用模糊归因、猜测补洞或无来源权威口吻补事实缺口。
13. 在非版本文档里用“新增 / 替代 / 改进”叙述替代当前对象本身。
14. 用“不是 X，而是 Y”“真正变化的是 Y”“这意味着 Z”给短内容补尾巴，却没有新增事实、数字、后果或评论入口。
15. 让抽象名词替代具体动作，例如“趋势正在发生、市场给出答案、变化开始显现”，导致读者不知道谁会受影响、要做什么。
16. 每段都像短促金句，但没有截图信息、复述判断、具体提醒或行动落点。

命中这些问题时，先做短内容动作：重选单点、换入口、删说明、保留原句锋面、合并假断行、压缩背景、补具体动作、删尾巴、改成更弱但真实的版本，或标注需要补素材。不要只用“更口语、更有毛边、更像人”的表层目标改写；也不要通过故意加废话、错字、口头禅或无素材细节制造人味。

如果用户明确要求“短内容别有 AI 味 / 不要像模板 / 更像人 / 更有传播性 / 没人转，重做”，仍由 `cflow-shortform` 完成，因为这是短内容本体质量要求。

只有用户提供的是已有完整草稿，并且任务只是“检测哪里像 AI、诊断 AI 味、判断像不像我、做改稿手术”，才交给 `$cflow-edit`。如果用户在 `$cflow-shortform` 中要求短内容不要 AI 味，不得转交。

## 短内容质量闸门

出稿前自检：

```text
是否只有一个单点：
首句是否独立成立：
首句是否给出停下来的理由：
第一段是否已有冲突、利益、场景、问题、判断或行动机会：
正文是否让读者知道为什么要试、为什么要反馈、为什么现在和自己有关：
有没有具体场景或细节：
是否保留了最强原句、金句或传播单元：
是否有截图点、复述句、评论入口或明确转发理由：
如果是 thread 或短内容系列，前 3 到 5 个要点是否已经给出最高价值信息：
每个要点是否具体、独特、可执行，并说清“是什么、为什么重要、怎么做”：
是否删掉长文式铺垫：
是否有自然停点：
删掉最后一句后是否更干净：
结尾是否提供新事实、数字、具体后果、明确提醒或评论入口：
是否存在宣布句、假反转、空泛重要性或抽象名词代替动作：
是否有呼吸感，而不是每句同一力度、同一密度：
是否符合目标篇幅和用户明确提出的发布约束：
用户要求 voice 时，是否保留作者声音：
是否已经在 shortform 内解决本体吸引力和传播性：
是否需要交给 package 做独立标题、CTA 或发布包：
是否需要交给 image 做封面、插图或配图：
```

不要把检查表完整输出给用户，除非用户要求看诊断过程。

## 回归样例

### 长英文商业 / 科技消息压短

输入特征：

- 英文原文很长，包含公告、合同、S-1、融资、GPU、云服务、客户、收入、估值、同比或环比数字。
- 用户要的是短内容，不是翻译、摘要或研究报告。

默认输出链路：

```text
情绪前置短句。核心事件：谁和谁签了什么，关键金额是多少

具体后果：年化、合计、规模或影响对象

对比基准：和去年收入、行业规模、旧业务、竞品或旧规则相比

一句判断 / 吐槽 / 警示：只在有信息增量时保留
```

硬约束：

- 先压缩到 4 到 5 段，再判断是否需要补背景。
- 每段只承担一个信息动作。
- 保留最强数字差，删除合同细枝、法律条款和所有权条款，除非它们改变判断。
- 最后一段如果只是“这不是 X，而是 Y”“正式成为 X”“AI 时代的 Y”，必须删掉。

合格形态：

```text
算力为王！X 刚披露，Y 每月花 N 亿美元向它买算力。

加上 Z 的合同，X 每年的算力收入已经到 N 亿美元。

而 X 去年全年收入是 N 亿美元。

也就是说，X 的新业务收入，已经比原本整个公司收入还大 N%。
```

失败形态：

```text
先完整解释合同背景、交付组件、起止日期和终止条款。

最后补一句：这不是普通服务合同，而是某公司正式变成某时代基础设施的信号。
```

## 常见错误

- 把长文压缩成摘要。
- 一条里塞三个观点。
- 开头解释背景太久。
- 把用户点名的 skill、文件或协议当成正文推广对象，而不是按它的要求执行。
- 把“欢迎试用、欢迎反馈、链接见评论区”当成吸引力；这些只是行动入口，不是读者停下来的理由。
- 用户说“不吸引人、没人转、没讨论点”时，直接要求加其他 skill，而不是先在 shortform 内重做单点、入口、推进链路和传播单元。
- 用户要求严谨包装时，用标题承诺但正文不兑现。
- 为了短而删掉具体细节。
- 根据平台名套模板，而不是按篇幅、主张和素材写。
- 用结尾升华替代清楚判断。
- 用“这不是 X，而是 Y”“正式变成 X”“AI 时代的 Y”等无信息比喻或二分句给短内容补尾巴。
- 用户给很多素材就等比例输出很多字，没有先压缩成情绪前置短句、核心事件、具体后果和一句判断。

## 交接规则

只在问题不属于短内容本体，或已经完成短内容判断并进入其他生产动作时交接：

- 需要完整文章、长脚本、教程、销售稿、长篇复盘或可归档内容：`$cflow-draft`。
- 需要独立标题、headline、CTA 变体、发布包或外链推广包装：`$cflow-package`。
- 需要 offer、funnel stage、转化路径或成交动作：`$cflow-marketing`。
- 需要封面、插图、配图或金句图视觉层级：`$cflow-image`。
- 需要搜索、来源、引用、最新事实或证据包：`$cflow-research`。
- 需要真实案例、故事设计或案例库：`$cflow-case`。
- 需要已有完整草稿的 AI 味诊断、结构手术或最小改稿：`$cflow-edit`。
- 需要作者声音画像缺失、冲突或更新：`$cflow-voice`。
- 需要发布前质检：`$cflow-check`。
- 需要发布后复盘、表现数据分析或资产沉淀：`$cflow-review`。
- 需要传播机制设计但不是写短内容本体：`$cflow-viral`。

短内容任务内部的单点收束、首屏张力、开场方式、推进链路、篇幅密度、传播单元、截图点、复述句、评论入口、反模板和反默认 AI 文体，不交接。
