# CFlow Shortform

## 工作目标

把输入压成一条清楚、短、有人愿意看的单点短文案。

这里的短文案不是广告文案，而是一条短帖、短新闻、短观点或短建议。

默认中文输出。英文素材先中文化，不做逐句翻译。

短文案优先级固定为：第一，不要 AI 味；第二，使用清楚的短文案模板；第三，提高传播度。模板只能组织事实、判断、动作和差异，不能变成固定腔调；传播点必须来自素材里的反差、利益、代价、情绪或可复述判断。

## 维护约束

- 正文不重复 description 已经说清的范围。
- 范围固定为超短文案和单条短文案。
- 本文只保留短文案生成规则和质量检查。
- 模板字段必须是信息单元：事实、判断、对象、数字、动作、差异。
- 反 AI 味只写底层问题和改法，避免容易过拟合的正反案例。

## 工作流

1. 判断用户要的是 **超短文案** 还是 **短文案**，再判断内容类型。
2. 选择开头 hook：情绪前置、反常识、好奇心缺口、直接事实、问题切入。
3. 检查是否吸引观众：第一句有没有停下来的理由，中段有没有继续看的理由。
4. 检查是否有 AI 味：删掉元话语、模板腔、假升华和无素材支撑的判断。
5. 检查传播度：是否有可截图、可复述、可评论或可保存的单点；没有就换单点或缩短，不硬加爆款腔。

## 篇幅

### 超短文案

只保留一个事实、判断、问题或动作。不要补背景。

### 短文案

一个单点加一到三个推进句。每段只承担一个信息动作。

## 内容类型

### 短新闻 / 关键信息提取

适合新闻、访谈、转录、公告、产品变化、技术变化。

```text
谁说了什么 / 发生了什么
具体开放、改变、推出或限制了什么
包括哪些关键对象、数字、条件或例子
如果有对比，只写具体差异
```

硬规则：

- 先提取事实链，不先写作者感想。
- 不用元话语替读者宣布重点。
- 不强补“谁最先受影响”“具体后果”“行业意义”，除非素材明确支持。
- 不用“不是 X，而是 Y”做抽象升华。
- 最后一段如果只是提醒、升华、额外说明或作者感想，删除。

### 观点判断

适合用户已经给出判断、态度或评论。

```text
判断
支撑判断的事实、原句或观察
具体差异或例子
```

### 方法建议

适合回答“怎么做”“怎么选”“哪里错了”。

```text
具体问题
直接答案
错误点
正确做法
```

### 清单

只在用户要扫读、收藏或要点整理时使用。

```text
对象或场景
3 到 5 个要点
```

## Hook 选择

- **情绪前置**：素材本身有明显反差、荒诞、惊讶、危险、利好或紧迫感。
- **反常识**：读者通常以为 X，但素材显示 Y。
- **好奇心缺口**：先给结果或异常，再解释原因。
- **直接事实**：信息本身足够强，直接说人名、动作、数字或变化。
- **问题切入**：用户要教学、建议、诊断或判断。

开头必须像正文的一部分，不要像分析说明。

## 吸引力检查

出稿前问四个问题：

```text
第一句有没有让目标读者停下来的理由？
中段有没有新的事实、反差、利益、代价或动作？
删掉最后一句后是否更干净？
信息最强的一句是否已经放到前面？
```

如果不吸引，按顺序改：

1. 换单点。
2. 换 hook。
3. 删背景。
4. 补具体事实、动作、数字或原句。

## AI 味检查

AI 味通常不是某个词的问题，而是内容没有回到素材本身。

先查四件事：

```text
有没有把事实提取写成观点解释？
有没有用总结句替代具体信息？
有没有为了完整硬补背景、影响对象或行业意义？
有没有把用户原话、强判断或现场感磨成中性说明？
```

命中后按顺序改：

1. 删掉开头的分析说明，直接进入事实、判断或动作。
2. 删掉没有信息增量的结尾升华。
3. 把抽象词换成素材里的具体名词、数字、动作或原句。
4. 合并假断行，不要默认一句一行。
5. 如果素材不足，就写短一点，不要补完整感。

元话语的底层问题：

```text
替读者宣布重点，而不是直接给重点。
用“也就是说 / 一句话”制造总结感，但后面没有新信息。
用“不是 X，而是 Y”制造假反转，但只是换个抽象说法。
用“意味着 / 正式开始 / 重新定义”制造重要性，但没有事实支撑。
用“最聪明 / 真正变化 / 底层逻辑”替代具体动作、对象、数字和边界。
```

替换模板：

```text
“这段话最值得看的是 X” -> 直接写 X。
“这次真正的重点是 X” -> 直接写发生了什么变化。
“一句话 / 也就是说 X” -> 如果 X 没有新信息，删除；如果有新信息，改成事实句。
“不是 X，而是 Y” -> 改成 X 和 Y 的具体差异。
“这意味着 X 正式开始” -> 改成谁接下来能做什么、不能做什么、成本变了什么。
“最聪明的地方在于 X” -> 改成具体设计、动作或选择。
```

判断标准：删掉这句话后，如果信息没有减少，它就是 AI 味。

常见问题：

- 把信息提取写成观点解释。
- 把模板字段写进正文。
- 为了完整而硬补背景、影响对象或行业意义。
- 每句都像金句，但没有事实增量。
- 默认一句一行、默认清单化、默认平台腔。
- 把用户原话磨成中性说明。

## 输出

用户只要正文时，直接给正文。

需要说明时，最多给：

```text
形态：
类型：
正文：
```
