# CFlow Angle

## 边界

`cflow-angle` 负责把话题压成“为什么读者要看”的主张、张力和 premise。角度要比话题更具体，也要比标题更结构化。

角度不是标题、选题池、完整草稿、包装资产或事实研究。标题、hook 和开头交给 `$cflow-package`；完整成稿交给 `$cflow-draft`；短内容交给 `$cflow-shortform`；事实核查和外部资料交给 `$cflow-research`；案例故事交给 `$cflow-case`。

如果用户还没有稳定话题、素材、读者或创作目标，先补齐会影响角度判断的缺口。选题对象不清时，先把内容对象钉住；如果需要生成或评估选题，交给 `$cflow-topic`。

当输入来自项目方、品牌方、sponsor brief 或产品资料时，先把项目方素材翻译成作者角度：作者想让读者记住什么判断、读者原本误解或忽略了什么、这个项目只是证明该判断的例子还是文章主角。

## 工作流

1. 用一句具体话重述话题，钉住内容对象。
2. 判断目标读者、内容任务和发布形态；缺项能推断就先作为假设，不连续追问。
3. 检查话题里是否有空转概念；无法落到具体场景、冲突或结果的词不要直接进入角度。
4. 找到读者正在经历的张力：困惑、代价、决策、恐惧、欲望、错误、误解或未被说清的经验。
5. 用矛盾、代价、转变、区分、场景、决策、机制、open loop 等模式生成候选角度。
6. 项目 brief 类输入至少比较“项目介绍角度”和“作者判断角度”，默认优先后者，除非用户明确要通稿或说明文。
7. 默认不因为表达强、冲突大或商业意图明显淘汰角度；先找最有张力、最敢说、最能让读者停下来的角度。
8. 根据读者张力、素材支撑、表达强度、payoff、可信度和篇幅适配选择最强角度。
9. 输出可直接交给成稿、标题、hook、案例或营销 skill 的角度交接。

## 诊断入口

先判断用户给来的是什么，不要默认把所有输入都当成“帮我想标题”。

| 输入 | 主问题 |
|---|---|
| 只有一个话题 | 这个话题缺什么读者张力或核心主张 |
| 选题已经明确 | 哪个角度最能让读者停下来并继续看 |
| 一堆素材、笔记或经历 | 哪个素材能放大成主张、冲突或转变 |
| 项目方、品牌方或产品资料 | 如何把资料翻译成作者判断，而不是通稿介绍 |
| 已有草稿但主张弱 | 主线问题是角度不清、读者张力弱，还是素材不足 |
| 多个候选 angle | 哪个最有张力、最能兑现、最适合后续交付物 |
| 想做营销或转化内容 | 读者欲望和异议是否先于解决方案建立 |

用户只说“这个选题怎么写”“帮我找角度”时，先给候选角度和判断依据，不要把流程卡死在追问里；但必须标出关键假设。

## 角度任务

同一个话题可以服务不同内容任务。选择角度前先判断当前主任务：

- **解释**：让读者理解一个概念、机制、误区或过程。
- **说服**：改变读者判断，处理异议或建立新信念。
- **教程**：把问题压成可执行路径、步骤或避坑逻辑。
- **转化**：建立欲望、信任和行动理由。
- **包装**：制造点击、停留、阅读入口或行动压力。
- **传播**：制造截图、复述、转发、评论或二创入口。
- **内容品牌**：让读者记住作者的判断、方法、栏目承诺、人格气质或可信度。
- **搜索**：匹配搜索意图，让内容可发现、可引用。
- **案例**：让抽象主张落到场景、故事或证明动作。

一个角度可以兼顾多个任务，但必须有一个主任务。副任务只能服务主任务，不能抢主线。

## 强角度类型

- **矛盾**：大家以为是 X，但实践中是 Y。
- **代价**：一个没被注意到的错误正在消耗时间、信任、金钱或注意力。
- **转变**：通过具体机制从 A 到 B。
- **区分**：两个相似东西会产生不同结果。
- **场景**：一个具体时刻揭示更大的模式。
- **决策**：面对取舍，选择这个，避开那个。
- **机制**：它有效是因为背后有一个隐藏过程。
- **Open loop**：一个意外开局让读者必须继续看才能得到解答。
- **失败解决方案**：读者试过一个合理办法，但因为缺少隐藏条件而失败。
- **Framebreak**：例子打破了读者对成功、专业或规模的想象。

## 角度作为创意变量

同一个主题可以因为 angle 不同而变成完全不同的内容。追求高传播创意时，先把主题、hook、angle 和可信度分开判断；不要把一个强 hook 误当成强角度，也不要把一个热门主题直接写成内容。

常见可测试 angle：

- 错误：目标读者反复犯什么错？
- 框架：能否把复杂问题压成可复述结构？
- 清单：读者是否需要可收藏、可执行或可筛选的列表？
- 短句 / 金句：是否适合用高密度判断连续推进？
- 发现：作者研究、实践或观察后发现了什么？
- 心理模型：这个主题背后有什么可迁移的判断模型？
- 人物 / 权威：是否能用真实相关的人物、专家或案例增加可信度？

选择 angle 时检查：

```text
同一主题下这个 angle 是否最有读者张力：
这个 angle 是否能被用户素材支撑：
它和 hook 是否互相兑现：
它是否提供真实 payoff，而不只是换包装：
可信度来自作者、案例、数据还是需要核验的外部人物：
```

## 选择标准

选择同时具备这些条件的角度：

- 具体读者。
- 可见问题。
- 清晰主张。
- 用户素材里可放大的信息。
- 自然延伸出的结构。
- 足够的篇幅张力。
- 好奇心足够强。
- 有数据、故事、例子、经历或强判断组成的推进路径。
- 需要案例时，可以被 `$cflow-case` 支撑。
- 需要事实或来源时，可以被 `$cflow-research` 核验。

## 角度清晰度检查

强角度优先回答：

- 现象：读者看得见的素材是什么？
- 冲突：它和什么预期相反？
- 机制：为什么会这样？
- 力度：这句话为什么值得停下来？
- Payoff：读者继续看之后会得到什么？

如果只剩“这是一个重要问题”“这很有价值”“大家都应该知道”，说明角度还在空转。

找角度时先列出目标读者、同行或热点评论里第一反应会写的解释，并主动淘汰这些显而易见角度。更强的角度通常让熟悉信息产生新感知：情理之中，但预料之外。

反差必须由素材、机制、场景或读者代价支撑，并在正文里兑现 payoff；不要为了陌生而制造空反常识。

## 素材和事实边界

Angle 可以放大用户素材里的张力、冲突、欲望和判断，但不能新增未被素材支撑的事实、功能、服务、承诺、运营范围或案例结果。

如果 angle 依赖专家、名人、书籍、研究、行业数据、具体外部事实或当前平台趋势，且用户没有提供可用素材，先标注需要 `$cflow-research` 或 `$cflow-case`，不要为了增强可信度直接编进角度。

强表达不自动降温。只有用户要求严谨、核查、合规、品牌安全或发布限制时，才收窄承诺和表达，并标注事实状态。

## 淘汰规则

淘汰这些角度：

- 只是话题标签。
- 没有任何张力或行动理由。
- 听起来像泛泛建议。
- 无法被用户素材支撑。
- 需要换成另一个目标读者。
- 其实是标题，不是论点。
- 制造好奇但没有真实 payoff。
- 在建立欲望或读者张力前就推产品。
- 把“个人 IP、影响力、长期主义、深度内容”这类标签当作主张。

## 欲望和异议角度

当内容有说服、销售或转化目标时：

- 先建立读者欲望，再展示解决方案。
- 点名读者心里已经有的异议。
- 用故事、场景、强判断或具体个人细节处理异议。
- 优先说“发生了什么”，少用抽象保证。
- 如果用户要求严谨、核查或来源，再标注事实状态；默认先服务角度强度。

## 协作路由

`cflow-angle` 只负责角度判断和交接。需要继续执行时交给对应 skill：

| 发现 | 交给 |
|---|---|
| 话题、读者或创作目标还不清 | `$cflow-interview` |
| 需要生成或筛选选题 | `$cflow-topic` |
| 需要查资料、数据、来源、当前事实或专家信息 | `$cflow-research` |
| 需要案例、故事、类比或反面例子支撑 | `$cflow-case` |
| 需要写完整文章、教程、脚本或销售稿 | `$cflow-draft` |
| 需要写短内容、短脚本或拆成短内容系列 | `$cflow-shortform` |
| 需要标题、hook、opening、CTA 或发布包装 | `$cflow-package` |
| 需要判断 offer、欲望、异议和转化路径 | `$cflow-marketing` |
| 需要分享动机、截图点、传播单元或二创入口 | `$cflow-viral` |
| 需要判断账号承接、栏目或复访理由 | `$cflow-account` |
| 需要复盘已发布内容的有效角度 | `$cflow-review` |

```text

内容任务：

为什么这个角度有效：

最佳结构：
包装方向：
需要补证据或案例的部分：
被淘汰的弱角度：

```

角度还不成立时先输出：

```text
话题：
卡住的词或假设：
缺失的冲突：
缺失的读者处境：
缺失的素材或证据：
可以继续加压的素材或案例：
最小修法：
建议交给其他 CFlow skill：
```
