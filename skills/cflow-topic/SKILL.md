# CFlow Topic

## 职责边界

`cflow-topic` 负责选题发现、选题评估、选题池和栏目选题组织。

选题是创作者可以围绕它做内容的具体对象。它还不是主张、hook、标题、结构或正文。`cflow-topic` 必须承担选题职责内的完整判断：题是否具体、是否有读者处境、是否值得做、为什么泛、缺什么素材、能不能进入选题池、适合哪个栏目、下一步该补什么。

负责：

- 从业务背景、读者痛点、个人经历、笔记、转录、研究材料或创作者目标中发现具体选题。
- 把模糊方向、内容支柱、账号定位、评论反馈或创作者愿望转成可做选题。
- 判断一个题值不值得做、哪里弱、怎么补强。
- 建立选题池、栏目选题和下一篇候选。
- 识别复杂变化、新政策、新平台动作、门槛变化和行业迁移里的具体选题。
- 用读者痛点、具体性、表达潜力、新鲜度、生产成本、素材可放大性、案例潜力和目标读者强度评估候选题。

不负责：

- 把选题加压成明确主张、冲突、读者张力或 angle；交给 `$cflow-angle`。
- 写完整文章、脚本、教程、销售稿或长篇复盘；交给 `$cflow-draft`。
- 写标题、hook、opening、CTA 或发布包；交给 `$cflow-package`。
- 写短内容、短脚本或短内容系列；交给 `$cflow-shortform`。
- 搜索、核查、来源、引用、最新事实或实时主题有效性；交给 `$cflow-research`。
- 设计案例故事、假设故事、类比故事或案例库；交给 `$cflow-case`。
- 决定 offer、funnel stage、转化路径或主 CTA；交给 `$cflow-marketing`。
- 复盘已发布内容表现、评论反馈和资产沉淀；交给 `$cflow-review`。

选题本身的泛、弱、空转、缺读者、缺素材、缺反馈、只是标题、只是角度、只是愿望标签，由 `cflow-topic` 自己判断和处理。只有进入非选题生产动作时才交接。

## 选题合同

开始前先确认或推断：

```text
创作者领域：
目标读者：
发布目标：
内容栏目 / 支柱：
已有素材：
读者问题：
业务目标：
发布环境：
时效或窗口：
反馈信号：
约束：
```

缺项但能继续判断时，直接补成假设或标为缺口。只有缺项会导致完全不同选题方向时才提问。如果用户还没有可用素材、目标读者、创作目标或真实问题，先补齐会影响选题判断的缺口。

## 工作流

1. 明确创作者领域、目标读者和发布目标。
2. 钉住可观察现象：读者正在经历什么、哪里和预期不一致、有什么行为或反馈信号。
3. 过滤空转词：把“有价值、影响力、个人 IP、深度、成长、系统性”等词替换成具体对象、场景或结果。
4. 从上下文中抽取选题原料：问题、决策、失败、例子、异议、反复解释的概念、窗口变化、评论反馈或个人经历。
5. 按内容栏目、内容支柱、读者任务或内容资产类型分组选题。
6. 用读者痛点、具体性、表达潜力、新鲜度、生产成本、素材可放大性、案例潜力和目标读者强度评估候选题。
7. 判断题是否只是标题、角度、愿望、标签、热点线索或素材方向；不够具体时先修成半成品选题。
8. 选出最强选题，并说明为什么值得做、缺什么素材、下一步怎么加压。
9. 当用户需要更锋利的观点时，交给 `$cflow-angle`；当用户要成稿、短内容、包装或研究时，再交给对应 skill。

## 输出格式

生成选题时输出：

- 内容栏目
- 选题
- 目标读者
- 读者问题
- 为什么现在值得做
- 所需素材
- 可继续加压的方向
- 下一步

评估选题时输出：

- 判断
- 最适合的用法
- 当前不够强的地方
- 修法
- 推荐角度方向

模糊输入时先输出：

- 当前清晰度：低 / 中 / 高
- 最大缺口
- 半成品选题
- 需要补的 1 到 3 个关键信息

选题池输出：

```text
栏目：
读者：
选题：
读者处境：
为什么值得写：
可放大素材：
可能角度：
生产难度：
张力路径：
目标读者 hook：
```

## 选题来源

- 客户或读者反复问的问题。
- 读者持续付出代价的错误。
- 有明显取舍的个人决策。
- 幕后流程。
- 来自真实工作的反常识经验。
- 行业内被误用的概念。
- 前后对比式转变。
- 失败尝试和它暴露的问题。
- 创作者真实使用的清单。
- 相似选择之间的比较。
- 打破读者想象的幕后场景。
- 来自优秀广告、脚本、杂志、故事、喜剧或其他领域的 swipe-file 模式。
- 可以在标题中直接点名的受众身份。
- 读者已经尝试过但失败的解决方案。
- 读者在相信、购买或行动前反复提出的异议。
- 可被 `$cflow-case` 扩展成案例故事的真实事件、微场景或未来预演。
- 创作者正在解决的真实问题，以及已经走过一两步的路径。
- 创作者明确不想回到的状态、错误生活方式或反愿景。
- 创作者当前最优先研究、实践、购买、放弃或反复解释的事。
- 创作者独特经历、技能、价值判断和兴趣交叉产生的具体问题。
- 新技术、新政策、新平台动作、制度缝隙、监管限制、资格门槛、费率变化、身份条件或交易路径变化。
- 高地位机构、专业系统或巨头公司出现低级错误、荒诞操作或反常行为，并暴露出可解释的行业机制。
- 圈内资金、人才、产品、入口、流量或中介层正在迁移，且能说清谁被替代、谁受益、谁付出新代价。

个人品牌选题不是“写我自己”。它要把创作者的路径翻译成读者也在付出代价的问题：我经历过什么、解决了什么、现在优先什么，最终都要落到读者处境、决策、痛点或行动上。

## 内容支柱转选题

内容支柱用于组织选题池，不是用来束缚表达。把账号支柱转成选题时，每个支柱都要落到可重复的读者任务、痛点、异议、案例来源或作者判断；如果某个支柱只能说明“我感兴趣”，但不能产生读者处境和可放大素材，先降级为素材方向，不升级成稳定栏目。

检查：

```text
支柱对应的目标读者是谁：
读者为什么持续需要这个支柱：
这个支柱能否产生多个具体问题：
这个支柱能否承接爆款带来的新注意力：
这个支柱和其他支柱是否吸引同一批人：
```

## 复杂变化类选题

复杂变化类选题不要停在“发生了什么”。它必须至少说清一个后果：旧规则被什么新规则替代、哪类人最先受影响、具体门槛是什么、读者需要做什么判断。

适用来源：

- 新技术。
- 新政策。
- 新平台动作。
- 制度缝隙。
- 监管限制。
- 资格门槛。
- 费率变化。
- 身份条件。
- 交易路径变化。
- 高地位机构、专业系统或巨头公司出现低级错误、荒诞操作或反常行为。
- 圈内资金、人才、产品、入口、流量或中介层迁移。

说不清后果时，先作为资料线索，不升级成正式选题。用户要求当前事实、最新进展或实时表现时，交给 `$cflow-research`。

## 评分

每个维度 1 到 5 分。默认不展示完整评分表，除非用户要求比较多个选题。

- **读者痛点**：是否解决或命名了真实问题？
- **具体性**：读者能不能想象这个处境？
- **表达潜力**：这个题能不能写出强判断、强利益或强冲突？
- **新鲜度**：是否有非显而易见的区分或例子？
- **生产成本**：现有素材能不能支撑？
- **素材可放大性**：是否有具体场景、指标、前后对比、截图、轶事或强观点可放大？
- **案例潜力**：是否能找到真实、假设、类比或未来预演案例来支撑？
- **目标读者强度**：是否能对窄读者说得足够具体，让无关读者自动离开？

优先选择高痛点、高张力、高转化或高传播潜力的题。流行本身可以成为理由，只要能写出强进入点。

## 选题杠杆

选题杠杆通常比表达技巧更先决定内容上限。好选题不只是“能写”，而是天然带着读者停留、继续看、收藏、转发或行动的理由。

判断时检查：

- 是否命中读者正在付出代价的问题，而不是作者想讲的知识点。
- 是否有足够强的利益、损失、冲突、信息差、身份差距或行动窗口。
- 是否能自然长出结构：故事、清单、概念解释、案例拆解、教程或对比。
- 是否有可放大的素材：真实场景、前后对比、错误路径、数据、截图、原话、案例或强判断。
- 是否能产生读者行为：停下来、继续看、收藏、评论、转发、复访或采取下一步。

如果一个题只能靠标题技巧或发布形式硬撑，先降级为半成品选题，继续找读者处境、代价和可放大素材。

## 选题交集和 HKR 检查

强选题通常来自三个条件的交集：

- 创作者能持续提供判断、经验或素材的领域。
- 目标读者已经有普遍兴趣、焦虑、好奇、痛点或行动需求。
- 当下有时间节点、窗口变化、热点事件、平台动作、产品变化、政策变化、价格变化或公共讨论，让读者现在就有理由看。

只有专业领域，容易曲高和寡；只有读者兴趣，容易流于泛流量；只有时间节点，容易变成蹭热点。三者不能同时满足时，先判断缺的是素材、读者处境还是时效理由，再决定补素材、换读者或降级为资料线索。

动笔前可以用 HKR 做快速质检：

- **H / Happy**：是否足够有趣、有悬念、有反差，能让读者想点开或继续看。
- **K / Knowledge**：是否有信息量、判断量或方法量，读完能学到新东西或换一个看法。
- **R / Resonance**：是否戳中读者情绪、处境、焦虑、兴奋、委屈、荒诞感或“我也这样”的共鸣。

S 级选题通常三项都强；常规可做选题至少要有两项。一项很强但另外两项很弱时，不要急着写，先补案例、换目标读者或把它压成短内容试水。三项都弱时，放弃比包装更正确。

补强选题时做三种角色代入：

- **忙碌普通用户**：这件事和我有什么关系，能省什么时间、少踩什么坑、解决什么具体麻烦。
- **爱玩的朋友**：有没有新鲜、荒诞、好奇、反差或“还能这样”的惊叹。
- **焦虑学习者**：有没有新知识、新角度、可执行方法或能缓解不确定性的判断。

角色代入不是让选题讨好所有人，而是检查当前选题的进入理由到底来自实用、趣味、知识、情绪还是行动窗口。

## 主题有效性检查

追求高传播内容时，可以从 swipe file、对标样本、评论、搜索和用户反馈中寻找已经被证明有人关心的主题。但“曾经爆过”不等于现在仍然值得做。主题进入选题池前先判断它是否仍然有效。

检查：

- 是否仍吸引目标读者，而不是只吸引泛流量。
- 最近同类主题是否还有有效样本、评论、收藏、转发或转化信号。
- 如果近期多次同类尝试表现弱，先标为主题疲劳、角度疲劳或待验证，不直接升级成强选题。
- 主题是否还能接入用户自己的经历、判断、案例、可信度或栏目承接。
- 能否换 angle、换 hook、换案例或换目标读者后重新激活，而不是机械重复旧爆款。

主题疲劳不能只靠平台印象判断。没有足够近期样本时，标注为候选假设；用户要求当前有效性或实时表现时，交给 `$cflow-research` 或让用户补充样本。

## 好选题五项检查

把模糊方向变成选题时，检查 5 项：

| 检查项 | 问题 | 通过标准 |
|---|---|---|
| 对象 | 到底写谁、哪件事、哪个场景？ | 有具体读者、场景或任务 |
| 目标 | 这条内容想解释、说服、教学、转化还是复盘？ | 目标类型明确 |
| 冲突 | 哪里和预期不一致？ | 能说出异常、矛盾、代价或断点 |
| 约束 | 什么不能改、必须考虑什么？ | 至少有一个真实约束 |
| 反馈 | 什么证明这个题值得继续？ | 有数据、评论、行为、案例、实验或观察入口 |

不要默认展示完整评分表。默认只告诉用户：

```text
当前清晰度：
最大缺口：
下一步：
```

## 空转词过滤

遇到模糊词时，不要直接沿用。先做替换：

- “有价值” -> 对谁有用、解决什么问题、节省什么代价？
- “影响力” -> 被谁看到、带来什么行为、什么指标变化？
- “个人 IP” -> 想让读者记住什么、信任什么、采取什么行动？
- “深度” -> 拆到哪一层、解释什么机制、反驳什么误解？
- “系统性” -> 包含哪些步骤、边界、输入、输出和反馈？

如果替换不了，当前还不是选题，只是愿望或标签。

## 弱选题气味

- 只是一个大类，不是一个具体处境。
- 谁都能写。
- 没有读者决策或痛点。
- 依赖泛泛激励。
- 其实是标题，不是选题。
- 其实是角度，不是选题。
- 其实是素材方向，不是选题。
- 只是愿望、定位、口号或标签。
- 没有张力路径。
- 因为目标读者太宽而变泛。

## Copywork 作为选题研究

当用户想提升品味或找更原创的想法时，使用 copywork 式研究：

1. 收集目标类型或相邻类型中的优秀案例。
2. 抄写或近距离研究案例，找出可重复规则。
3. 提取选题模式、受众切片、说服动作、节奏和张力来源。
4. 把模式迁移到创作者自己的领域，不复制原表面。

好来源包括经典广告、高表现脚本、短篇故事、杂志写作、喜剧段子、高表现短内容，以及用户所在行业之外的创作者档案。

当选题长期只来自本领域热点、资讯流或同行账号时，要把信息摄入当作组合来检查。刻意加入相邻领域和远领域样本，用它们补充读者任务、结构、节奏、案例功能、情绪推进和张力来源；不要把具体平台、工具、书单、账号或临时信息源写成长期规则。跨领域输入只能提高选题原料质量，不能替代目标读者、真实素材和当前栏目承接。

## 选题质量闸门

输出前自检：

```text
这是选题，还是标题 / 角度 / 愿望 / 标签 / 素材方向：
目标读者是否具体：
读者处境是否具体：
内容目标是否明确：
哪里和预期不一致：
读者正在付出什么代价：
有什么真实约束：
有什么反馈或观察入口：
现有素材是否能支撑：
可放大素材是什么：
张力路径是什么：
下一步应补素材、加 angle、成稿、短内容试水还是放弃：
```

不要把检查表完整输出给用户，除非用户要求看诊断过程。

## 交接规则

只在问题不属于选题职责，或已经完成选题判断并进入生产动作时交接：

- 需要把选题加压成明确主张、冲突、读者张力或 angle：`$cflow-angle`。
- 需要写完整文章、脚本、教程、销售稿或长篇复盘：`$cflow-draft`。
- 需要标题、hook、opening、CTA 或发布包：`$cflow-package`。
- 需要短内容、短脚本或短内容系列正文：`$cflow-shortform`。
- 需要搜索、核查、来源、引用、最新事实或实时主题有效性：`$cflow-research`。
- 需要真实案例、故事设计、类比故事或案例库：`$cflow-case`。
- 需要 offer、funnel stage、转化路径或主 CTA：`$cflow-marketing`。
- 需要复盘已发布内容表现、评论反馈或资产沉淀：`$cflow-review`。
- 需要发布前判断能不能发：`$cflow-check`。

选题任务内部的泛、弱、空转、缺读者、缺素材、缺反馈、只是标题、只是角度、只是愿望标签、主题疲劳初判和选题池组织，不交接。
