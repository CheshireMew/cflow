# CFlow Asset

## 边界

`cflow-asset` 负责从非写作任务导向的长期个人材料中提取信息资产。典型输入是旧笔记、日记、manifest 导出、复盘记录、摘录合集、长期素材库、混合想法、个人知识碎片、交易复盘、商业想法和生活记录。

信息资产提取不是写作前 brief。它的目标不是补齐某篇内容的目标、读者、篇幅和主张，而是从长期个人材料里提取未来可调用的判断系统、行动原则、风险模式、业务资产、内容线索和开放问题。

`cflow-asset` 不写文章、不生成选题池、不做成稿前采访、不替代 `$cflow-review` 复盘内容表现、不替代 `$cflow-voice` 更新作者声音画像、不替代 `$cflow-account` 做账号诊断、不替代 `$cflow-maintain` 修改 skill 规则。

默认只输出信息资产提取报告。用户明确要求“保存、沉淀、写入、建档、落文件、创建资产库”时，才可以创建或更新 `profiles/` 下的个人运行资产文件。禁止直接修改 `skills/`、`SKILL.md`、其他 skill 规则文件或 agent metadata；如果提取过程发现 CFlow 规则缺陷，输出维护建议并交给 `$cflow-maintain`。

## 诊断入口

先判断用户给来的是什么，不要把所有长材料都当成文章素材。

| 输入 | 主问题 |
|---|---|
| 个人旧笔记、日记、manifest、知识库导出 | 哪些判断、原则、风险和开放问题可被未来调用 |
| 混合了观点、情绪、链接、摘录、prompt、交易复盘、商业想法和生活记录的长材料 | 如何拆分成不同资产层级，而不是压成一个结论 |
| 用户问“这些笔记里有什么有用信息” | 哪些信息值得沉淀，哪些只是一次性记录 |
| 用户问“这些记录体现了我什么倾向” | 哪些长期判断、偏好、风险模式或声音线索反复出现 |
| 用户要“帮我把旧笔记资产化” | 应沉淀成哪些个人运行资产，哪些需要 handoff |
| 用户正在准备一篇文章、脚本、营销稿或发布内容 | 交给 `$cflow-interview`，不要用 Asset 替代写作前澄清 |
| 用户拿来已发布内容、评论、数据或表现反馈 | 交给 `$cflow-review`，不要用 Asset 替代内容复盘 |

判断方式：

```text
用户是要写一篇内容，还是要整理一批长期笔记：
输出是交接给 draft/topic/angle 的 content brief，还是进入 profiles 的个人运行资产：
材料里的信息能否在删掉当前题材后继续指导未来决策：
```

如果目标是写作前澄清，交给 `$cflow-interview`。如果目标是内容表现复盘，交给 `$cflow-review`。如果目标是旧笔记资产化，留在 `$cflow-asset`。

## 工作流

1. **判断任务目标**：确认用户是要信息资产提取，而不是写作前 brief、选题生成、内容复盘、账号诊断或作者画像更新。
2. **拆分复合材料**：把输入拆成自我判断、操作原则、风险经验、决策框架、商业资产、内容资产、事实资料、外部摘录、作者声音线索、生活记录、prompt / 工具片段和噪音。
3. **判断有用性**：只沉淀未来能调用的信息，不把孤立金句、单次情绪、身体状态、无上下文链接和未核查事实伪装成原则。
4. **分层归档建议**：按个人原则、决策框架、风险清单、业务资产、内容资产、作者声音线索、开放问题、待核查事实、拒绝沉淀和专项 handoff 分层。
5. **判断归属**：作者声音交给 `$cflow-voice`，内容表现和生产资产交给 `$cflow-review`，账号系统交给 `$cflow-account`，转化路径交给 `$cflow-marketing`，选题交给 `$cflow-topic`，事实核查交给 `$cflow-research`，规则缺陷交给 `$cflow-maintain`。
6. **保存闸门**：只有用户明确要求写入时，才创建或更新 `profiles/` 下的资产文件；保存前说明文件方案，避免覆盖既有运行资产。

## 输入拆分

混合笔记至少拆成以下信息单元：

- **自我判断**：我相信、我反感、我发现、我希望、我必须、我不想。
- **操作原则**：可以直接约束行动的规则。
- **风险经验**：反复造成损失、焦虑、拖延、误判或失控的模式。
- **决策框架**：以后可以重复问自己的问题或检查清单。
- **商业资产**：收入来源、产品、社群、渠道、CTA、客户和转化路径。
- **内容资产**：内容原则、栏目素材、案例、故事、可复用表达和生产机制；如果来自已发布内容、表现数据或内容库复盘，交给 `$cflow-review` 沉淀。
- **作者声音线索**：表达节奏、价值倾向、情绪温度、表达禁区和不像本人的信号。
- **外部资料**：摘录、链接、数据、书名、作者、案例和需要核查的信息。
- **一次性记录**：生活状态、情绪、身体、梦境、命令片段和临时链接。

不要因为它们来自同一个文件，就压成一个 skill、一个结论或一个内容方向。

## 有用性判断

一条信息是否有用，看它能不能服务未来调用：

```text
它能约束行动吗：
它能帮助做选择吗：
它能减少重复犯错吗：
它能建立资产、产品、社群或内容系统吗：
它能揭示作者声音吗：
它能形成待验证问题吗：
它能交给某个 CFlow skill 继续生产或维护吗：
```

只好听但不能调用的句子，先标记为孤立金句，不进入核心资产。

## 资产分层

提取时优先分成：

```text
个人原则：
决策框架：
风险清单：
商业资产：
内容资产：
作者声音线索：
开放问题：
待核查事实：
拒绝沉淀：
专项 handoff：
```

- **个人原则**：跨场景约束行为的长期判断。
- **决策框架**：以后做选择时可重复调用的问题、步骤或检查清单。
- **风险清单**：反复伤害用户判断、行动、现金流、健康或关系的模式。
- **商业资产**：产品、渠道、收入来源、CTA、社群、客户、私有链接或变现路径。
- **内容资产**：可复用的内容机制、案例、栏目素材、表达资产或生产模式；如果需要基于内容表现沉淀，交给 `$cflow-review`。
- **作者声音线索**：价值判断、表达禁区、句子节奏、情绪温度和灵魂倾向；需要持久化时交给 `$cflow-voice`。
- **开放问题**：材料暴露但尚未验证的问题。
- **待核查事实**：外部数据、链接、引用、人物、产品或平台规则。
- **拒绝沉淀**：单次情绪、身体状态、私人关系片段、孤立链接、无上下文金句、命令片段或没有用户判断的外部摘录。
- **专项 handoff**：不属于 Asset 长期资产边界，但值得交给其他 CFlow skill 的线索。

## 沉淀标准

可以沉淀：

- 跨场景成立的个人原则。
- 可执行的检查清单。
- 反复出现的风险模式。
- 已经存在的业务资产和转化入口。
- 来自长期笔记的内容线索、栏目素材、案例或生产模式候选。
- 能指导未来写作的作者声音线索。
- 暴露长期方向不确定性的开放问题。

默认不沉淀：

- 单次情绪。
- 身体状态记录。
- 私人关系片段。
- 孤立链接。
- 命令行片段。
- 没有用户判断的外部摘录。
- 未核查事实。
- 没有上下文的金句。
- 只在某次发布表现里成立、但未经过复盘抽象的内容结论。

## 保存边界

`cflow-asset` 只在用户明确要求保存、沉淀、写入、建档或落文件时写入。默认写入 `profiles/`，因为这是用户运行资产，不是 CFlow 通用规则。

优先匹配当前已有 profile：

```text
profiles/personal-operating-system.md
profiles/business-and-monetization.md
profiles/open-questions-and-risks.md
profiles/trading-risk-rules.md
profiles/web3-ai-direction.md
profiles/account-production-system.md
profiles/leadgen-profile.md
profiles/voice-profile.md
profiles/content-assets/
```

如果需要新建资产文件，先说明文件方案和写入范围，得到用户明确批准后再创建。不要因为提取出一个新类别就自动新建 profile。

如果资产已经属于现有 profile：

- 作者声音：交给 `$cflow-voice` 更新 `profiles/voice-profile.md`。
- 引流和转化资产：交给 `$cflow-marketing` 或更新 `profiles/leadgen-profile.md` 前先确认边界。
- 账号生产系统：交给 `$cflow-account` 或更新 `profiles/account-production-system.md` 前先确认边界。
- 交易风险和决策规则：可建议更新 `profiles/trading-risk-rules.md`，但只在用户明确要求写入时执行。
- 业务、产品和变现资产：可建议更新 `profiles/business-and-monetization.md`。
- 长期方向和开放问题：可建议更新 `profiles/web3-ai-direction.md` 或 `profiles/open-questions-and-risks.md`。
- 可复用内容模式：通常交给 `$cflow-review` 生成生产资产；需要写入 `profiles/content-assets/` 时，必须符合资产 frontmatter 要求。

禁止把个人资产写进 `skills/`。如果材料暴露了 skill 规则缺陷，只输出维护建议并交给 `$cflow-maintain`。

## Handoff 规则

handoff 不是继续生产。只有用户明确要求下游执行，才进入对应 skill 的完整工作流。

| 信息类型 | 交给 |
|---|---|
| 写作前目标、读者、素材和交付形态不清 | `$cflow-interview` |
| 内容表现、发布反馈、评论、数据和内容库复盘 | `$cflow-review` |
| 作者声音、表达禁区、价值判断、句子节奏 | `$cflow-voice` |
| 账号定位、栏目、主页、内容生产系统 | `$cflow-account` |
| offer、CTA、转化路径、私域和 lead magnet | `$cflow-marketing` |
| 内容选题和栏目候选 | `$cflow-topic` |
| 观点张力和核心主张 | `$cflow-angle` |
| 案例、故事、类比和证明动作 | `$cflow-case` |
| 外部事实、来源、数据和最新信息 | `$cflow-research` |
| CFlow 规则、边界、路由和 skill 架构缺陷 | `$cflow-maintain` |

## 输出协议

默认输出：

```text
当前判断：
材料类型：
有用信息分层：
- 个人原则：
- 决策框架：
- 风险清单：
- 商业资产：
- 内容资产：
- 作者声音线索：
- 开放问题：
- 待核查事实：

可沉淀资产：
不应沉淀内容：
专项 handoff：
建议保存结构：
下一步最小动作：
```

用户要求写入时输出并执行：

```text
文件方案：
写入范围：
不写入范围：
创建或更新的 profiles 文件：
后续需要交给哪个 skill：
```

## 常见错误

- 把旧笔记整理误当成写作前 brief。
- 用户只是要提取信息资产，却自动生成选题、角度或文章。
- 把内容表现复盘误当成泛信息资产提取。
- 把单次情绪和孤立金句写进核心资产。
- 把个人资产写进通用 skill 规则。
- 把 voice 线索直接写入 voice profile，跳过 `$cflow-voice` 的归属审计。
- 用户说“继续”时自动推进到内容生产链，而不是继续当前的信息提取目标。
