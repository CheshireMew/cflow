# CFlow Image

## 边界

`cflow-image` 负责内容视觉资产的判断、设计和交接：封面、thumbnail、文章头图、正文插图、配图、分享图、图表 / 示意图、信息图、截图说明、视觉 brief、图片生成 prompt、视觉对标、系列视觉语法、视觉实验和视听留存 brief。

它必须自己完成图像任务内的核心判断：这张图是否必要、用什么类型、第一眼是否成立、文字是否过载、主视觉是否服务主张、生成图是否会误导事实、系列识别是否压过本期信息、视觉实验应该测试什么。不能把这些判断外包给 `$cflow-check`、`$cflow-package`、`$cflow-review` 或任何“合同”。

不负责：

- 生成或改写正文标题、hook、opening、CTA 和短发布文案；这些交给 `$cflow-package`。但封面文字、thumbnail text 和 cover text 属于 `cflow-image`。
- 搜索真实来源、核查事实、确认产品状态、查人物/公司/价格/政策/数据；用户要求真实来源、事实核查、合规、品牌安全或发布限制时，交给 `$cflow-research`。
- 发布后数据复盘和表现归因；发布后 reach、点击、收藏、转发、评论和关注转化交给 `$cflow-review`。但发布前视觉实验变量由 `cflow-image` 设计。
- 重写主张、选题、长文、短内容、营销策略或 SEO 结构；主张不成立时交给 `$cflow-angle` / `$cflow-topic`，正文重写交给 `$cflow-draft` / `$cflow-edit`，短内容交给 `$cflow-shortform`，转化路径交给 `$cflow-marketing`，SEO/GEO 结构交给 `$cflow-seo`。
- 直接把 AI 生成图当成真实证据。生成图可以表达隐喻、氛围、假设场景或非事实概念，但不能伪造产品截图、新闻现场、人物合照、数据图或研究结论。

## 入口判断

进入 `cflow-image` 后先判断用户要的是哪类交付：

- **封面 / thumbnail**：争夺点击和识别，第一眼说明“这是什么、为什么值得看、适合谁”。
- **文章头图**：建立主题气质、场景和记忆点，不必像封面一样强刺激。
- **正文插图 / 配图**：帮助理解机制、步骤、对比、空间关系、情绪场景或行动路径。
- **分享图**：增强停留、截图传播、复述或第一眼识别。
- **图表 / 示意图 / 信息图**：解释结构、流程、分类、因果、层级、对比或数据。
- **产品截图 / 截图说明**：展示界面、功能、结果或路径；用户要求真实证明时按事实边界处理。
- **生成图**：表达抽象隐喻、场景想象、视觉气质或非事实概念。
- **视觉 prompt**：把视觉 brief 转成可执行图片生成 prompt。
- **视觉对标 / 视听留存 brief**：拆解封面、视频、动效、声音或视觉样本里的可迁移机制。
- **系列视觉**：为固定栏目、资源卡、教程卡、复盘卡、视频 thumbnail 或长期发布包定义可复用视觉语法。
- **视觉实验**：为同一主张、文案或内容设计 1 到 3 个可比较视觉变量。

## 工作流

1. **判断图像任务**：确认是封面、文章头图、插图、分享图、图表、截图、生成图、prompt、对标、系列视觉还是实验。
2. **确认内容基础**：读者、交付形态、发布约束、核心主张、读者张力、第一眼动作、主动作 / CTA。
3. **判断图像必要性**：图像是否帮助点击、停留、理解、记忆、信任、转化或传播；不能帮助就不加。
4. **选择图像类型**：真实照片、产品截图、实拍、生成图、图表、流程图、信息图、文字型封面或混合方案。
5. **设计第一眼信息层级**：主视觉、主文字、辅助文字、品牌/作者信息、场景信号和缩小预览可读性。
6. **判断事实边界**：是否涉及人物、公司、产品界面、政策、价格、数据、研究结论或当前状态；用户要求真实来源或严谨发布时，明确哪些必须核查。
7. **判断系列识别**：固定栏目、系列内容或账号资产优先定义可复用版式、色彩、字体层级、截图处理、编号或视觉锚点。
8. **生成视觉 brief**：比例、主题、构图、文字、风格、色彩、素材来源、要求出现和要求避开的元素。
9. **生成图片 prompt**：需要 AI 生成图时，把 brief 转成可执行 prompt；准确中文文字优先建议后期排版，不依赖生成模型。
10. **设计视觉实验**：需要测试第一眼表现时，给出 1 到 3 个变量，并说明发布后应观察的信号。
11. **交接下一步**：只把不属于图像职责的问题交给对应 skill。

## 类型选择

优先问：这张图承担什么任务？

| 任务 | 优先类型 | 避免 |
|---|---|---|
| 展示产品或界面（用户要求真实证明时） | 截图、官方图、实拍 | AI 生成假界面 |
| 解释流程或结构 | 流程图、信息图、示意图 | 氛围图 |
| 提高点击 | 文字型封面、强场景封面 | 信息太多的海报 |
| 建立情绪和主题 | 文章头图、风格化插图 | 与主张无关的装饰图 |
| 展示数据差异 | 图表、对比图 | 信息不清楚 |
| 表达假设或未来场景 | 生成图 | 画面无冲击力或看似事实 |
| 降低操作成本 | 截图说明、流程图、路径图 | 抽象隐喻图 |
| 增强截图传播 | 分享图、金句图、对比卡 | 只装饰不自足的配图 |

默认可以为了点击、停留、理解、氛围或传播加图；用户要求极简、严谨或无图时，再收窄到必要视觉。

## 封面和 Thumbnail

封面先解决识别，再解决美感。

按顺序确认：

1. **读者**：谁应该停下来？
2. **主题**：这条内容讲什么？
3. **张力**：为什么现在要看？
4. **场景或冲击**：凭什么停下来看？
5. **品牌/作者**：是否需要署名、栏目名或系列识别？

封面文字不是正文标题的复制。它通常只放一到两个信息层：

- 主文字：核心对象、结果、冲突、问题、数字差或读者处境。
- 副文字：范围、条件、受众、时间窗口或具体场景。

封面文字规则：

- 比标题更短、更直接。
- 优先使用具体名词、结果、冲突、对象、数字或读者处境。
- 缩小预览时仍能读出主信息。
- 不把标题、摘要、CTA、解释和品牌口号都塞进封面。
- 默认允许使用强词、强对比和强场景；用户要求品牌克制、事实严谨或发布限制时再收窄。
- 如果正文主张弱，封面可以强化刺激点，但不能伪造正文没有的事实、结果或承诺。主张本身不成立时交给 `$cflow-angle` 或 `$cflow-topic`。

封面失败信号：

- 缩小后主文字不可读。
- 图很好看，但读者不知道内容讲什么。
- 文字层级太多，像海报说明书。
- 主视觉和主张无关，只是装饰氛围。
- 封面承诺强于正文能兑现的 payoff。
- 系列固定元素压过本期内容。

## 文章头图

文章头图负责建立主题气质、场景和记忆点，不必像封面一样强刺激。

优先使用：

- 与主张相关的真实场景、对象、动作或空间。
- 能承载文章情绪的主视觉，而不是泛泛氛围图。
- 能让读者进入主题的具体物件、人物姿态、界面状态或场景信号。

避免：

- 与内容无关的抽象科技感、光效、城市夜景、握手、电脑桌面等泛图。
- 画面漂亮但信息完全替代不了正文第一句。
- 生成图让未证实事实看起来已经发生。

## 正文插图和配图

正文插图应该至少满足一个条件：

- 读者不用读长段文字也能理解结构。
- 展示前后对比、流程、层级、空间关系或因果。
- 让抽象判断落到具体场景。
- 增强现场感或说服力，例如截图、数据图或原始材料；用户要求严谨时才作为证据处理。
- 增加记忆点，但不改变事实。
- 降低行动成本，把入口、路径、步骤或操作顺序可视化。

不建议加图的情况：

- 只是在重复正文已经说清楚的话。
- 视觉隐喻比正文更抽象。
- 插图没有解释功能，只是占版面。
- 用户要求事实严谨时，生成图会让事实看起来更确定。
- 图片和阅读场景不匹配。

## 图表 / 示意图 / 信息图

当内容需要解释流程、结构、分类、因果、层级、对比或数据差异时，优先考虑图表 / 示意图，而不是氛围图。

选择规则：

- **流程**：用步骤图、路径图、时间线或泳道图。
- **层级**：用金字塔、树状图、分层卡片或嵌套结构。
- **因果**：用箭头链路、反馈环或前后状态图。
- **分类**：用矩阵、象限、标签组或分组表。
- **对比**：用左右对照、前后对照、差异表或计分卡。
- **数据**：用柱状图、折线图、散点图、面积图或简单数值卡。

图表纪律：

- 读者应一眼知道图在解释什么。
- 不为了“专业感”增加多余维度、颜色和箭头。
- 没有真实数据时，不画成数据图；可以画概念示意图，并标明不是实测数据。
- 需要严谨发布时，数据来源、统计口径和更新时间交给 `$cflow-research`。

## 视觉刷新

长内容、密集教程、复杂概念、推广文案或高压短内容需要视觉时，先问视觉承担什么刷新功能，而不是按固定间隔机械加图。

可用功能：

- **注意力刷新**：在信息密度高、连续抽象或情绪疲劳处给读者新的第一眼锚点。
- **结构解释**：把流程、层级、对比、因果或分类变成更快理解的图。
- **截图传播**：把核心判断、清单、框架或前后对比做成一屏自足的分享单元。
- **证据承接**：用截图、原始材料、数据图或实拍增强现场感；用户要求严谨时再按证据边界处理。
- **行动降低成本**：把步骤、入口、路径或操作顺序可视化，减少读者执行阻力。

不要为了“更像爆款”加装饰图。视觉没有降低认知负荷、提高停留、帮助理解、制造记忆点或服务传播时，就不加。

## 系列视觉和账号识别

系列视觉服务复访和账号识别，不是装饰统一。用户做固定栏目、系列内容、资源卡、复盘卡、教程卡、视频 thumbnail 或长期发布包时，先设计可重复的视觉语法：

- **版式锚点**：标题位置、编号位置、主图比例、留白和信息区位置。
- **识别锚点**：固定色块、栏目名、作者标记、图标、边框、截图处理或标题层级。
- **信息锚点**：每张图第一眼都回答同一类问题，例如“发生什么 / 为什么重要 / 读者该看哪里”。
- **变化区**：每期可以变化的主视觉、关键词、数字、截图或人物，不要把整张图做成完全固定模板。
- **不可复制区**：如果来自对标创作者，只迁移信息层级、认知负荷和节奏，不复制对方识别性元素。

系列视觉检查：

```text
这个视觉是否能让老读者一眼认出栏目？
新读者不认识账号时，是否仍能看懂本期内容？
固定元素是否压过了本期主张？
变化区是否足够承载每期的新信息？
缩小后标题、数字和主视觉是否还成立？
```

系列视觉表现要回流 `$cflow-review`：比较同系列不同封面、同文案不同视觉、同视觉不同标题的 reach、点击、收藏、转发、评论和关注转化。不要用单次视觉表现直接否定内容主张。

## 视觉实验

当同一主张、短内容或推广文案文字表现弱，但判断本身仍有张力时，可以把视觉作为实验变量，而不是立刻否定内容。

可测试：

- 封面文字是否更快说明对象、结果或冲突。
- 主视觉使用真实图、截图、生成图或文字型封面的表现差异。
- 分享图是否增加停留、截图传播或点击。
- 截图、对比图、流程图或示意图是否让读者更快理解机制。
- 同一文案配图前后的 reach、点击、收藏、转发或评论差异。
- 同一系列视觉中固定元素和变化区的占比是否影响识别。

视觉实验只说明第一眼识别、停留或点击可能改变。不要把视觉带来的表现变化直接写成内容主张已经被证明。

实验输出只给 1 到 3 个变量。变量太多会导致发布后无法归因。

## 视觉对标和视听留存 Brief

当用户要求拆解或迁移某个视频、封面、动效、声音风格或视觉样本时，先学习信息层级和认知机制，不复制表面装饰。

可迁移维度：

- **第一眼识别**：读者是否立刻知道对象、冲突、结果或受众。
- **视觉锚点**：画面中有没有持续引导注意力的主元素、人物、形状、截图或文字。
- **认知负荷**：颜色、字体、构图、动效和文字数量是否降低理解成本。
- **节奏刷新**：长脚本、短脚本或动效是否用新画面、新文字、新运动或新声音定期刷新注意力。
- **声音提示**：转折、重击、出现、推进和停顿是否有音效或语音节奏配合。
- **品牌一致性**：色彩、字体、构图和声音是否服务同一内容气质。

输出视觉或动效 brief 时，写清楚“这个元素承担什么功能”。不要只写“黑白极简、科技感、电影感、高级感”。如果某种风格来自特定创作者，只能迁移锚点、层级、节奏和认知负荷控制，不要求复制对方识别性元素。

用户已提供视觉样本并要求拆解“为什么有效”时，`cflow-image` 先完成视觉机制判断；如果要把表现数据、评论、转发或发布后反馈沉淀为内容机制，再交给 `$cflow-review`。

## 真实图、截图和生成图边界

普通视觉包装先服务点击、停留、理解和传播。只有用户要求真实来源、事实核查、合规、品牌安全或发布限制时，才执行严格事实核查边界。

必须优先真实来源的情况：

- 涉及真实人物、公司、产品界面、政策、价格、数据、研究结论或当前状态。
- 图片要作为证据、证明、教程截图、产品能力展示或事实说明。
- 发布平台、品牌或合作方要求真实素材。
- 图像内容可能造成误导、侵权、虚假背书或不实新闻感。

生成图可以用于：

- 抽象隐喻。
- 氛围和主题气质。
- 假设场景。
- 非事实概念。
- 无特定真实人物和真实产品界面的风格化场景。

生成图不能用于：

- 替代真实产品 UI、运行结果、数据图表或实拍证据。
- 伪造新闻现场、人物合照、采访画面、财务数据图、研究图表或官方截图。
- 让未证实事实看起来已经发生。
- 让读者误以为图像是实拍、截图或官方材料。

如果素材来源不明，输出里标注“需要来源确认”或“仅作视觉方向”。

## 图片 Prompt 合同

生成 prompt 时写清楚画面，而不是只写抽象风格。

```text
Subject:
Scene:
Composition:
Text:
Style:
Color:
Lighting:
Aspect ratio:
Avoid:
```

中文内容可以保留中文 brief，但图片生成 prompt 可用英文写，以提高模型执行稳定性。图片中需要准确中文文字时，优先考虑后期排版，不要依赖生成模型精确渲染中文。

Prompt 纪律：

- 先写画面主体、场景和构图，再写风格。
- 不用“高级感、科技感、电影感、爆款感”替代具体视觉。
- 写清楚需要避免的误导元素、伪事实元素、过度装饰和文字错误。
- 如果需要封面文字，优先输出“后期排版文字”，而不是要求图像模型精准生成中文。
- 如果图像需要真实截图、真实人物、真实产品或真实数据，不直接生成 prompt 伪造，先交给 `$cflow-research` 或标注来源缺口。

## 常见错误

- 用漂亮氛围图替代清楚信息。
- 视觉不够抓人，但没有指出第一眼到底缺对象、冲突、结果还是受众。
- 封面文字太多，缩小后不可读。
- 插图没有解释功能，只是占版面。
- 用户要求严谨时，把 AI 生成图当作事实证据。
- 所有内容都套同一种视觉模板，失去主题和第一眼任务差异。
- 只说“更高级、更有质感、更科技、更冲击”，没有落到主视觉、文字层级、构图和缩略图可读性。
- 对标时复制别人识别性元素，而不是迁移信息层级、认知负荷和视觉节奏。
- 系列视觉固定元素太重，导致每期新信息看不见。
- 用图表制造专业感，但图表没有真实数据、清晰关系或明确读者结论。
- 生成图表现了不存在的产品界面、人物关系、新闻现场或数据结果。

## 路由

只在问题不属于 `cflow-image` 时路由：

- **标题、hook、opening、CTA、短发布文案要生成或重写**：交给 `$cflow-package`。
- **事实来源、真实图片、产品状态、数据、政策、人物或引用需要确认**：交给 `$cflow-research`。
- **主张、角度或读者张力不成立**：交给 `$cflow-angle` 或 `$cflow-topic`。
- **正文需要成稿或重写**：交给 `$cflow-draft` 或 `$cflow-edit`。
- **短内容正文、thread 或短脚本需要生产**：交给 `$cflow-shortform`。
- **offer、funnel、CTA 策略或转化路径不清**：交给 `$cflow-marketing`。
- **SEO/GEO/AEO/LLMO 结构需要设计**：交给 `$cflow-seo`。
- **发布后视觉表现、评论、转发、截图和数据要复盘**：交给 `$cflow-review`。

不能路由的情况：

- 用户要求封面、配图、插图、视觉 brief、图片 prompt 或视觉对标，`cflow-image` 必须先承担视觉判断。
- 用户问“该不该加图、用什么图、真实图还是生成图、封面文字怎么放”，`cflow-image` 必须自己判断。
- 用户提供视觉样本想迁移风格，`cflow-image` 必须先拆信息层级、认知负荷和视觉功能，不能只交给 `$cflow-review`。
- 用户担心 AI 生成图误导事实，`cflow-image` 必须先判断图像边界；需要查证来源时才交给 `$cflow-research`。
