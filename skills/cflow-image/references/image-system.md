# 图像系统

## 图像任务类型

- **封面 / thumbnail**：争夺点击和识别，第一眼要说明“这是什么、为什么值得看、适合谁”。
- **文章头图**：建立主题气质和记忆点，不必像封面一样强刺激。
- **正文插图**：帮助理解机制、步骤、对比、空间关系或情绪场景。
- **社交配图**：增强停留、截图传播或平台识别。
- **图表 / 示意图**：解释结构、流程、分类、因果或数据。
- **产品截图**：证明真实状态，展示界面、功能或结果。
- **生成图**：表达抽象隐喻、场景想象或风格化视觉，不当作事实证据。

## 类型选择

优先问：这张图承担什么任务？

| 任务 | 优先类型 | 避免 |
|---|---|---|
| 证明产品或界面真实存在 | 截图、官方图、实拍 | AI 生成假界面 |
| 解释流程或结构 | 流程图、信息图、示意图 | 氛围图 |
| 提高点击 | 文字型封面、强场景封面 | 信息太多的海报 |
| 建立情绪和主题 | 文章头图、风格化插图 | 与主张无关的装饰图 |
| 展示数据差异 | 图表、对比图 | 只写夸张结论 |
| 表达假设或未来场景 | 明确标注的生成图 | 伪装成真实照片 |

不能说明图像任务时，不要为了“丰富一点”加图。

## 封面信息层级

封面先解决识别，再解决美感。

按顺序确认：

1. **读者**：谁应该停下来？
2. **主题**：这条内容讲什么？
3. **张力**：为什么现在要看？
4. **证据或场景**：凭什么可信？
5. **品牌/作者**：是否需要署名或系列识别？

封面文字通常只放一到两个信息层：

- 主文字：核心对象、结果、冲突或问题。
- 副文字：范围、条件、受众或具体场景。

不要把标题、摘要、CTA 和解释都塞进封面。读者应在缩小预览时仍能读出主信息。

## 封面文字

封面文字不是正文标题的复制。

- 比标题更短、更直接。
- 优先使用具体名词、结果、冲突或对象。
- 避免空泛词：成长、逆袭、效率提升、认知升级、底层逻辑。
- 避免万能大词：AI 时代、未来已来、彻底改变、一文讲透。
- 如果正文主张弱，不要用更刺激的封面遮盖，先回到 `$cflow-angle` 或 `$cflow-draft`。

## 插图判断

正文插图应该至少满足一个条件：

- 读者不用读长段文字也能理解结构。
- 展示一个前后对比、流程、层级或关系。
- 让抽象判断落到具体场景。
- 提供真实证据，例如截图、数据图或原始材料。
- 增加记忆点，但不改变事实。

不建议加图的情况：

- 只是在重复正文已经说清楚的话。
- 视觉隐喻比正文更抽象。
- 生成图会让事实看起来更确定。
- 图片和平台阅读场景不匹配。

## 真实图、截图和生成图边界

- 涉及人物、公司、产品界面、政策、价格、数据、研究结论或当前状态时，优先真实来源。
- 产品 UI、运行结果、数据图表不能用 AI 生成图替代真实证据。
- 生成图可以表达比喻、氛围、假设场景或非事实概念，但要避免让读者误以为它是真实记录。
- 如果素材来源不明，输出里标注“需要来源确认”或“仅作视觉方向”。
- 不要生成看似真实的新闻现场、人物合照、产品截图或财务数据图。

## 图片 Prompt 合同

生成 prompt 时写清楚画面，而不是只写抽象风格。

```text
Subject:
Scene:
Composition:
Text:
Style:
Color:
Lighting:
Aspect ratio:
Avoid:
```

中文内容可以保留中文 brief，但图片生成 prompt 可用英文写，以提高模型执行稳定性。图片中需要准确中文文字时，优先考虑后期排版，不要依赖生成模型精确渲染中文。

## 常见错误

- 用漂亮氛围图替代清楚信息。
- 视觉比正文更夸张，制造点击后落差。
- 封面文字太多，缩小后不可读。
- 插图没有解释功能，只是占版面。
- 把 AI 生成图当作事实证据。
- 所有内容都套同一种视觉模板，失去平台和主题差异。
