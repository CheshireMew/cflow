# 案例故事系统

## 共享合同

案例故事受 `$cflow` 的 `references/content-production-contract.md` 约束。本文件只维护案例类型、故事功能、写入位置和真实性边界。案例必须服务主任务，不单独抢走内容主轴。

## 案例功能

一个案例至少承担一种功能：

- **制造落点**：让主张有画面、场景和记忆点。只有用户要求严谨时才当证据处理。
- **解释机制**：让抽象逻辑变具体。
- **增加趣味**：打破干燥论述。
- **制造情绪**：让读者感到惊讶、共鸣、愤怒、安心或好奇。
- **降低理解成本**：用熟悉场景解释复杂概念。
- **处理异议**：回答读者心里的“不一定吧”。
- **增强转化**：让 offer、CTA 或行动更想发生。
- **制造记忆点**：让内容有可复述的场景。

默认保留有注意力、情绪、反差或记忆点的故事。用户要求严谨论证时，再删除没有论证功能的故事。

## 案例类型

### 真实历史事件

适合支撑规律、机制、反常识观点。

默认要求：

- 普通创作中可以先作为案例方向输出，不要因为未核查就停止生产。
- 用户要求真实核查、来源、引用或严肃论证时，再标注“需要核验”并交给 `$cflow-research`。

### 个人经历

适合建立人味、情绪和代入感；用户要求严谨论证时也可作为素材来源。

要求：

- 保留具体场景
- 不擅自美化结果
- 允许有不完整和毛边

### 用户/客户案例

适合营销、服务、产品、社群、课程内容。

要求：

- 区分匿名、脱敏、公开案例
- 如果用户要求严谨，再标注结果是否有数据支撑
- 明确前后变化和关键动作

### 行业案例

适合解释趋势、商业机制或发布环境变化。

要求：

- 说明行业背景
- 用户要求当前事实核查、来源或引用时，正式研究交给 `$cflow-research`
- 用户要求严谨时，不把个例当普遍规律
- 标出可迁移部分

### 未来预演

适合展示趋势、风险或战略选择。

标注为：

```text
类型：未来预演 / scenario
真实性：预测，不是事实
```

要求：

- 明确假设条件
- 默认可以制造清晰的压力、代价和趋势感；用户要求严谨时再检查确定性边界
- 让读者看到“如果继续这样，会发生什么”

### 假设故事

适合解释概念、降低理解成本。

标注为：

```text
类型：假设故事
真实性：虚构，用于解释
```

要求：

- 用户要求真实性边界时，不伪装成真实经历
- 场景要符合读者生活或业务处境
- 只服务一个概念

### 类比故事

适合把陌生机制解释成读者熟悉的机制。

要求：

- 说明相似点
- 说明类比边界
- 用户要求严谨论证时，不用类比替代证据

### 反面案例

适合展示错误成本、失败机制、不要做什么。

要求：

- 不为了攻击而攻击
- 讲清楚失败机制
- 给出可迁移警示

### 微场景

适合短内容、开头、hook、过渡段。

要求：

- 一两个细节就够
- 不展开成长故事
- 直接服务读者识别和情绪

### 创意案例

适合产品体验、工具分享、玩法教程、AI 整活、资源推荐和创意展示。它不是普通例子，而是正文里的一个小型 payoff。

基本链路：

```text
挑战：作者或读者想解决什么具体问题
脑洞：想到了什么不寻常的做法、组合或测试方式
过程：实际怎么一步步做，中间有什么阻碍、选择或意外
结果：最后出现什么让人惊讶、想试、想转发或记住的东西
```

判断标准：

- 案例本身有独立观赏价值、创意价值或启发价值。
- 过程里有动作、限制和选择，不只是展示结果。
- 结果能承担情绪 payoff，而不是靠“很惊艳、很震撼”这类形容词硬夸。
- 真实素材不足时，先输出“需要补的过程素材”，不要编造作者亲历或产品效果。
- 多个创意案例并列时，交给 `$cflow-draft` 按逐一展示和升番排序，最强样本放后面。

## 案例选择标准

优先选择同时满足这些条件的案例：

- 能直接支撑核心主张
- 读者能快速理解
- 细节具体
- 不需要大量背景解释
- 默认先看画面和情绪，用户要求严谨时再看真实性边界
- 用户要求 voice 时，符合作者声音
- 能放进目标篇幅或发布约束
- 不抢走主张本身
- 有戏剧性、反差或情绪功能时优先保留；不要为了“稳”删掉记忆点

## 案例输出格式

```text
主张：
案例类型：
真实性标注（仅严谨模式必填）：
联网状态：
案例摘要：
关键细节：
承担功能：
为什么适合：
可继续加压：
写入位置：
可用开头：
```

## 写入位置

- **开头**：用来抓注意力或制造场景。
- **论证中段**：用来解释机制或支撑主张。
- **转折处**：用来从抽象转入具体。
- **异议处理处**：用来回答读者反驳。
- **结尾**：用来形成记忆点或行动理由。

## 严谨模式检查

- 用户要求严谨时，虚构故事被写得像真实案例
- 用户要求严谨时，把未核验真实事件写成已确认事实
- 用户要求严谨时，类比过度
- 案例比主张更抢戏
- 案例有趣但无功能
- 案例和目标读者无关
- 未来预演被写成确定预测
- 用户要求严谨时，为了戏剧性擅自补事实
