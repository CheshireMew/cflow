# CFlow 案例故事

## 边界

`cflow-case` 负责为观点、角度、论证、营销转化或草稿寻找、设计、筛选和标注能支撑主张的案例 / 故事素材。

案例默认服务表达效果。可以为了注意力、情绪、反差、解释、异议处理、转化桥或记忆点加入故事；用户要求严谨论证时，再检查是否严格服务一个具体主张。

`cflow-case` 不是资料核查系统。真实、来源、引用、当前事实、数据、人物、公司和政策细节需要核查时，交给 `$cflow-research`。`cflow-case` 负责案例类型选择、故事功能、画面化、类比、假设故事、未来预演、微场景和写入位置。

用户要求“真实故事、历史故事、生活细节、普通人能懂、有趣一点”时，先区分宏观制度案例和可写成场景的生活故事。信用制度、护照、公证、清算网络这类宏观案例只能解释机制；如果要做开头故事，优先找有人、动作、阻碍和具体物件的场景。故事进入正文前，不要急着把它抽象成概念。

## 工作流

1. **确定主张**：先明确案例要支撑什么观点、机制、情绪或转化动作。
2. **判断案例任务**：案例承担解释、趣味、情绪、反差、记忆点、异议处理、转化桥还是证明。
3. **选择案例类型**：真实事件、个人经历、客户案例、行业案例、历史生活场景、宏观制度案例、未来预演、假设故事、类比故事、反面案例、微场景或创意案例。
4. **选择呈现方式**：默认先判断案例如何制造画面、情绪、反差、记忆点或转化桥；如果用户要的是故事开头，必须能写出人、动作、阻碍、物件和现场顺序。
5. **生成候选**：给出多个不同策略的案例方向，不把所有案例压成同一种故事。
6. **评估表现力**：检查是否有画面、有反差、有情绪、有记忆点，是否会抢走主张。
7. **判断真实性边界**：只有用户要求严谨、真实、来源、引用、合规或严肃论证时，才评估真实性、来源和核查状态。
8. **交接生产**：需要写进正文时交给 `$cflow-draft`；需要角度化时交给 `$cflow-angle`；需要营销转化时交给 `$cflow-marketing`。

## 诊断入口

先判断用户缺的是哪类案例，不要默认只找真实历史故事。

| 输入 | 主问题 |
|---|---|
| “这个观点缺例子” | 需要解释机制、制造落点，还是增强可信度 |
| “内容太干” | 需要微场景、故事开头、生活细节还是情绪反差 |
| “帮我找真实案例 / 历史案例” | 是否需要来源核查；未核查时只给案例方向和待核验状态 |
| “需要一个未来场景” | 用未来预演展示什么趋势、风险或战略选择 |
| “能不能编个例子” | 用假设故事、类比故事或微场景解释哪个概念 |
| “营销内容缺证明” | 需要客户案例、用户/客户前后变化、社会证明还是异议处理 |
| “需要反面例子” | 要展示什么错误成本、失败机制或不要做什么 |
| “开头缺故事” | 是否有人、动作、阻碍、具体物件和现场顺序 |

如果用户只是要事实核查、来源包、真实案例搜寻或历史事件细节，交给 `$cflow-research`；如果用户已经有主张但缺能写进内容的故事功能，留在 `$cflow-case`。

## 案例功能

一个案例至少承担一种功能：

- **制造落点**：让主张有画面、场景和记忆点。只有用户要求严谨时才当证据处理。
- **解释机制**：让抽象逻辑变具体。
- **增加趣味**：打破干燥论述。
- **制造情绪**：让读者感到惊讶、共鸣、愤怒、安心或好奇。
- **降低理解成本**：用熟悉场景解释复杂概念。
- **处理异议**：回答读者心里的“不一定吧”。
- **增强转化**：让 offer、CTA 或行动更想发生。
- **制造记忆点**：让内容有可复述的场景。

默认保留有注意力、情绪、反差或记忆点的故事。用户要求严谨论证时，再删除没有论证功能的故事。

## 案例类型

### 真实历史事件

适合支撑规律、机制、反常识观点。

要求：

- 普通创作中可以先作为案例方向输出，不要因为未核查就停止生产。
- 用户要求真实核查、来源、引用或严肃论证时，再标注“需要核验”并交给 `$cflow-research`。
- 涉及具体年份、人物、机构、政策细节和因果判断时，不要为了故事效果补细节。

### 个人经历

适合建立人味、情绪和代入感；用户要求严谨论证时也可作为素材来源。

要求：

- 保留具体场景。
- 不擅自美化结果。
- 允许有不完整和毛边。
- 不替用户补关键事实。

### 用户 / 客户案例

适合营销、服务、产品、社群、课程内容。

要求：

- 区分匿名、脱敏、公开案例。
- 如果用户要求严谨，再标注结果是否有数据支撑。
- 明确前后变化和关键动作。
- 不编造客户结果、收入、截图或反馈。

### 行业案例

适合解释趋势、商业机制或发布环境变化。

要求：

- 说明行业背景。
- 用户要求当前事实核查、来源或引用时，正式研究交给 `$cflow-research`。
- 用户要求严谨时，不把个例当普遍规律。
- 标出可迁移部分。

### 未来预演

适合展示趋势、风险或战略选择。

标注为：

```text
类型：未来预演 / scenario
真实性：预测，不是事实
```

要求：

- 明确假设条件。
- 默认可以制造清晰的压力、代价和趋势感；用户要求严谨时再检查确定性边界。
- 让读者看到“如果继续这样，会发生什么”。

### 假设故事

适合解释概念、降低理解成本。

标注为：

```text
类型：假设故事
真实性：虚构，用于解释
```

要求：

- 用户要求真实性边界时，不伪装成真实经历。
- 场景要符合读者生活或业务处境。
- 只服务一个概念。

### 类比故事

适合把陌生机制解释成读者熟悉的机制。

要求：

- 说明相似点。
- 说明类比边界。
- 用户要求严谨论证时，不用类比替代证据。

### 反面案例

适合展示错误成本、失败机制、不要做什么。

要求：

- 不为了攻击而攻击。
- 讲清楚失败机制。
- 给出可迁移警示。

### 微场景

适合短内容、开头、hook、过渡段。

要求：

- 一两个细节就够。
- 不展开成长故事。
- 直接服务读者识别和情绪。

### 创意案例

适合产品体验、工具分享、玩法教程、AI 整活、资源推荐和创意展示。它不是普通例子，而是正文里的一个小型 payoff。

基本链路：

```text
挑战：作者或读者想解决什么具体问题
脑洞：想到了什么不寻常的做法、组合或测试方式
过程：实际怎么一步步做，中间有什么阻碍、选择或意外
结果：最后出现什么让人惊讶、想试、想转发或记住的东西
```

判断标准：

- 案例本身有独立观赏价值、创意价值或启发价值。
- 过程里有动作、限制和选择，不只是展示结果。
- 结果能承担情绪 payoff，而不是靠“很惊艳、很震撼”这类形容词硬夸。
- 真实素材不足时，先输出“需要补的过程素材”，不要编造作者亲历或产品效果。
- 多个创意案例并列时，交给 `$cflow-draft` 按逐一展示和升番排序，最强样本放后面。

## 故事开头硬检查

如果案例要承担正文开头，必须先检查是否具备：

```text
人：
动作：
阻碍：
具体物件：
现场顺序：
```

前 120 字内默认不急着写“本质、核心、基础设施、验证层、复杂事实、可验证凭证”等抽象词；除非用户明确要求技术开门见山。

宏观制度案例、技术机制和行业趋势可以作为正文中段解释材料，但不天然适合做开头故事。要做开头，先把它落到人、动作、阻碍和具体物件。

## 案例选择标准

优先选择同时满足这些条件的案例：

- 能直接支撑核心主张。
- 读者能快速理解。
- 细节具体。
- 不需要大量背景解释。
- 默认先看画面和情绪，用户要求严谨时再看真实性边界。
- 用户要求 voice 时，符合作者声音。
- 能放进目标篇幅或发布约束。
- 不抢走主张本身。
- 有戏剧性、反差或情绪功能时优先保留；不要为了“稳”删掉记忆点。

## 写入位置

- **开头**：用来抓注意力或制造场景。
- **论证中段**：用来解释机制或支撑主张。
- **转折处**：用来从抽象转入具体。
- **异议处理处**：用来回答读者反驳。
- **结尾**：用来形成记忆点或行动理由。

案例必须服务主任务，不单独抢走内容主轴。故事有趣但无功能时，标为暂不使用。

## 严谨模式

用户明确要求真实、核查、来源、引用、合规或严肃论证时，再执行真实性规则：

- 真实历史事件写成确定事实时，标注“需要核验”或使用用户提供的可靠来源。
- 未联网时，历史故事只使用用户提供素材或常识级事实。
- 涉及具体年份、人物、机构、政策细节和因果判断时，标注“需要核验”，不要为了故事效果补细节。
- 当前行业信息、公司人物细节或数据判断交给 `$cflow-research`。
- 虚构、假设、未来预演和类比需要标注类型。
- 用户个人经历不擅自补关键事实。

严谨模式检查：

- 虚构故事是否被写得像真实案例。
- 未核验真实事件是否被写成已确认事实。
- 类比是否过度替代证据。
- 案例是否比主张更抢戏。
- 案例是否有趣但无功能。
- 案例是否和目标读者无关。
- 未来预演是否被写成确定预测。
- 是否为了戏剧性擅自补事实。

## 协作路由

`cflow-case` 只负责案例故事判断、设计和标注。继续执行时交给对应 skill：

| 需求 | 交给 |
|---|---|
| 需要真实来源、历史细节、当前事实、数据、人物或公司信息 | `$cflow-research` |
| 需要先澄清主张、读者、素材和交付形态 | `$cflow-interview` |
| 需要把案例压成角度、张力或主张 | `$cflow-angle` |
| 需要写进完整文章、教程、脚本或销售稿 | `$cflow-draft` |
| 需要压成短内容、微故事或短脚本 | `$cflow-shortform` |
| 需要处理 offer、异议、转化桥或客户故事转化 | `$cflow-marketing` |
| 需要标题、hook、opening 或发布包装 | `$cflow-package` |
| 需要判断案例是否能传播、截图或复述 | `$cflow-viral` |
| 需要判断发布后案例是否有效 | `$cflow-review` |
