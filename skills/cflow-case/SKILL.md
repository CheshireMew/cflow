# CFlow 案例故事

## 边界

负责为内容寻找或设计“能支撑观点的案例/故事素材”。不要替代 `$cflow-draft` 把案例写成完整正文。

案例必须服务一个具体主张。不要为了有趣而加入无功能故事。

## 工作流

1. **确定主张**：先明确案例要支撑什么观点、机制、情绪或转化动作。
2. **选择案例类型**：真实事件、个人经历、客户案例、行业案例、未来预演、假设故事、类比故事、反面案例或微场景。
3. **标注真实性**：明确是真实、待核验、虚构、假设、类比还是预测。
4. **筛选功能**：判断案例承担的是证据、解释、趣味、情绪、反差、记忆点、异议处理还是转化桥。
5. **生成候选**：给出多个不同策略的案例方向。
6. **评估风险**：检查是否牵强、过度戏剧化、无法核验、误导读者或偏离作者声音。
7. **交接生产**：需要写进正文时交给 `$cflow-draft`；需要角度化时交给 `$cflow-angle`；需要营销转化时交给 `$cflow-marketing`。

## 输出

返回：

- 要支撑的主张
- 推荐案例类型
- 案例候选
- 真实性标注
- 案例功能
- 为什么适合
- 使用风险
- 写入正文的建议位置

## 真实性规则

- 真实历史事件必须标注“需要核验”，除非用户已提供可靠来源。
- 当用户需要真实历史事件、当前行业案例、公司案例、人物案例、数据案例或近期事件时，正式资料搜寻和事实核查交给 `$cflow-research`。没有联网工具或来源不足时，必须标注“未联网验证 / 待核验”，不能把记忆中的细节写成事实。
- 编造故事必须标注“虚构 / 假设”，不能伪装成真实案例。
- 未来预演必须标注“预测 / scenario”，不能伪装成事实。
- 类比故事必须说明类比边界，避免把相似性当证据。
- 用户个人经历可以作为案例，但不能擅自补关键事实。
