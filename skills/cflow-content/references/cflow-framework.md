# CFlow 框架

## 任务类型

用这张表控制边界。

- **策略**：用户需要方向、内容栏目、节奏或可重复系统。
- **选题**：用户需要一个具体可做的内容对象。
- **对标**：用户需要找到、拆解或迁移值得参考的内容对象。
- **角度**：选题已存在，但阅读理由弱或泛。
- **Brief**：用户需要成稿前的生产计划。
- **草稿**：用户需要完整内容。
- **改稿**：用户想保留意图但改造已有草稿。
- **编辑**：用户需要诊断、清理或局部提升。
- **包装**：用户需要标题、hook、CTA、封面文案或平台变体。
- **复用**：用户要把一个素材变成多个格式。
- **复盘**：用户想知道哪里有效、哪里弱、下一步怎么做。

## Content Brief 合同

写较长草稿前先创建或推断：

```text
目标：
读者：
平台：
格式：
核心主张：
读者张力：
证据：
声音：
约束：
交付物：
```

只有当用户明确要求直接输出，且缺失信息可从上下文恢复时，才省略可见 brief。

## 内容质量门槛

进入 draft、package 或 marketing 前，先检查：

- **读者**：是否知道这条内容在对谁说？
- **收益**：读者看完得到什么，或少犯什么错？
- **冲突**：哪里和读者预期、行为或处境不一致？
- **素材**：是否有事实、案例、故事、数据、亲历、截图或可标注的假设？
- **证据路径**：核心主张靠什么支撑？
- **平台形态**：这条内容适合长文、短视频、图文、thread、newsletter 还是广告页？

缺少素材、证据或冲突时，不要用包装补洞。先给最小补足动作：

```text
当前缺口：
为什么会影响成稿：
最小补足动作：
补足后交给：
```

## 格式匹配

- 观点冲突、认知反差、强个人判断：适合短视频、thread 或社交帖。
- 工具清单、步骤、模板：适合图文、newsletter、blog。
- 深度拆解、方法论、系统复盘：适合长文、newsletter、blog 或长视频。
- 案例、数据、前后对比：适合图文、短视频、文章，也可交给 `$cflow-case` 扩展。
- 争议、异议、强互动问题：适合直播、评论区引导或社交帖。

平台选择要服务内容形态，不要因为平台流行就硬塞。

## 角度选择

可用角度通常至少包含一种机制：

- **矛盾**：大家以为是 X，但真正有用的是 Y。
- **代价**：这个错误正在消耗时间、信任、金钱或注意力。
- **转变**：从 A 走到 B 的具体机制。
- **区分**：两个看似相似的东西会带来不同结果。
- **场景**：一个具体事件揭示更大的规律。
- **决策**：在取舍中选择这条路，避开那条路。

拒绝只复述话题、模仿平台套路但没有实质，或依赖夸张确定性的角度。

## 草稿结构

选择一个结构，不要无必要地叠结构。

### 诊断型

```text
症状
错误诊断
根因
具体机制
应该怎么做
例子
收束句
```

### 实用指南型

```text
问题
常见建议为什么失败
原则
步骤
例子
常见陷阱
下一步动作
```

### 观点型

```text
主张
为什么现在重要
别人忽略了什么
推理
影响
反方观点
最终立场
```

### 故事到洞察型

```text
场景
张力
变化
洞察
可迁移经验
应用
结尾
```

## 编辑深度

选择能解决根因的最浅编辑级别。

- **Level 1 清理**：清晰度、语法、节奏、冗余。
- **Level 2 重排**：移动段落、修转场、加强开头和结尾。
- **Level 3 重构角度**：改变角度、主张或目标读者，同时保留素材。
- **Level 4 重写**：原结构无法承载目标，用素材重建。

诊断或大改时说明选择了哪一级。

## 声音保留

保留：

- 有个人感的原句
- 具体例子
- 有用的不确定感
- 自然的不平整
- 作者真实使用的领域词

删除：

- 泛泛鸡血
- 夸大主张
- 光滑但空的转场
- 重复抽象名词
- 平台套话
- 每段节奏过度对称的 AI 感

## 平台说明

调整结构，不改事实。

- **短视频**：重视口语节奏、即时张力、从场景到观点。
- **小红书/RED**：重视标题压力、具体利益、可扫读结构、生活细节。
- **LinkedIn**：重视职业张力、决策逻辑、实用收获、克制自信。
- **Twitter/X**：重视压缩、顺序推进、一条一个想法。
- **Newsletter/blog**：重视上下文、论证连续性、例子和长期价值。

## 终检清单

- 是否只有一个主张？
- 目标读者是否明显？
- 开头是否用真实张力换取注意力？
- 具体素材是否足够？
- 无证据主张是否被标记、软化或删除？
- 结构是否适合平台？
- 结尾是否说明发生了什么变化？
- 声音是否还像作者，而不是泛用助手？
