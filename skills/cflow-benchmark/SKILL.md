# CFlow Benchmark

## 边界

负责内容对标和可迁移模式拆解。

对标不是搬运。对标要拆出结构、机制、读者张力、篇幅密度和交付形态，再迁移到作者自己的领域、素材和声音里。

默认可以基于用户提供材料、截图、链接描述或离线样本做拆解。只有用户要求当前表现、来源包、事实核查或实时竞品现状时，资料搜集交给 `$cflow-research`。

## 工作流

1. 明确用户要对标的对象：账号、栏目、单篇内容、标题、封面、脚本、广告、CTA 或发布节奏。
2. 判断对标目的：找选题、学结构、学包装、学表达、学转化、学篇幅密度还是建立 swipe file。
3. 判断是否需要研究：只有用户要求实时查看当前页面、账号、SERP、广告、评论或表现信号时，才交给 `$cflow-research` 收集资料。
4. 筛选对标：优先选张力强、可拆解、可迁移、能刺激创作的对象。
5. 拆解颗粒度：选题、读者、角度、案例、结构、hook、说服动作、节奏、表达强度、CTA、评论反馈、发布频率。
6. 区分可迁移和不可迁移：默认大胆迁移机制、节奏、钩子、情绪和结构；用户要求严谨时再处理事实、经历、身份或数据边界。
7. 输出迁移方案：把可复用模式交给 `$cflow-topic`、`$cflow-angle`、`$cflow-case`、`$cflow-package`、`$cflow-image`、`$cflow-marketing` 或 `$cflow-voice`。
8. 如果用户只是想“更像某人”，先提醒：学习结构和判断，不复制人格。

## 输出

找对标时输出：

- 对标候选
- 为什么值得参考
- 适合学习的部分
- 不适合学习的部分
- 下一步拆解对象

拆解对标时输出：

- 对标对象
- 内容任务
- 读者和场景
- 核心张力
- 结构拆解
- 包装策略
- 说服动作和案例
- CTA 或转化路径
- 可迁移模式
- 可迁移边界
- 联网状态
- 交接到哪个 CFlow skill

颗粒度检查时输出：

- 已对齐部分
- 没对齐部分
- 差异是否有理由
- 需要马上修的差异
- 可以保留的作者差异
