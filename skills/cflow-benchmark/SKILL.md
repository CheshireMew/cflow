# CFlow Benchmark

## 边界

只负责内容对标和可迁移模式拆解。不要替代 `$cflow-topic` 生成完整选题池，不要替代 `$cflow-draft` 写成稿，不要替代 `$cflow-marketing` 设计完整销售漏斗。

对标不是搬运。对标要拆出结构、机制、读者张力和平台适配，再迁移到作者自己的领域、素材和声音里。

当对标依赖当前账号、页面、SERP、广告、评论、平台表现或竞品现状时，优先联网查看真实对象。没有联网工具或用户未提供链接/截图时，只能做离线拆解假设，不能声称当前对标表现如何。

## 工作流

1. 明确用户要对标的对象：账号、栏目、单篇内容、标题、封面、脚本、广告、CTA 或发布节奏。
2. 判断对标目的：找选题、学结构、学包装、学表达、学转化、学平台机制还是建立 swipe file。
3. 判断是否需要联网：当前页面、账号、SERP、广告、评论或表现信号需要实时查看。
4. 筛选对标：优先选同目标读者、同平台、同内容任务、可观察表现强、可拆解、可迁移的对象。
5. 拆解颗粒度：选题、读者、角度、案例、结构、hook、证据、节奏、voice、CTA、评论反馈、发布频率。
6. 区分可迁移和不可迁移：能学机制，不复制事实、经历、身份、客户案例或不可验证数据。
7. 输出迁移方案：把可复用模式交给 `$cflow-topic`、`$cflow-angle`、`$cflow-case`、`$cflow-package`、`$cflow-marketing` 或 `$cflow-voice`。
8. 如果用户只是想“更像某人”，先提醒：学习结构和判断，不复制人格。

## 输出

找对标时输出：

- 对标候选
- 为什么值得参考
- 适合学习的部分
- 不适合学习的部分
- 下一步拆解对象

拆解对标时输出：

- 对标对象
- 内容任务
- 读者和场景
- 核心张力
- 结构拆解
- 包装策略
- 证据和案例
- CTA 或转化路径
- 可迁移模式
- 不可迁移风险
- 联网状态
- 交接到哪个 CFlow skill

颗粒度检查时输出：

- 已对齐部分
- 没对齐部分
- 差异是否有理由
- 需要马上修的差异
- 可以保留的作者差异
