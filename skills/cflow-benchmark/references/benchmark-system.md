# 内容对标系统

## 共享合同

对标拆解和迁移受 `$cflow` 的 `references/content-production-contract.md` 约束。本文件只维护对标筛选、copywork 颗粒度和可迁移机制。学到的通用写作规则要回到共享合同或对应专项 skill，不在对标中另立规则。

## 对标筛选

优先选择这些对标：

- 面向相近读者。
- 篇幅和交付形态相近。
- 内容任务相近：教育、观点、故事、转化、复盘、招募、品牌。
- 表现强且有可观察信号：阅读、互动、评论、转发、收藏、转化、持续更新。
- 能看懂结构，不只看见表面风格。
- 有可迁移模式；身份、资源、历史红利或不可复制事件也可以先作为灵感来源，之后再迁移成自己的机制。

不要只因为粉丝多就对标。粉丝量不是内容机制。

## 联网研究规则

用户要求当前表现、来源核查或实时竞品现状时，这些信息由 `$cflow-research` 联网搜集，或由用户提供链接/截图：

- 当前账号内容、栏目、资料结构和发布时间。
- 当前 SERP、广告、搜索结果类型和 AI answer。
- 评论区反馈、互动信号和可见转化路径。
- 竞品页面、landing page、价格、offer 和 CTA。
- 当前发布环境、热榜、趋势和内容形态。

用户要求当前表现或来源核查但不能联网时，输出标注：

```text
联网状态：未联网验证
当前判断性质：离线假设 / 基于用户材料
需要补充：
```

默认 copywork 和结构拆解可以离线完成；只有用户要求当前发布环境事实时，才需要这条限制。

## 内容研究系统

不要把内容研究理解成偶尔刷到灵感。持续做内容的人需要建立 swipe file 或对标档案，定期收集同读者、同任务、高表现且可拆解的内容样本，再把样本拆成可迁移机制。平台、工具、过滤器和互动阈值只是操作方式，不进入通用规则；判断重点是样本是否能说明读者行为和内容机制。

内容研究流程：

1. 明确研究目的：找选题、hook、结构、传播单元、CTA、栏目模式还是账号承接。
2. 选择样本范围：同读者、同交付形态、同内容任务，或相邻领域中机制可迁移的样本。
3. 记录可观察信号：阅读、互动、评论、收藏、转发、转化、持续更新或用户提供的表现证据。
4. 拆解内容动作：选题、读者、hook、结构、情绪、证明动作、CTA、传播单元和账号承接。
5. 迁移到用户自己的素材、声音、栏目和转化路径，不复制表面格式、身份或平台红利。

内容研究输出至少区分：

```text
可直接学习的机制：
只能作为灵感的部分：
不可复制的条件：
可进入选题池 / hook 库 / 传播单元 / CTA 资产的内容：
下一次如何验证：
```

### 爆款创意变量组合

追求爆款时，不要只复制单条内容表面。先把高表现样本拆成变量，再重新组合到用户自己的领域、素材、声音和品牌资产里。常用变量：

```text
主题：读者已经关心什么？
Hook：第一眼如何呈现这个主题？
Angle：用什么张力、框架、错误、发现、清单或故事讨论它？
可信度：为什么读者应该信这条内容？
```

数据库质量决定创意质量。进入变量库的样本至少要说明：它吸引的是不是目标读者、完成的是什么内容任务、表现信号是否可观察、机制是否能拆解、是否仍有新鲜度。样本可以来自任意平台或离线材料；平台路径、固定点赞门槛和具体工具操作不写成规则。

组合输出时必须区分：

```text
已验证变量：
当前用户可用素材：
需要补充或核验的可信度：
不可复制的身份 / 资源 / 时机：
组合后的创意：
预计承接到哪个栏目 / CTA / 后续内容：
```

如果组合依赖名人、专家、数据、成果或历史事实，先判断这些信息是否由用户提供且真实相关；需要外部核查时交给 `$cflow-research`，不要为了借用权威直接把人物、数字或案例写进当前内容。

## 五重过滤

| 筛子 | 问题 | 淘汰信号 |
|---|---|---|
| 读者是否相近 | 对方吸引的人是不是你也想吸引的人？ | 受众完全不同 |
| 任务是否相近 | 对方内容在完成什么任务？ | 对方做娱乐，你做转化 |
| 机制是否看得懂 | 你能说清它为什么有效吗？ | 只能说“感觉好” |
| 素材是否可迁移 | 能否迁移成自己的机制、节奏、钩子或情绪？ | 完全无法变形 |
| 篇幅是否匹配 | 篇幅密度和交付形态是否一致？ | 把短内容逻辑硬搬到长文 |

过不了五重过滤的对标，不进入深拆。

## 样本形态剖面

对标对象涉及风格、短内容、账号表达、copywork 或模仿时，先做低成本形态剖面，再抽象机制。形态剖面不是为了复制表面，而是防止把短内容拆成报告、把口语表达改成咨询分析、把样本没有的结构硬套进去。

至少记录：

- 篇幅范围。
- 段落数或行数。
- 是否有标题。
- 是否使用清单、编号、表格。
- 开头类型。
- 结尾方式。
- 常见连接词。
- 具体信息密度。
- 明显禁用形态。

如果样本里没有某种形态，例如标题、行首清单、编号论证、总结段或报告小节，不要在迁移时默认加入。只有用户要求、目标平台需要，或内容任务确实需要时，才改变形态，并说明这是有意改造，不是对标对象本身的模式。

## 成功模型拆解

拆解创作者、账号、栏目或商业化内容系统时，不要把对方的成功压缩成“照着做这套流程”。先分离不同来源：

- **内容机制**：选题、结构、hook、节奏、案例、CTA 和复用流程。
- **人格和声音**：价值判断、表达强度、叙事姿态、读者关系。
- **视觉和听觉包装**：第一眼识别、视觉锚点、剪辑节奏、声音提示和认知负荷控制。
- **商业验证**：受众是否有支付意愿、offer 是否被验证、转化路径是否闭合。
- **执行能力**：更新频率、深度工作、生产系统和工具熟练度。
- **时机红利**：发布环境阶段、赛道窗口、身份稀缺、历史事件或早期入场优势。

迁移时只迁移可复用机制。时机红利、个人魅力、已有信任、私人经历和不可复制资源只能作为风险提示或启发，不能写成用户照做即可获得同等结果的规则。

## Copywork 颗粒度

copywork 不是泛泛总结。至少拆到这些层：

- 选题：为什么是这个题，不是更大的话题？
- 读者：标题和正文分别筛选了谁？
- Hook：第一眼或开头用什么张力留人？
- 结构：每一段/每一镜在推进什么？
- 说服动作：用数据、故事、场景、对比、权威还是情绪推动？
- 节奏：哪里快、哪里慢、哪里转折？
- 语言：哪些句子服务表达强度，哪些服务篇幅效率？
- CTA：下一步行动被放在什么时机？
- 传播单元：哪些句子、截图段、清单、模板或站队点能被读者带走？
- 账号承接：这条内容如何让读者记住作者、栏目、主页入口、后续内容或转化路径？

如果只能得到“结构清晰、观点犀利、情绪到位”，说明拆得太粗。

## Prompt 化迁移

当用户想把对标对象变成可重复工作流、AI prompt、SOP 或团队生产方法时，先完成 copywork，再转成执行资产。不要直接让 AI 模仿对标对象。

Prompt 化迁移至少拆成两段：

1. **结构指南**：这类内容如何选题、开头、推进、制造张力、使用案例、收尾和 CTA。
2. **上下文采集**：执行前需要从创作者那里问到哪些信息，例如领域、目标读者、核心立场、素材、案例、禁用表达、篇幅目标和行动目标。

输出 prompt 或 SOP 时必须包含：

- 要迁移的机制，而不是要复制的表面风格。
- 需要采访用户的问题。
- 输入素材的边界。
- 生成变体的数量、类型和约束。
- 如何检查是否仍然属于作者自己的领域、素材和声音。

如果拆解结果要写短内容，交给 `$cflow-shortform`；要做标题、hook 或开头，交给 `$cflow-package`；要校准作者声音，交给 `$cflow-voice`。`$cflow-benchmark` 只维护对标机制和 prompt 化迁移方法。

## 迁移规则

- 学机制、节奏、张力和情绪；用户要求严谨时再区分事实边界。
- 学结构，也可以学习人格化表达；用户要求原创性审查时再处理人格边界。
- 学读者切法，不冒充身份。
- 学证明位置和说服动作；用户要求事实核查时再处理证据来源。
- 学 CTA 时机，不硬套 offer。
- 学篇幅节奏，默认优先提高表现力；用户要求 voice 时再保留作者声音。

迁移方案必须明确区分：

```text
可以学习：
- 切入方式
- 读者筛选
- 节奏和篇幅密度
- 信息选择
- 证明动作
- 情绪强度
- 结构机制

不要学习：
- 私人身份
- 不可复制资源
- 未验证经历
- 目标作者没有的语气
- 样本没有的结构形态
- 只属于单次热点或平台窗口的表面写法
```

这个区分用于防止整包搬运。可迁移机制要交给对应 CFlow skill 执行；不可迁移表象只能作为风险提示、反例或需要用户补充的素材缺口。

迁移输出要明确交给哪个 CFlow skill：

| 学到的东西 | 交给 |
|---|---|
| 选题模式、栏目 | `$cflow-topic` |
| 核心冲突、主张 | `$cflow-angle` |
| 案例类型、故事功能 | `$cflow-case` |
| 标题、hook | `$cflow-package` |
| 封面、插图、配图、thumbnail text、视觉 brief | `$cflow-image` |
| CTA、offer、转化桥 | `$cflow-marketing` |
| 作者表达差异 | `$cflow-voice` |
| 复用经验 | `$cflow-review` |

## 严谨模式检查

- 对标对象只是流量大，但和目标读者不一致。
- 只抄标题，不理解正文兑现方式。
- 只抄人设，不理解内容任务。
- 用户要求原创性或严谨审查时，把对方私人经历当成可复制素材。
- 用户要求发布环境事实判断时，把短期红利当成内容能力。
- 用户要求 voice 时，对标太多导致作者声音被磨平。
- 拆解停在评价层，没有产出可执行迁移动作。
