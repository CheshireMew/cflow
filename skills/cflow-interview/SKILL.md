# CFlow Interview

## 边界

`cflow-interview` 负责写作前澄清、采访、讨论、追问缺失信息、整理当前写作任务内素材，并生成可交接的 content brief。

它不写最终草稿，不替代 `$cflow-topic` 评估选题，不替代 `$cflow-angle` 生成最终主张，不替代 `$cflow-research` 联网查资料，不替代 `$cflow-voice` 建立作者声音画像，不替代 `$cflow-asset` 提取旧笔记和个人知识资产。

当用户只有模糊写作想法、当前内容素材、经历片段、业务目标或“想写但说不清”时，先进入 interview。目标是先问出稳定写作合同，而不是马上生产正文。

当用户提供的是长期旧笔记、日记、manifest、个人知识库导出或混合记录，并要求“提取有用信息、信息资产化、沉淀个人原则、整理风险和开放问题”时，交给 `$cflow-asset`。不要把这类任务误当成写作前 interview。

当用户提供外部 sponsor brief、项目推广 brief、合作邀约或品牌资料，但交付形态、篇幅、联网范围、作者身份、核心角度或表达强度开放时，也先进入 interview。不要把长 brief 的完整性误判成稳定写作合同。

当用户带着读者评论、发布结果或内部反馈回来，目标是做下一篇内容的素材收口，Interview 可以接；目标是判断内容为什么有效或无效、提炼长期机制，则交给 `$cflow-review`。

## 工作流

1. **识别输入状态**：判断用户给的是写作想法、经历片段、业务目标、当前写作素材、草稿前构思、空白讨论、反馈回收还是 sponsor / 项目 brief。
2. **盘点已知信息**：目标、读者、篇幅、交付形态、发布约束、主题、素材、主动作、表达强度和事实边界。
3. **识别缺口**：读者不清、目标不清、素材不足、主张不清、冲突不清、篇幅不清、CTA 不清、事实待查、声音不明。
4. **选择追问模式**：快速采访、深度采访、主题探索、元问题模式、写作任务内素材盘点或 sponsor / 项目 brief 收口。
5. **优先追问关键缺口**：不要一次问完所有问题；先问会改变后续方向的 1 到 3 个问题。
6. **提炼可用素材**：保留用户原话、具体经历、判断、例子、反感点、限制条件和可放大细节。
7. **生成交接 brief**：整理成可交给下游 skill 的轻量合同，并标明缺口和建议下一步。

## 输入状态

| 输入状态 | 判断方式 | Interview 的任务 |
| --- | --- | --- |
| 模糊想法 | 只有一个方向、主题词或想写的感觉 | 找出目标、读者、可能选题和关键缺口 |
| 经历片段 | 有故事、过程或个人判断，但还没形成内容对象 | 追问事件、判断、代价、冲突和可用细节 |
| 业务目标 | 想招生、成交、引流、解释产品或建立信任 | 收口转化目标、读者状态、offer / CTA 和表达强度 |
| 当前写作素材 | 为一篇内容、一次发布或一个营销稿准备的笔记、链接、截图、转录、评论、数据、案例 | 做素材盘点，区分事实、判断、故事、缺口和待核查项 |
| 草稿前构思 | 大概知道写什么，但缺结构和主张 | 收口目标、读者、主张候选和下游交接 |
| 空白讨论 | 用户想先聊，暂时不知道产物是什么 | 用少量问题帮用户发现真正要解决的写作任务 |
| 反馈回收 | 用户带着评论、发布结果或内部反馈回来想再做内容 | 把反馈转成下一篇内容素材；长期机制复盘交给 `$cflow-review` |
| Sponsor / 项目 brief | 外部资料很多，但交付合同仍开放 | 收口作者角度、任务边界、事实缺口和表达强度 |

不同输入状态决定追问方式。不要把所有模糊输入都直接推给 `$cflow-topic` 或 `$cflow-draft`。

## 追问模式

### 快速采访

适合用户目标比较清楚，只缺少少量关键信息。

优先问：

```text
这次内容给谁看？
读者看完要改变什么判断或做什么动作？
必须保留哪些素材或限制？
```

### 深度采访

适合用户有经历、观点、业务判断或复杂案例，但还没有说清楚。

追问方向：

- 具体发生了什么？
- 当时你为什么这样判断？
- 哪个细节最能说明问题？
- 你反感外界怎么误解这件事？
- 如果读者只记住一句话，你希望是什么？
- 这件事背后的代价、冲突或取舍是什么？
- 有没有一个能证明这个判断的场景、对话、截图、动作或结果？

### 主题探索

适合用户只有大方向，还没确定写什么。

追问方向：

- 这个方向里你最近反复遇到什么问题？
- 哪类读者最需要听这个？
- 哪个常见说法你觉得不对？
- 最近有没有一个小事件能代表这个问题？
- 你想解释、说服、吐槽、教学、转化还是复盘？

### 元问题模式

适合用户知道学习方向、内容方向或业务目标，但不知道该问什么、该补什么信息。

处理方式：

- 先生成 8 到 12 个可继续追问的问题，不直接写正文或完整大纲。
- 按目标、读者、素材、事实、结构、交付形态和行动缺口分组。
- 每组问题都说明它能消除什么不确定性。
- 用户选定问题或补充回答后，再整理 content brief 或交给对应下游 skill。

元问题的价值是暴露缺口，不是展示提问框架。不要把外部 prompt 框架名录写进 brief；只保留这次任务真正需要补齐的信息。

### 写作任务内素材盘点

适合用户为当前写作任务给了很多材料，但没有整理。它的终点是 content brief，不是个人知识库、原则库或长期资产库。

整理顺序：

1. 原始事实或素材。
2. 用户自己的判断。
3. 可用故事、场景和例子。
4. 可做 hook 的冲突或代价。
5. 需要核查或补充的外部事实。
6. 不应该混进正文的推测。

如果用户给的是旧笔记、日记、manifest、长期素材库或混合个人记录，并且目标是“提取有用信息、沉淀资产、看出个人倾向、整理原则和风险”，交给 `$cflow-asset`。

### Sponsor / 项目 Brief 收口

适合用户提供外部 sponsor brief、项目推广 brief、合作邀约、品牌资料、产品资料或活动资料，但还没有稳定写作合同。

项目方 brief 完整不等于作者写作合同完整。只要作者身份、发布形态、表达强度、核心角度或 sponsor 味道强度仍开放，就必须先问 1 到 3 个会改变正文的问题。不要把用户给的项目资料重新整理一遍当成交付。

先收口：

- 项目方或品牌方真正想达成什么。
- 作者自己要让读者记住什么判断。
- 项目是正文主角、证明材料、案例，还是只是背景。
- 交付形态、篇幅、发布位置、截止时间和不能碰的限制。
- 哪些是用户已确认事实，哪些需要 `$cflow-research` 核查。
- 是否有 offer、CTA、私信、购买、预约、报名或领取动作。
- 表达强度是通稿、作者判断、软广、硬广、教程、复盘还是品牌内容。

不要因为外部 brief 很长就直接进入 `$cflow-draft`。合同不稳时，目标看似明确也只能先追问；只有写作合同稳定后，才整理 content brief 或交给成稿。

## 追问纪律

- 每轮最多问 1 到 3 个关键问题。
- 先问会改变方向的问题，不问装饰性细节。
- 不为了完整表格打断用户表达。
- 用户已经给出足够信息时，停止追问，直接整理 content brief。
- 外部 sponsor brief 很完整时，仍要检查作者身份、发布形态、表达强度和核心角度；缺一项且会改变正文，就先问，不整理项目 brief。
- 用户表达混乱时，先复述你听到的判断，再问缺口。
- 不把用户临时口误、犹豫和半句话抛光掉；这些可能是作者声音或真实判断线索。
- 需要外部事实、来源或最新信息时，标记为待 `$cflow-research`，不要在 brief 阶段假装已核查。

## 写作合同

交接给下游 skill 时尽量整理成：

```text
目标：
目标读者：
篇幅：
交付形态：
发布约束：
主题 / 选题：
核心主张候选：
读者张力：
可用素材：
必须保留的原话：
主动作 / CTA：
表达强度：
事实边界：
声音线索：
缺失信息：
建议下一步 skill：
```

不是每次都要填满。缺项要标注，不要用想象补成事实。

## 交接判断

| 状态 | 下一步 |
| --- | --- |
| 方向太泛，还需要判断写什么 | `$cflow-topic` |
| 有题但缺主张、张力或 premise | `$cflow-angle` |
| 缺真实例子、证明故事、反面案例或场景 | `$cflow-case` |
| 写作合同稳定、素材明确，需要完整一稿 | `$cflow-draft` |
| 已经有草稿，需要诊断或重写 | `$cflow-edit` |
| 有 offer、CTA、funnel 或转化路径问题 | `$cflow-marketing` |
| 需要标题、hook、开头、CTA 或短发布文案 | `$cflow-package` |
| 需要来源、事实核查、最新资料或证据包 | `$cflow-research` |
| 用户反复强调“不像我”“帮我保持我的味道” | `$cflow-voice` |
| 旧笔记、manifest 或混合个人记录需要信息资产化 | `$cflow-asset` |
| 已发布内容、评论、指标或失败草稿需要提炼长期机制 | `$cflow-review` |

## 输出协议

需要继续追问时输出：

```text
当前判断：
已知信息：
最大缺口：
追问问题：
为什么先问这些：
```

整理 content brief 时输出：

```text
当前判断：
已知信息：
可用素材：
缺失信息：
内容 brief：
建议交接：
```

如果用户只是想先聊，不要强行输出完整 brief；先用最少问题推进到可判断状态。

## 常见错误

- 用户说“想聊聊”，立刻写草稿。
- 把旧笔记信息资产提取误当成写作前 interview。
- 把发布表现复盘误当成单篇素材盘点。
- 一次问十几个问题，让用户变成填表。
- 只问篇幅、字数、格式，不问读者处境和主张。
- 把采访得到的推测写成事实。
- 把 content brief 写成大纲，过早决定结构。
- 把用户的真实判断磨成中性总结。
- 外部 sponsor brief 很长时，跳过作者角度和合同收口。
- 下游交接不清，导致 `$cflow-draft` 重新猜目标。
