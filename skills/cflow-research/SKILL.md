# CFlow Research

## 边界

负责“搜寻资料、核查事实、评估来源、整理证据”。

研究结果必须服务内容任务。不要为了“资料更全”无限扩展。先明确要支持哪个主张、选题、案例、竞品判断、SEO brief 或营销判断。

研究前先判断资料用途，不默认把一手文档、API 文档或权威事实当成最优结果。普通介绍文章、观点文章、工具发现、工作流复盘和创作者内容，优先寻找能帮助读者进入的材料：真实使用场景、外部案例、社区讨论、相似工作流、读者痛点、反方经验和可复述的故事。技术文档只用于校验关键事实，不得抢走文章主线。

`$cflow-research` 只在研究任务被触发时工作。用户只是要求成稿、改稿、包装或营销文案时，不因为素材里出现产品、价格、活动、政策、时间节点或公司信息就自动联网。

触发研究后，如果需要实时信息、外部事实、数据、人物、公司、产品、政策、价格、趋势、历史事件、竞品现状或来源引用，优先使用当前环境可用的联网工具。没有联网能力时，明确标注“未联网验证”，并请求用户提供来源或允许基于已有材料做离线研究。

## 工作流

1. **定义研究任务**：事实核查、背景研究、案例搜寻、数据搜寻、来源包、引用包、竞品资料、趋势扫描、读者兴趣材料、外部使用案例或反方证据。
2. **确定研究问题**：把模糊请求改写成 1 到 3 个可搜索、可验证的问题。
3. **选择来源层级**：先按资料用途选择来源。事实核查优先官方/一手资料；普通内容参考优先真实案例、社区使用场景、用户问题、实践文章和能支撑读者张力的材料，再用一手资料校验定义和边界。
4. **执行搜索和核查**：使用联网工具或用户提供材料；关键事实尽量交叉验证。
5. **分层记录**：区分已确认事实、来源观点、真实使用场景、读者痛点、合理推测、争议点、未核查项和不可用材料。
6. **整理证据包**：只保留能服务内容任务的资料，标注来源、时间、可信度和用途。资料如果只能证明“技术上存在”，但不能帮助文章更好读、更可信或更想收藏，应压缩为背景校验，不放进主证据。
7. **交接给生产 skill**：案例交给 `$cflow-case`；成稿交给 `$cflow-draft`；对标交给 `$cflow-benchmark`；SEO/GEO 结构交给 `$cflow-seo`；转化证据交给 `$cflow-marketing`。

## 输出

默认输出：

- 研究问题
- 联网状态
- 已确认事实
- 关键来源
- 可用证据
- 争议或不确定点
- 不建议使用的材料
- 仍需核查
- 交接建议

事实核查输出：

- 原说法
- 判断：支持 / 部分支持 / 不支持 / 无法确认
- 依据
- 反证或限制
- 可安全写法

案例搜寻输出：

- 主张
- 案例候选
- 来源状态
- 为什么适合
- 风险
- 交给 `$cflow-case` 的建议

## 来源标注

研究输出必须标注：

```text
联网状态：已联网核查 / 用户提供来源 / 未联网验证
来源等级：一手 / 权威二手 / 普通二手 / 社媒信号 / 未知
时间敏感性：高 / 中 / 低
仍需核查：
```

不要把未核查信息写成事实。查不到就说查不到。
