# 资料研究系统

## 研究任务类型

| 类型 | 目标 | 输出 |
|---|---|---|
| 事实核查 | 判断一个说法是否成立 | 支持/部分支持/不支持/无法确认 |
| 背景研究 | 快速理解话题、人物、公司、事件 | 背景摘要和关键来源 |
| 案例搜寻 | 找能支撑主张的真实案例 | 案例候选和来源状态 |
| 数据搜寻 | 找数据、指标、报告、统计 | 数据点、口径、来源 |
| 来源包 | 为内容准备引用材料 | source pack |
| 反方证据 | 找反例、限制、争议 | 风险和边界 |
| 趋势扫描 | 看近期变化和信号 | 当前状态和不确定性 |
| 竞品资料 | 收集竞品页面、广告、评论、价格 | 资料包，深拆交给 `$cflow-benchmark` |

## 来源优先级

优先级从高到低：

1. **官方/一手资料**：政府、公司官网、原始公告、公开财报、原始论文、原始数据、当事人公开声明。
2. **专业资料**：学术论文、行业报告、数据库、标准文件、专业机构。
3. **权威媒体**：有编辑流程和事实核查能力的媒体。
4. **普通二手资料**：博客、百科、行业文章、播客整理。
5. **受众信号**：评论、帖子、论坛、影音内容、用户反馈。
6. **未知来源**：无法确认出处的截图、转述、搬运内容。

不同任务允许不同来源。写历史事实、政策、价格、产品、人物和公司信息时，优先一手或权威来源。研究情绪、舆论、用户语言时，社媒信号可以有价值，但不能当事实结论。

## 交叉验证

关键事实尽量满足：

- 至少两个独立来源互相支持。
- 时间敏感信息检查发布日期。
- 数据要看口径、样本、地区、时间范围。
- 历史事件要避免单因果简化。
- 公司/产品/价格/政策以官方或近期来源为准。

如果只能找到单一来源，要标注：

```text
来源数量：单一来源
风险：需要进一步确认
安全写法：
```

## 事实分层

研究记录不要混写。按层级整理：

- **已确认事实**：来源可靠，能直接使用。
- **来源观点**：某个作者、媒体、报告的判断，不等于事实。
- **合理推测**：基于材料的推断，需要标注。
- **争议点**：来源之间不一致或解释不同。
- **未核查项**：还没找到可靠来源。
- **不可用材料**：来源弱、过时、断章取义或与任务无关。

- ...

## Fact Check 格式

```text
原说法：
判断：支持 / 部分支持 / 不支持 / 无法确认
依据：
反证或限制：
时间敏感性：
安全写法：
来源：
仍需核查：
```

## 搜索纪律

- 先明确研究问题，再搜索。
- 搜索词要覆盖同义词、英文/中文、官方名称、时间范围。
- 优先打开原始来源，不只看搜索摘要。
- 对近期信息，检查发布日期和更新日期。
- 对数据，记录口径，不只摘数字。
- 对案例，记录真实性和可迁移边界。
- 对争议议题，主动找反方或限制条件。
- 查不到时停止编造，输出“无法确认”。

## 交接规则

| 研究结果 | 交给 |
|---|---|
| 可写成故事的案例 | `$cflow-case` |
| 可支持草稿的证据包 | `$cflow-draft` |
| 竞品页面和对标资料 | `$cflow-benchmark` |
| 搜索意图、关键词、SERP 结构 | `$cflow-seo` |
| 转化证明、客户证据、市场资料 | `$cflow-marketing` |
| 发布后数据和反馈 | `$cflow-review` |

交接时不要只给链接。要说明每个来源能支持什么、不能支持什么。
