## 账号当前任务

账号不只是 Crypto / AI 信息发布，更像一个高密度信息加工账号：

- 用爆款内容承担 reach。
- 用权威视频、商业故事和技术趋势建立 trust。
- 用工具、资源、教程和清单制造 save / share。
- 用 Web3 入门、社群、频道、Substack、博客和交易所链接承接 conversion。

当前最大风险是：reach 内容、trust 内容、save 内容和 conversion 内容没有分层发布，导流帖和链接帖容易污染主时间线的表现判断。

## 栏目职责

### Reach 栏目：视觉奇观 / 历史见闻

任务：拉新、破圈、扩大陌生曝光。

典型内容：

- 巨物、罕见照片、历史日常、世界见闻、强视觉反差。

使用方式：

- 只承担 reach，不强行导流。
- 后续用主页、置顶或相邻内容承接，不在正文里塞多个入口。
- 第一张图 / 第一条必须兑现首屏承诺。

风险：

- 泛人群强，关注转化可能低。
- 如果后续账号承接不清，爆款只带来一次性浏览。

### Trust 栏目：高赌注商业故事 / 大师课 / 权威视频

任务：建立判断力、筛选力和账号品味。

典型内容：

- 创始人反转、公司兴衰、投资大师演讲、罕见访谈、历史节点。

使用方式：

- 不只讲名人和大数字，必须落到一个可迁移机制。
- 适合接轻 CTA：长文版、频道更新、收藏观看。
- 这是把泛流量转成账号关系资产的主栏目。

风险：

- 过度依赖马斯克、巴菲特、达利欧等人物光环，会让读者记住素材而不是记住账号判断。
- 如果只做翻译和摘要，账号信任会停留在信息搬运层。

### Save 栏目：工具 / 资源 / 教程清单

任务：收藏、转发、复访和低摩擦信任。

典型内容：

- 工具列表、网站合集、搜索技巧、课程频道、AI / Mac / iPhone / Web3 教程。

使用方式：

- 每条必须说明替读者省掉什么成本。
- 清单要有筛选标准和使用场景，不只堆链接。
- 适合承接到博客、Substack、教程或频道，但主内容要先完整交付。

风险：

- 如果核心内容变成“去某处领取”，互动会下降。
- 链接过多会让内容从资源交付变成导流广告。

### Authority 栏目：AI / 科技趋势

任务：证明账号能解释新变化，而不是只搬运旧资料。

典型内容：

- AI 水印、模型能力、开源工具、技术趋势、平台变化。

使用方式：

- 用“变化 -> 后果 -> 判断”结构。
- 先讲普通读者、创作者、投资者或工具用户会受到什么影响。
- 可交给 `complex-change-shortform-translation.md` 和 `authority-megatrend-signal.md` 等资产生产。

风险：

- 如果只有专家引用或观点摘录，缺少后果翻译，容易低互动。
- AI 热点不等于账号定位，必须回到读者任务。

### Core 栏目：Crypto / Web3 / 交易

任务：服务账号商业和私域基本盘。

典型内容：

- Web3 入门、交易所、钱包、安全、交易、加密故事、链上事件。

使用方式：

- 不要把 core 栏目全部写成硬导流。
- 优先做“新手避坑、工具链、真实案例、风险解释、路径教学”。
- 转化动作分层：入门教程 > 交流群 / 频道 > 交易所链接。

风险：

- 当前数据里 Crypto / Web3 直接内容均值弱，说明它更适合作为承接和信任深化，不宜直接承担大规模 reach。
- 交易所链接如果前置太重，会压低互动和账号观感。

### Conversion 栏目：导流 / 链接推广

任务：承接，而不是拉新。

典型内容：

- Telegram 群、频道、Substack、博客、GitBook、Binance、OKX、商务合作。

使用方式：

- 单篇默认最多一个主引流动作。
- 平台不适合放链接时，用主页简介、置顶、评论关键词或私信关键词。
- 导流内容应嵌入对应栏目，不独立高频刷屏。

风险：

- 纯链接帖互动极弱，会拉低时间线质量。
- 如果连续发布，会让老读者感到账号从信息交付变成流量回收。

## 栏目组合判断

建议把账号内容分成三层，而不是所有内容在同一层竞争：

```text
破圈层：视觉奇观 / 历史见闻 / 高赌注故事
信任层：大师课 / 权威视频 / AI 科技趋势 / 商业机制拆解
承接层：工具清单 / Web3 教程 / 社群频道 / 博客 Substack / 交易所链接
```

发布时先判断内容属于哪一层。不同层用不同指标评估：

- 破圈层看 reach、关注转化、主页访问。
- 信任层看收藏、转发、评论质量、复访。
- 承接层看链接点击、私信、进群、订阅、注册。

不要用导流帖的点赞判断转化价值，也不要用视觉奇观的浏览判断账号信任。

## 当前根因假设

主因：近期发布量上升，但内容目标混杂，导流、链接、短评论和资源入口变多，削弱了时间线的信息交付感。

次因：

- 栏目之间缺少固定承接关系，爆款后的新读者不知道关注后稳定得到什么。
- Crypto / Web3 商业基本盘直接承担 reach 的能力弱，应该更多作为信任深化和转化承接。
- 资源清单如果没有筛选标准和使用场景，容易从“省读者成本”退化成“链接堆叠”。

证据不足的假设：

- 是否存在平台限流、跨语言分发变化或算法周期变化，当前文件不能证明。
- 哪些内容带来关注、私信、订阅、注册，当前文件没有转化数据。
- 图片 / 视频质量对爆款贡献多大，当前文本文件不能完整判断。

## 30 天实验

主假设：账号表现下滑不是单条内容不会写，而是栏目任务混杂和导流前置导致主时间线交付感下降。

目标：恢复高信息密度账号心智，同时让转化动作从内容后自然发生。

内容配比：

- 40% Trust：高赌注商业故事、大师课、权威视频、AI / 科技趋势。
- 30% Save：工具、资源、教程、清单。
- 20% Reach：视觉奇观、历史见闻、强视觉反差。
- 10% Conversion：Web3 入门、社群、频道、博客、交易所链接。

共同约束：

- 每条内容先判断所属栏目和主任务。
- 单篇最多一个主 CTA。
- 资源清单必须有筛选标准和使用场景。
- 商业故事必须落到一个可迁移机制。
- AI / 科技趋势必须写出普通读者的具体后果。
- 纯链接帖降级，不作为主时间线常规内容。

观察指标：

- Reach 栏目：浏览、关注转化、主页访问。
- Trust 栏目：转发、收藏、评论质量、复访。
- Save 栏目：收藏、转发、后续打开或私信索取。
- Conversion 栏目：链接点击、进群、订阅、注册、商务询问。

记录方式：

- 每条记录栏目、主任务、CTA、素材来源、生产成本。
- 每周只复盘同栏目 Top 3 和 Bottom 3，不全量平均比较。
- 单独标记导流帖，不和内容帖混算均值。

停止条件：

- 连续两周同栏目均无有效互动，先换包装或角度；仍无改善再降级栏目。
- 转化帖连续低互动但有高转化，不停止，只改发布位置和频率。
- 破圈帖高浏览低关注时，优先修主页、置顶和后续承接。

复盘时间：30 天后按栏目分桶复盘，不直接看总赞均值。

## 调用规则

后续内容生产前，先问：

```text
这条内容属于哪一层：破圈、信任、保存、承接？
它的主指标是什么？
它替读者省了什么成本？
它是否有足够素材兑现 hook？
它是否需要 CTA？如果需要，只接一个什么动作？
```

如果任务是：

- 选题池：交给 `$cflow-topic`。
- 首屏和标题：交给 `$cflow-package`。
- 短帖和 thread：交给 `$cflow-shortform`。
- 商业故事补机制：交给 `$cflow-case`。
- 转化路径和 CTA：交给 `$cflow-marketing`。
- 发布后复盘：交给 `$cflow-review`。
- 作者声音校准：交给 `$cflow-voice`。
