# 杀手级 thread 质量门槛

## 资产卡片

资产名称：杀手级 thread 质量门槛

资产类型：可迁移模式 / thread 质检资产 / 短内容系列生产资产 / 包装兑现资产

来源：`$cflow-maintain` 对一组外部 thread 写作方法论的机制提取。该资产只沉淀可迁移质量门槛，不沉淀原文链接、具体案例、作者身份、平台经验或数字承诺。

## 核心机制

强 thread 不是强 hook 加普通正文。

有效 thread 需要同时完成三件事：

```text
首屏让读者停下来
+
前几条让读者确认值得继续读
+
正文持续给出具体、可执行、可复述的 payoff
```

如果 hook 很强但正文只有泛泛建议，读者会点进来，但不会停留、收藏、转发或复访。thread 的质量门槛必须同时检查包装和正文兑现。

## 五个必要动作

### 1. 把最高价值信息前置

前 3 到 5 条必须放最强判断、最反常识的信息、最具体结果或最有用步骤。

不要把精华埋到中后段等待读者发现。读者还没有投入足够沉没成本前，每一条都在决定他是否退出。

检查：

```text
第一条之后，读者是否立刻知道继续读会得到什么？
前几条是否已经给出一个具体 payoff？
删掉前五条后，thread 是否才开始有价值？如果是，顺序错了。
```

### 2. 每个要点都回答三件事

每个要点至少要承担一个清楚功能：

```text
是什么：这条到底讲哪个具体观点、步骤、错误或判断？
为什么重要：它影响读者什么结果、代价、理解、信任或行动？
怎么做：读者下一步能执行、检查、判断或迁移什么？
```

不是每一条都要机械写成三段，但整条要点读完后，读者不能只知道一个抽象建议。

### 3. 具体性承担可信度和行动

具体不是装饰，而是让读者相信、记住和执行。

优先使用：

- 具体读者处境。
- 具体动作。
- 具体前后变化。
- 具体门槛、数字、步骤、时间或结果。
- 具体错误和修正方式。
- 真实案例、场景、截图、观察或作者判断。

素材没有支撑时，输出更弱但真实的版本，或标注需要补充。不要为了“具体”编造收入、粉丝、时间、客户结果、权威背书或案例。

### 4. 节奏服务继续阅读

节奏不是默认一句一行，也不是把每句话都压短。

有效节奏来自：

- 短句用于重击、转折或停顿。
- 中句推进解释和判断。
- 长句承载必要细节、条件和因果。
- 列表用于扫读、收藏或多点并列。
- 空行用于层级和停顿，不用于制造假呼吸感。

检查时大声读一遍：如果每条力度一样、长度一样、功能一样，说明节奏已经变成模板。

### 5. Hook 学习只迁移机制

可以从已验证 hook、swipe file、对标样本里学习：

- 结构。
- 张力。
- 动词。
- open loop。
- 句长节奏。
- 信息释放顺序。

不能直接迁移：

- 人物。
- 数字。
- 结果。
- 经历。
- 权威背书。
- 私有信源。
- 身份条件。

Hook 的吸引力必须能被当前素材兑现。不能用别人的成果、案例或权威为当前内容借可信度。

## Thread 质检清单

发布前检查：

```text
主题是否具体到目标读者能判断和自己有关？
hook 是否给出进入理由，而不是只总结内容？
前 3 到 5 条是否放了最高价值信息？
每个要点是否具体、独特、可执行？
每个要点是否说清是什么、为什么重要、怎么做？
正文是否持续兑现 hook，而不是只靠开头吸引点击？
是否有可截图、可收藏、可复述或可转发的传播单元？
节奏是否有长短变化、停顿和信息密度变化？
排版是否服务扫读、强调和推进，而不是一行一句的模板？
是否删掉了副词、填充词、重复解释和无功能铺垫？
是否从对标中只迁移机制，没有搬运事实、数字、身份和成果？
```

## 可迁移模板

```text
主题：
目标读者：
核心 payoff：
Hook 机制：
前 5 条最高价值信息：
要点列表：
每个要点的是什么 / 为什么 / 怎么做：
截图点或复述句：
收藏或转发理由：
节奏和排版处理：
素材缺口：
```

## 常见失效

- Hook 很强，但正文只是泛泛建议。
- 每条要点只说“是什么”，没有执行动作。
- 前半段铺垫太久，精华在后面。
- 为了具体性编造数字、收入、粉丝增长或客户结果。
- 每一句都单独成段，但没有信息密度变化。
- 清单很多，读者却不知道优先做哪一步。
- 从对标里搬运人物、结果、故事或权威背书。
- 结尾堆关注、收藏、转发、评论多个 CTA，读者不知道主动作。

## 适配到各 skill

- `$cflow-shortform`：负责 thread 本体、短内容系列和每条要点推进。
- `$cflow-package`：负责 hook、opening、标题、首屏承诺和 hook 变体纪律。
- `$cflow-check`：负责发布前判断 hook 与正文是否互相兑现，以及下一刀交给谁。
- `$cflow-viral`：负责截图点、复述句、转发理由、评论入口和分享动机。
- `$cflow-benchmark`：负责拆解对标 thread 的结构、张力和节奏，不复制不可迁移事实。

## 下一次使用方式

当用户提供 thread 草稿、短内容系列、对标样本或要求“写一个爆款线程 / 质检 thread / hook 要强但正文也要好”时，可以调用这个资产：

```text
使用“杀手级 thread 质量门槛”，先检查 hook、前 5 条最高价值信息、每个要点的是什么 / 为什么 / 怎么做，再决定交给 cflow-package、cflow-shortform、cflow-check 或 cflow-viral。
```

是否需要交给 `$cflow-maintain`：只有当多个任务反复暴露 thread 质量门槛没有被调用、资产发现失败，或专项 skill 对 thread 的边界发生冲突时才需要。
